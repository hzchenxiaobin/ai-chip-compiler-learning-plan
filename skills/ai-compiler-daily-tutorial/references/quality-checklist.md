# 每日教程质量检查清单

## 内容是否通俗易懂

- [ ] 开头 200 字内出现当天要解决的具体问题；
- [ ] 首次出现的术语都有简短解释和必要英文原名；
- [ ] 每个核心概念附近都有例子或技术图；
- [ ] 类比之后有准确技术映射和边界说明；
- [ ] 没有连续多段只下定义、不解释用途的内容；
- [ ] 没有为了“通俗”而牺牲类型、Shape、精度、依赖或执行语义等关键约束；
- [ ] 没有无意义宣传语、空泛开头和过度拔高。

## 是否真正做到图文并茂

- [ ] 至少 3 个本地 SVG／PNG／JPG／WebP 文件真实存在；
- [ ] 至少 2 张图表达流程、结构、机制或数据，而非装饰；
- [ ] 所有图片均有有意义的替代文本和图注；
- [ ] 图片与相邻正文互相解释，不是重复贴字；
- [ ] 相对链接可从教程所在目录正确解析；
- [ ] SVG 可解析，其他图片非空且格式有效；
- [ ] 没有“此处放图”“待补充”“建议插图”等占位文字；
- [ ] 没有把 Mermaid 源码、ASCII 图或远程图片链接当作已生成图片。

## 实践是否可执行

- [ ] 所需目录、文件、工具和版本前提明确；
- [ ] 代码包含运行所需的关键上下文；
- [ ] 运行命令使用正确路径；
- [ ] 实际执行过的结果与预期输出明确区分；
- [ ] 至少有一个修改参数或输入的对照观察；
- [ ] 性能数据来自真实测量，或明确标为估算／假设；
- [ ] 常见错误包含现象、原因、定位和修复。

## 是否形成学习闭环

- [ ] 今日目标可以用行为验证，而不是“了解”“掌握”等空泛表述；
- [ ] 有必做练习和可选挑战；
- [ ] 有至少 3 项可勾选验收标准；
- [ ] 总结回顾问题、机制、实践和验证；
- [ ] 下一天预告简短，不额外扩张学习范围。

## 最后技术审查

- [ ] 代码、公式、Shape、单位和图表数字相互一致；
- [ ] 外部事实和版本信息经过必要核实；
- [ ] 没有伪造引用、执行结果、图片或性能数据；
- [ ] 文件命名、目录和链接与交付说明一致。
