# 每日教程默认模板

按以下结构写作，可调整标题名称和顺序，但保留完整学习闭环。默认正文约 2500～4500 字，实践控制在 30～60 分钟；复杂实践可拆成“必做”和“选做”。

```markdown
# 第 N 天：用一句问题式或结果式标题点明主题

> **今日目标**：完成本教程后，你能做到……
> **预计时间**：学习 X 分钟＋实践 X 分钟
> **前置准备**：只列真正需要的工具、代码和概念
> **今日产出**：一个文件、一组测试或一张可验证的结果图

## 1. 今天解决什么问题？

从一个具体失败、性能现象或工程任务开始。说明为什么今天值得学习，不写空泛的“随着人工智能的发展”。

用一个贯穿全文的小例子给出输入、操作和预期结果。

## 2. 先看全貌：今天的内容位于哪里？

[嵌入图 1：全局流程或知识位置图]

**图 1**：用一两句话告诉读者看图时关注什么。

用 3～5 个步骤描述全局流程，不在此处展开所有细节。

## 3. 核心概念：先用直觉，再给准确定义

### 3.1 概念 A

- 一句通俗解释；
- 一个生活或工程类比；
- “对应到技术上是……”的准确映射；
- 一个最小例子；
- 一个常见误解或类比边界。

### 3.2 概念 B

沿用同一例子解释，并说明它与概念 A 的关系。

## 4. 图解核心机制

[嵌入图 2：核心机制、数据结构、IR 或内存图]

**图 2**：说明输入、输出和最关键的变化。

按图中编号逐步讲解。每一步都回答“发生了什么”和“为什么需要这一步”。

## 5. 动手实践：完成一个最小可运行例子

### 5.1 准备文件

给出目录结构和准备命令。

### 5.2 编写代码

提供关键完整代码，并解释最重要的几行。省略代码时明确说明省略原因和位置。

### 5.3 运行与观察

给出命令、实际输出或明确标注的预期输出。

[嵌入图 3：输入输出、优化前后或实验结果图]

**图 3**：解释结果说明什么，不只说“如图所示”。

### 5.4 修改一个参数再观察

设计一个低成本对照实验，让读者通过变化理解机制。

## 6. 常见错误与排查

至少列出 3 个真实错误，使用“现象 → 原因 → 定位 → 修复”的格式。

## 7. 今日练习

### 必做练习

给出一个能在当天例子上完成的练习，说明输入和预期产出，不直接给完整答案。

### 选做挑战

增加一个边界条件、性能对照或小扩展，不引入大量新知识。

## 8. 今日验收

- [ ] 我能用自己的话解释……
- [ ] 我能独立运行……
- [ ] 我能修改……并预测结果……
- [ ] 我能定位……错误……
- [ ] 我保存了……代码、测试或图……

## 9. 一句话总结与明天预告

用 3～5 句话总结“问题、机制、实践、验证”。最后用一句话说明与下一天的衔接，不展开新教程。
```

## 图片写作要求

- 图 1 负责定位，图 2 负责解释机制，图 3 负责证明或对照；不要让三张图重复。
- 每张图前用文字提出问题，图后解释结论。
- 图中使用简短标签，完整推理留在正文。
- 优先使用真实数据、真实 IR 或当天代码中的名称。
- 性能图必须注明输入、单位、环境和统计口径；没有真实数据时不画伪造性能图。
