## 一、第三阶段一页总结（3 分钟口径）

**结论先行**：图编译器不仅做模式匹配，还要管理**布局、资源和数值语义**——
模式匹配（消除/融合/折叠）只是改写图的动作；决定动作能不能做的，
是三类语义资源的安全边界。第三阶段四周就是在逐类补这三本账。

| 周 | 主题 | 一句话 | 关键数字（实测） |
|---|---|---|---|
| W9（D57~63） | Shape/Stride/Layout 地基 | Shape 相同 ≠ 内存布局相同 | 同一 (2,12) 存储：连续视图 shares_memory=True，转置视图 False |
| W10（D64~70） | 布局与冗余消除 | 图结构相同 ≠ 内存语义相同 | 5 个"看似能消除但不能"的反例集 |
| W11（D71~77） | 融合收益与代价 | 合法/正确/更快是三张 certificate | R4ctl：流量 −64 MiB、活集 +256 B、并发 4→3；1024³ spill 一票否决 |
| W12（D78~84） | 数值精度与量化 | 位等价与 golden 是两本账 | 位等价容差=0（50 张随机图 100%）；golden 账本 atol=4.29e-06 |

**端到端数字**（Day 83 主图，Day 84 复跑确认）：11 节点 → 7（清理不动点）→ 5（融合）；
运行时算子 8 → 2；ΔB = 192 B、工作集 228 B ≤ 片上 256 KiB；位等价 + golden 双通过；
1024³ 时工作集 12 MiB > 256 KiB → 拒绝（等第四阶段 Tiling）。

**三个高发追问的标准接答**：

1. **"剩下的 reshape 为什么不删？"** —— 图层面必须保留（matmul 的 Shape 契约，
   删了图不合法）；物理层面免费（连续输入零拷贝，strides=(24,4)B，三种读法喂
   GEMM 逐位相等）；前提进清单（B1：转置视图上的 reshape 是真实搬运，
   shares_memory=False 实测）。
2. **"golden 为什么差一个码？"** —— 半格分叉：fp32 的除法把商舍到 k+0.5，
   banker 舍入进位；fp64 的真商在半格下方退回——码差 1，值差一个 scale。
   实弹：s=0.7/127，w=0.0082677165…，fp32 商恰为 1.5 → 码 2；fp64 商
   1.4999999944 → 码 1；值差 0.00551。随机 2M 样本命中 5 个，半格定向扫描
   命中 62 个——窄概率事件，但真实存在。修正：scale 取 2 的幂（0 分叉）或
   golden 量化同精度（0 分叉）。
3. **"你怎么保证不改错数？"** —— 先反问哪个维度：结构（Verifier/rewire 纪律）、
   数值（位等价容差=0 + golden 账本）、收益（ΔB + spill 红线）——对应下面清单
   的 A/E、D、C 组。

## 二、优化正确性检查清单 v1.0（五组 16 项）

设计原则：**可执行**（每项是一个函数，接进 CI 就是测试用例）、**有出处**
（每项标注来源天数，可回溯规则的血案现场）、**被负例验证过**（三枚探针各红一列——
清单全绿是结果，探针能红才是清单被验证的证据）。

### A 结构（合法性——Day 12/39/45/51/52/59/60/64/69）

- [ ] **A1 终图过 Verifier**：Shape 全部可推导、返回值与输入引用无悬空（D12/39/59/60/64）
- [ ] **A2 删除即无主**：被删除的节点不得再被任何输入/返回值引用——rewire 先迁移使用者（D45/51/52）
- [ ] **A3 清理不动点收敛**：清理闸复跑零改写，防止顺序敏感和无限变换（D69）

### B 布局（元信息前提——Day 57/59/64/65/66）

- [ ] **B1 连续性前提**：reshape 不得消费非连续生产者（transpose 输出）——
      元信息改写的零拷贝前提，破了就是真实数据搬运（D57/59/66）
- [ ] **B2 无漏折**：终图残留的 transpose 祖先链必须含运行时输入——
      纯编译期数据的数据移动应全部折进常量（D64/65/83）
- [ ] **B3 链合并完成**：reshape 链深度 ≤ 1（D66）

### C 资源（账本与红线——Day 72/73/74/76）

- [ ] **C1 融合有账**：每个融合候选在审计里有 ΔB 与工作集记录——先记账后动手（D72/73/76）
- [ ] **C2 决策一致**：判"融合" ⇒ 无 spill 且 ΔB>0——决策与资源账不得矛盾（D74/76）
- [ ] **C3 红线复核**：spill 形状（如 1024³，工作集 12 MiB > 片上 256 KiB）的
      Cost Model 决策必须是拒绝（D73/76）

### D 数值（两本账＋量化——Day 78/79/81/82/83）

- [ ] **D1 位等价**：优化图 vs 原图，同一组输入 fp32 逐位相等，容差=0
      （固定输入＋随机输入；改写不得引入任何数值变化）（D79/83）
- [ ] **D2 golden**：fp32 执行 vs fp64 参考在账本 atol 内——
      `atol=(2K+2)·eps32·maxΣ|a·b|`（MatMul 不用逐元素固定阈值）（D78/79）
- [ ] **D3 量化声明**：图内 Q/DQ 的 scale 为 2 的幂；否则 golden 须同精度并把
      atol 放宽一个 scale 且写明理由（D81/82/83）
- [ ] **D4 融合核形状门**：bias 形状 ∈ {(), (N,), (1,N)}——add 合法 ≠ 能融合（D74/83）

### E 流程（纪律——Day 69/75/82/83）

- [ ] **E1 原图不动**：优化在副本上执行，原图 IR 逐字保留——对照基准不能消失（D82/83）
- [ ] **E2 审计先于动作**：改写步数 ≤ 审计行数——有动作必须有记录（D82/83）
- [ ] **E3 拒绝也是决策**：融合/拒绝/登记/报警在审计中可查（D75/82/83）

### 负例探针（清单的自检——三个都必须红在正确的组）

| 探针 | 破坏方式 | 预期红项 | 实测红项 |
|---|---|---|---|
| P1 数值 | 删掉尾部 Q→DQ（Day 82 R06 拒绝的不安全规则） | D1 | D1（max\|diff\| = 0.0625 = s/2） |
| P2 结构 | 忘记单使用者检查的断链融合（rewire 漏迁移） | A1, A2 | A1, A2, C1, D1, D2, E2 |
| P3 资源 | 1024³ 工作集 12 MiB 顶爆片上仍伪造"融合"决策 | C2 | C2（spill=True 仍判融合） |

### 使用与扩展

- 运行：`cd tutorials/day-084/code && python3 stage3_review.py`（8 项汇总检查全绿）
- 新加优化 Pass 后：跑两个正例场景（该融就融／该拒就拒）——16/16 是门槛；
