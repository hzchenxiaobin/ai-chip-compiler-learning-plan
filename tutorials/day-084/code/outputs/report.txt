Part 3  补讲 1（Layout）：终图剩下的 reshape(2,12 → 4,6) 到底贵不贵？
========================================================================
Day 83 收官时留了一句话：「剩下的 reshape 不能删」。讲稿排练时这里最容易卡壳——
它到底是一个运行时开销，还是一个纸面符号？用同一块存储做三种读法：

物理存储 buf：shape=(2, 12)，C 连续=True，共 24 个 fp32

读法一：reshape 成 (4,6) 当作视图（numpy 自动做的事）
  v = buf.reshape(4,6)：shares_memory = True，strides = (24, 4) 字节 → 零拷贝，纯元信息

读法二：stride 描述符（第四阶段 Lowering 的预演）——不给数据搬家，
  只告诉硬件「按 (6,1) 的步长把这块 (2,12) 缓冲当 (4,6) 读」
  as_strided(buf, (4,6), strides=(24,4)B)：shares_memory = True

读法三：老老实实物化一份新拷贝（数据真的搬了家）
  v.copy()：shares_memory = False（新分配了一块 96 B）

偏移公式对照：两种逻辑形状读的是同一条线性序——
  (i,j)→12i+j 的 24 个偏移 == (p,q)→6p+q 的 24 个偏移：True

反例（连续性前提不是免费的）：转置视图上做 reshape，元信息改写退化为物理搬运
  t = buf.T（非连续），t.reshape(2,12)：shares_memory = False → 发生了真实的数据移动

三种读法喂进同一个 GEMM，位等价核验（用的是终图里折叠好的常量 Ŵᵀ）：
  view   @ Ŵᵀ == stride描述符 @ Ŵᵀ：True
  view   @ Ŵᵀ == 物化拷贝  @ Ŵᵀ：True

结论（补讲 1 的标准答案，三句话）：
  ① 图层面它必须保留：matmul 的 Shape 契约要求 (M,K) 输入，删掉 reshape
     图就不合法；「按任意 stride 读缓冲」是 Lowering 的能力，图优化器不越权；
  ② 物理层面它免费：x 连续，(2,12)→(4,6) 是同一条线性序的两种记法，
     零拷贝（shares_memory=True 实测），Lowering 用 stride 描述符即可吸收；
  ③ 前提要写进清单：B1 之所以检查「reshape 不吃非连续生产者」，就是因为
     转置视图上的 reshape 会退化成真实搬运（反例实测 shares_memory=False）。

Part 4  补讲 2（量化）：s = max|W|/127 时，fp32 和 fp64 为何各舍各的？
========================================================================
Day 83 错误 4 留下的坑：常规校准 scale 不是 2 的幂，golden 对比会「无缘无故」
差出一个码。复盘排练时这句话最难讲清楚——今天把它解剖开：

常规校准：s = max|W|/127 = 0.7/127 = 0.005511811024（不是 2 的幂）
随机压测：2,000,000 个 fp32 权重，fp32/fp64 取整分叉 5 个（0.000250%——半格是道窄门，随机数据很难正中）
定向扫描：沿 k=1..127 每条半格 (k+0.5)·s 的 fp32 邻域逐点检查，命中 62 个分叉点——分叉不是都市传说，是窄概率事件

分叉点解剖（半格机制）：真商贴着 k+0.5 时，两种精度看到的商不一致，
  round 一个向下 一个向上，码差 1，反量化后差整整一个 scale：
  实弹（定向扫描第一发）：w = 0.008267716504633427（目标半格 k=1，w ≈ (k+0.5)·s）
    fp32 商 w/s = 1.5
    fp64 商 w/s = 1.4999999944120646
    半格 = 1.5（fp32 商距半格 +0.000e+00，fp64 商距半格 -5.588e-09）
    → fp32 的除法把商舍到了半格上，round-half-even 进到 2；
      fp64 看到的商在半格下方，退回 1——码差 1
    → 反量化值差 = |s·2 − s·1| = 0.00551181 = 一个 scale（s = 0.00551181）
