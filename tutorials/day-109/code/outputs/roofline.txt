 一、机器模型（三个探针实测；屋顶与被分析数据同一执行层）
   A 解释屋顶 P_int   = 0.0547 GFLOPS（纯 Python 标量 FMA，2,000,000 迭代 × 5 次取中位数）
   B Python 级流读 BW = 0.385 GB/s（迭代式，名义 8 B/元素；下标式敏感性对照 0.210 GB/s）
   C C 级缓冲区扫描 BW_C = 2.68 GB/s（zlib.adler32，64 MB；crc32 对照 0.99 GB/s）

 二、屋脊点 AI* = P ÷ BW（FLOP/B）：左边带宽区，右边算力区
   Python 层：AI* = 0.0547 ÷ 0.385 = 0.142 FLOP/B
   敏感性：换成下标式流读 AI* = 0.0547 ÷ 0.210 = 0.260 FLOP/B
           ——探针风格挪动屋脊 1.8×，但 matmul 的 AI 仍在右侧 41 倍以上，判定不动

 五、C 层 what-if（带宽用实测 BW_C；算力屋顶 P_hw 是假设参数——本环境无 BLAS，测不到）
   屋脊随假设移动：P_hw ∈ {1, 5, 20} GFLOPS → AI* ∈ {0.37, 1.87, 7.47} FLOP/B
   matmul AI 10.67~16.00 在三种假设下都高于屋脊 → C 层上 matmul 是算力受限（compute-bound 算子的由来）
   S1 要翻成带宽受限需要 P_hw > BW_C×AI = 29 GFLOPS——屋脊判定只由两个屋顶的比值决定
   对照：elementwise bias-add AI ≈ 1/8 = 0.125 FLOP/B，低于上述任一屋脊 → C 层上带宽受限
   → 融合（D72）让低强度的 elementwise 搭 matmul 数据复用的便车——今天给 D110 cost model 备料

 六、数据指纹：解释受限的独立证据（不依赖探针，只看记录）
   冠军 GFLOPS：S1 33.2 / S2 34.3 / S3 34.5 MFLOPS——工作量差 3.4×，速率只差 4%；
   若带宽受限：AI 更高的 S2（16.0）应该显著更快——实测没有；
   若真硬件算力受限：GFLOPS 不该只有 0.03 量级（差假设算力屋顶 2~3 个数量级）；
   平坦＋贴解释屋顶＝解释成本按 FLOP 计价的指纹，与探针屋脊点判定互相印证。

 诚实边界：探针与 D108 测量不在同一进程，跨进程漂移 D107 实测 ~8.6%；
 屋脊余量 75~113×，屋顶利用率取值当 ±10% 看即可，判定不受影响。
