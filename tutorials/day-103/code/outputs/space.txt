双缓冲空间账本：×2 只加在 DMA 流入项（规则沿用 D101）
========================================================================================
Tile 32³   单缓冲    12,416 B → 双缓冲    20,608 B   (+8,192 B, +66.0%)   256KiB? ✓ 住得下
Tile 64³   单缓冲    49,408 B → 双缓冲    82,176 B   (+32,768 B, +66.3%)   256KiB? ✓ 住得下
Tile 128³   单缓冲   197,120 B → 双缓冲   328,192 B   (+131,072 B, +66.5%)   256KiB? ✗ 被拒绝
Tile 256³   单缓冲   787,456 B → 双缓冲 1,311,744 B   (+524,288 B, +66.6%)   256KiB? ✗ 被拒绝

64³ 明细：A 16,384 + B 16,384 + C 16,384 + bias 256 = 49,408 B（D101）
64³ 双缓冲：A×2 32,768 + B×2 32,768 + C 16,384 + bias 256 = 82,176 B
占 256 KiB 预算 31.36%（单缓冲 18.84%）——用 66% 的空间买回 74% 的时间。
为什么 C 不 ×2：C 是读-改-写的累加器，只有一个『活跃实例』；
A/B 是纯流入流（DMA 写、计算读），乒乓才有意义。bias 首圈就消费掉，
只有 256 B，不值得为它翻倍。
警示：128³ 双缓冲 328,192 B > 262,144 B，被 D101 预算当场拒绝——
时间上的最优解会被空间一票否决，这正是 D104 资源过滤器的入口。
