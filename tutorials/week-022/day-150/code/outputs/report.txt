== 理论量计算（160³ matmul＋bias＋relu）==
  计算量：2×160×160×160 = 8.2 MFLOP
  访存量（无 cache 最坏）：33.0 MB
  访存量（L1 命中估算）：33.2 MB

== 算术强度 ==
  AI（最坏）= 0.25 FLOP/Byte
  AI（cache）= 0.25 FLOP/Byte

== 机器屋顶（教学估算·M 系）==
  峰值算力：50 GFLOP/s
  峰值带宽：50 GB/s
  拐点 AI* = 50/50 = 1.0 FLOP/Byte

== 实测对照 ==
  实测：0.392 GFLOP/s
  计算屋顶：50 GFLOP/s（差距 128×）
  访存屋顶（最坏 AI）：12.4 GFLOP/s（差距 32×）
  访存屋顶（cache AI）：12.3 GFLOP/s（差距 31×）

== 瓶颈判定 ==
  实测离计算屋顶 128×、离访存屋顶（最坏）32×
  → 两个屋顶都远（128× 与 32×）——
    这说明瓶颈不是「计算 vs 访存」的二选一，而是「执行效率」：
    朴素三重循环的指令开销（循环控制/地址计算/依赖链）吞掉了性能——
    每个乘加只用了 ~0.4 GFLOP/s 的「有效算力」
  → 假设 H1：循环控制开销主导（展开可救——D125 的 O2 证据：3.4GF＝8×）
  → 假设 H2：数据复用不足（L1 miss 频繁——tile 化可救——D151 的实验）
  → 假设 H3：依赖链限制 ILP（acc 串行——重排可救——教学版不做）
