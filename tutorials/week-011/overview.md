> 第三阶段：AI 计算图与图优化（第 57～84 天）

### 第 071 天｜计算量与访存量

- **学习**：FLOPs、字节数、算术强度和中间 Tensor 流量。
- **实践**：计算 MatMul、Add、Relu 独立执行时的理论计算量和访存量。
- **产出**：计算公式、代入示例和数据表。

### 第 072 天｜融合减少的流量

- **学习**：中间结果写回和再次读取的开销。
- **实践**：计算 `MatMul + Bias + Relu` 融合前后需要落盘的中间 Tensor 字节数。
- **产出**：融合流量对照表和收益公式。

### 第 073 天｜融合的资源代价

- **学习**：寄存器、片上存储、并行度和指令复杂度对融合收益的影响。
- **实践**：设计一个简单资源估算结构，记录融合算子的临时空间需求。
- **产出**：资源估算模型和假设清单。

### 第 074 天｜合法性与收益性分离

- **学习**：合法性 Pattern 与 Profitability 分析的接口边界。
- **实践**：将“能否融合”和“是否建议融合”拆成两个函数，默认策略保持保守。
- **产出**：独立收益判断接口和单元测试。

### 第 075 天｜构造不融合案例

- **学习**：多使用者、重复计算、资源超限和并行度下降导致的负收益。
- **实践**：至少构造两个图结构合法但应拒绝融合的案例，并说明原因。
- **产出**：负收益案例、决策日志和测试。

### 第 076 天｜简单 Cost Model 集成

- **学习**：Cost Model 的输入、输出、可解释性和误差来源。
- **实践**：按减少流量与资源代价给出评分，支持强制融合和自动决策两种模式。
- **产出**：Cost Model v0.1、IR 对照和决策结果表。

### 第 077 天｜第 11 周复盘

- **学习**：区分“融合合法”“融合后正确”和“融合后更快”。
- **实践**：用一个具体 Shape 完整讲解融合前后的计算量、流量和资源变化。
- **产出**：一页标准回答和本周实验数据。
