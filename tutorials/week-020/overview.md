> 第五阶段：端到端编译与 Runtime（第 113～140 天）

### 第 134 天｜IR 与 Pass 测试整理

- **学习**：单元测试、IR 文本测试和端到端测试的不同职责。
- **实践**：补齐 Verifier、Shape、融合、Layout 和 Lowering 的正反例。
- **产出**：分类清晰的 IR 测试集。

### 第 135 天｜随机 Shape 正确性测试

- **学习**：随机测试的分布、边界值和失败用例保存。
- **实践**：生成随机 M、N、K 和 Tile，先验证正确性再记录性能；固定随机种子。
- **产出**：随机测试工具和失败复现文件。

### 第 136 天｜Pass 二分定位

- **学习**：通过阶段 IR 和 Pass 开关定位最早错误点。
- **实践**：实现或脚本化逐个关闭 Pass 的调试流程，对一个故意注入的错误进行定位。
- **产出**：Pass 调试工具和定位记录。

### 第 137 天｜最小失败用例还原

- **学习**：Reduce 思想：删除无关节点、缩小 Shape、简化类型。
- **实践**：把一个复杂失败用例缩减为最小 IR，并确认仍能触发同一问题。
- **产出**：最小复现用例和修复后的回归测试。

### 第 138 天｜性能回归测试

- **学习**：性能阈值、机器波动、统计口径和基准版本。
- **实践**：固定一组基准 Shape，保存中位数和波动范围，建立合理回归报警。
- **产出**：性能基准文件和自动比较脚本。

### 第 139 天｜完整回归与项目冻结检查

- **学习**：正确性、编译时间、运行性能和文档的联合验收。
- **实践**：执行全部测试，整理未解决问题，区分必须修复和后续扩展。
- **产出**：回归报告、问题清单和第五阶段版本。

### 第 140 天｜第 20 周复盘

- **学习**：总结编译器调试的核心是定位最早语义破坏点。
- **实践**：脱稿演示一次“失败 → Dump IR → 关闭 Pass → 最小复现 → 修复”的流程。
- **产出**：调试流程图和阶段总结。
