==============================================================================
 实验二：shape 对照——512 走整除模式，516 逼出尾部模式
==============================================================================
 512³：div 模式 tile 池 = [8, 16, 32, 64, 128, 256, 512]（7 个/维）
        516 = 2²·3·43：整除 516 且是 8 的倍数的正整数——一个都没有！
        div 模式 tile 池（516）= []  ← 空集警报：值域剪过头不是省钱，是断粮

 逃生门：div 剪成空集 → 自动降级 tail 模式（D95 尾部机制接住非整除）
 516³ tail 模式 tile 池 = [32, 64, 96, 128, 160, 256]（6 个/维）
        池里 6/6 个值不整除 516 → 216 个 tile 组合全部带尾部
        （516 的因数里没有 32~256 的值——它是天然的『尾部 shape』，D97 冠军翻转的现场）

 [512·div]  值域原始 20,580 → 参数剪 588 个 → 资源剪 7,022 个 → 幸存 12,970 个
     参数剪例：8³ ijk U=16 fp32·single +bias  U=16 > 最内层 k 的圈数 8（主循环 0 圈的死代码）
 [516·tail]  值域原始 12,960 → 参数剪 0 个 → 资源剪 4,620 个 → 幸存 8,340 个
     老朋友回来了：96³ 幸存 60 个配置、160×128×64 幸存 60 个
     （D104 判定表里的 96³ fp32·double = 184,704 B ✓、160×128×64 = 229,888 B ✓）

 观察点：同一套值域规则，512 给 343 个 tile，516 一个都不给——
 值域剪枝的产出取决于 shape 的因数结构；规则越紧越要留逃生门，
 否则调优器对 516 这类 shape 直接罢工（空集不是答案，是 bug）。
