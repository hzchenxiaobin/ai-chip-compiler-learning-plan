## 【错误】

#### 1. "错误二"宣称的"峰值少算 32 个元素"在本图所有合法顺序下都不会发生
- **原文**："现象：峰值少算 32 个元素；更糟的是复用规划器以为 `x` 在步骤 1 后死亡"
- **依据**：把 `x` 的 last_use 误取为首次使用步（顺序 A 记 `[0,1]` 而非 `[0,3]`），用当天脚本同款算法复算：顺序 A（main-first）每步为 [288, 288, 160, 320]，峰值仍为 320；顺序 B（skip-first，x 误记 [0,1] 而非 [0,2]）每步为 [160, 384, 416, 320]，峰值仍为 416；交错顺序（t1→s→t2→y，x 误记 [0,1] 而非 [0,2]）每步为 [288, 384, 416, 320]，峰值仍为 416。原因：顺序 A 的峰值步 4（t2+s+y=320，concat 硬下界）与顺序 B/交错的峰值步 3（t1+t2+s=416）都不依赖 `x` 是否存活，受影响步骤（各少 32 个元素）不是峰值步。该错误真正的后果是同一段后半句描述的复用冲突（t2 覆盖 x 的缓冲区、步骤 3 读到垃圾数据），以及受影响步骤每步合计少 32——但"峰值少算 32"这个症状读者用教程自己的图复现不出来，且与"错误一"（开区间确实把峰值报成 288）形成对照，容易让人误以为两类错误都会压低峰值报告。核实方式：在 `compute_intervals` 结果上手工把 x 的区间改为 `(0, 首次使用步)` 再跑 `peak_and_steps`（本机已按三种顺序逐一验证）。
- **置信度**：高（用当天代码与图复算，三种合法顺序结论一致）

## 【建议】

#### 2. 把 MLIR bufferization 与 XLA buffer assignment 并列为"做的都是这件事"过于笼统
- **原文**："这叫静态内存规划（MLIR 的 bufferization、TVM 的静态内存规划、XLA 的 buffer assignment 做的都是这件事）"
- **依据**：按 MLIR 官方文档（mlir.llvm.org/docs/Bufferization/），bufferization 的定义是"把 tensor 语义的 op 转换为 memref 语义"，其省内存目标（少占内存、少拷贝、复用已分配缓冲区）主要通过 One-Shot Bufferize 的 in-place / destination-passing 决策实现，且文档明说"同一函数里其他可能复用的缓冲区不在 One-Shot Bufferize 的考虑范围内"——即 MLIR 侧的复用是就地/目标缓冲区级别的，而"按活跃区间不重叠做全图缓冲区共享规划"的是 XLA buffer assignment、TVM storage planning（含 MicroTVM USMP）一类机制。方向性并列（都在编译期决定缓冲区）没有错、不影响当天内容，但初学者按这句话去查 MLIR 时会把 bufferization 当成区间复用规划器，建议补半句区分"转换＋就地复用"与"全图区间共享规划"。
- **置信度**：高（MLIR 官方文档已核对；XLA/TVM 侧按公开资料的一般性描述，未逐一核对其当前实现细节）

#### 3. "s 只要出生在 t1 存活期间"对顺序 3 不成立
- **原文**："`s` 只要出生在 `t1` 存活期间（顺序 2、3），它的 128 个元素就全程压在 `t1` 身上"
- **依据**：顺序 3 是 `s → t1 → t2 → y`（即 skip-first.txt）：s 的 def=1，t1 的区间是 [2,3]——s 出生时 t1 还不存在（t1 的 def=2 晚于 s 的 def=1），严格说是"t1 出生在 s 存活期间"。对两种顺序都成立的命题是"s 的存活区间与 t1 的区间重叠"（顺序 3：[1,4] ∩ [2,3] ≠ ∅）。峰值结论（416）不受影响，建议改为"s 只要与 t1 的存活期重叠"。
- **置信度**：高（区间数字直接来自冻结输出 skip-first.txt）

#### 4. 单闭区间模型隐含"每个张量只有一个生产者"，建议补一句适用边界
- **原文**："对每个张量 t 计算 `def(t)`（产生它的算子的步号）和 `last_use(t)`（最后一个读它的算子的步号）"
- **依据**：今天推导规则成立的前提是数据流图/SSA 式单赋值：每个张量恰好被一个算子定义一次，活跃性才是单条闭区间。真实图 IR 里带循环（loop-carried 缓冲区每轮迭代都被重写重读）或多写者（原地更新、while 子图）时，同一缓冲区的活跃性是多个区间的并集，单区间模型会把"中间死了又被写活"的空隙误判成可复用。教程已声明动态 Shape 留到第 19 周，但"循环"这一最常见反例未提；初学者把今天的表直接套到带循环的图上会踩坑。建议在 3.1 的四条约定后补一句适用范围（单生产者、无循环的数据流图）。
- **置信度**：高（标准活跃性分析结论；本图无循环，不影响当天内容正确性）
