== E2 异步仿真：launch 立即返回＋event 同步 ==
  launch k1：耗时 0.01ms（入队即返回——不等执行）
  launch k2：又 0.01ms（同 stream 排队）
  两个 30ms kernel 总耗时 60ms（stream 内串行——同 GPU 语义）
  launch 开销：0.01ms vs 执行 60ms

  双 stream 并行：两个 30ms kernel 总 43ms（<60ms——真并行）
  → 单 stream 串行、多 stream 并行——GPU 的执行模型

  场景 B（假想·未融合）：

    依赖：bias 读 matmul 输出、relu 读 bias 输出
    同一 stream：自动按序——无需显式 event（顺序执行语义保证）
    跨 stream：必须 event——bias_stream.wait_event(matmul_event)
  场景 C（池化内存的交互——D131 的伏笔）：
    release(buf) 必须等读 buf 的最后一个 kernel 完成！
    → 池的归还语义在异步世界要加 event 依赖——否则数据竞争

  Compiler/Runtime 分工（异步版）：

    调用方 ：最终同步（wait 最后一个 event）＋读结果
