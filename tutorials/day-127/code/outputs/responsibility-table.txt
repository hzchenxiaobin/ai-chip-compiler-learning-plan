第 127 天：Compiler/Runtime 职责划分表（机器生成）
==============================================================================

决策点                     归属        证据与对照
------------------------------------------------------------------------------
Shape 确定（M/N/K）
  归属：COMPILE
  minic 证据：S2 从图推断：const.shape/arg.tensor/reshape.new_shape 三来源（loop_lower._infer_shape）
  真实系统：TVM: 编译期全静态；PyTorch: 运行期动态 shape（每次推理现推）
  评注：minic 是『纯静态派』——图 IR 里 shape 是属性不是输入

Stride/布局确定
  归属：COMPILE
  minic 证据：S2 签名 strided<[K,1]> 写死行主序（gen_loop_ir_full）
  真实系统：TVM: layout 自由变换；cuDNN: 运行期选 NHWC/NCHW
  评注：D57~D68 的布局课在 minic 里退化为固定行主序——教学取舍

Tile 参数选择
  归属：COMPILE
  minic 证据：CLI --tile 传入，manifest.tile 记录（但 D125 证明教学版不消费）
  真实系统：TVM/Ansor: 搜索空间+代价模型；AutoTVM: 运行期 autotune
  评注：D106~D111 的调优管道是它的真身

Kernel 选择（哪个实现）
  归属：COMPILE
  minic 证据：S1 融合决策 + S2 单一展开路径（无备选）
  真实系统：cuDNN: 运行期 heuristic 按 shape 选 kernel；Triton: JIT 缓存
  评注：minic 无备选——D129/D130 的特化/回退将引入『两个实现』

内存分配（输出缓冲区）
  归属：RUNTIME
  minic 证据：kernel 内 memref.alloc → malloc(48)，每次调用都分配（stage-5.ll: %20 = call @malloc）
  真实系统：TVM: 运行时 TVMArray 从 allocators 拿；CUDA: cudaMalloc 或池
  评注：D118 挂账的 malloc 债务——D131 结清（分配器/池）

内存释放
  归属：NONE
  minic 证据：kernel 不 free——泄漏（教学规模无所谓，D118 诚实声明）
  真实系统：真实 Runtime 必须管生命周期（引用计数/arena/池）
  评注：『没人负责』也是一种划分——真实系统不能这么选

输入数据搬运
  归属：CALLER
  minic 证据：driver 的 desc_t 构造把 A/B 地址传给 kernel（verify_driver.c）
  真实系统：GPU: cudaMemcpyAsync/H2D；CPU: 零拷贝（指针直传）
  评注：CPU 教学版天然零拷贝——GPU 版的搬运是 Runtime 大头

同步（何时算完）
  归属：IMPLICIT
  minic 证据：C 函数调用返回＝完成（同步语义，D118 AOT 路线）
  真实系统：CUDA: stream+event；异步 Launch 后 host 侧 sync
  评注：D132 的主题——CPU 的隐式同步在 GPU 上显式化

验证（结果对不对）
  归属：TEST
  minic 证据：S6 golden bitwise（verify_e2e，12/12）
  真实系统：真实系统：UT 层面做，运行期不做逐次验证（太慢）
  评注：验证是『开发期职责』不是运行期——但 CI 里它守着每次提交

Kernel 缓存（编译结果复用）
  归属：NONE
  minic 证据：每次 minic 调用都全管道重跑（无缓存）
  真实系统：Triton: @lru_cache 按 (shape,dtype) 缓存；TVM: 本地磁盘缓存
  评注：D129 特化将引入『按 shape 缓存』的雏形

错误诊断与恢复
  归属：COMPILE
  minic 证据：E1xx/E2xx 诊断体系（minic.py DIAG_CODES）
  真实系统：运行期错误（OOM/超时）由 Runtime 兜底重试或降级
  评注：编译期诊断已完备；运行期恢复（D130 回退）下周见

==============================================================================

归属统计与解读：
  COMPILE ×4（Shape/Stride/Tile/Kernel选择）—— minic 是纯静态编译派
  RUNTIME ×1（输出内存分配）—— malloc 债务的唯一运行期职责
  CALLER ×1（输入搬运）—— driver 负责，天然零拷贝
  IMPLICIT ×1（同步）—— CPU 调用语义隐式保证
  NONE ×2（释放/缓存）—— 没人负责——真实系统不能留空的两格
  TEST ×1（验证）—— 开发期职责，不进运行期热路径

核心结论（下周的地图）：
  ① D128 运行期参数——Shape 从"编译期属性"变"运行期输入"要动什么
  ② D129 特化——Kernel 选择从 COMPILE（单一）变 SPLIT（多版本+分发）
  ③ D130 回退——错误恢复从 NONE 变 RUNTIME（分发器兜底）
  ④ D131 内存——分配从 RUNTIME（裸 malloc）变 RUNTIME（池化）＋释放从 NONE 变 RUNTIME
  ⑤ D132 同步——从 IMPLICIT 变显式（stream/event 的教学映射）
