Day 90 修复闭环：红 → 定位 → 修复 → 绿（全部真实运行）
环境：Linux aarch64, Python 3.11.4, numpy 1.26.4; 本机未安装 MLIR（DialectConversion 语义仿真＋访存日志解释执行，不伪造 MLIR 行为）

定位手段（两个「应然 vs 实然」的对照面）：
  ① LoopSpec 出生证明（Day 88）：每条循环的 ub 来源——i←M=A.shape[0]、
    j←N=B.shape[1]、k←K=内维契约；注释印在 IR 里，与实际 for 绑定的常量一比即见错位；
  ② 下标语义表（Day 85/89）：A[i,k]=行×归约、B[k,j]=归约×列、C[i,j]=输出坐标。

── M1 a_swap：配对写反：load %a[%k, %i]（A 的行列互换；方阵时算 Aᵀ·B，不越界） ──
  红（OOB 路径）：A(2,3)@B(3,5) → OOB
    memref.load %a(2, 0)：第 0 维下标 2 ∉ [0, 2)（shape (2, 3)）
  红（NUM 路径）：A(3,3)@B(3,3) → NUM
    max|C − ref| = 2.199e+00（静默算错）
  修复：load %a 的下标绑回 [%i, %k]（行号在前、归约在后）
  绿：同一 killer 形状用正确绑定重跑 → 与同序参考逐位相等（True）
  回归：全矩阵 15/15 位等价（ST1）＋ ST2~ST6 全 PASS

── M2 b_swap：配对写反：load %b[%j, %k]（B 的行列互换；K==N 时算 A·Bᵀ，不越界） ──
  红（OOB 路径）：A(4,3)@B(3,1) → OOB
    memref.load %b(0, 1)：第 1 维下标 1 ∉ [0, 1)（shape (3, 1)）；线性地址 1 甚至仍在缓冲区（3 格）内——只查线性地址抓不住这类逻辑越界
  红（NUM 路径）：A(3,3)@B(3,3) → NUM
    max|C − ref| = 1.701e+00（静默算错）
  修复：load %b 的下标绑回 [%k, %j]（归约在前、列号在后）
  绿：同一 killer 形状用正确绑定重跑 → 与同序参考逐位相等（True）
  回归：全矩阵 15/15 位等价（ST1）＋ ST2~ST6 全 PASS

── M3 i_ub_n：边界错绑：i 循环上界绑到 %cN（应绑 %cM）；M==N 时位相同（隐身） ──
  红（OOB 路径）：A(1,7)@B(7,4) → OOB
    memref.load %a(1, 0)：第 0 维下标 1 ∉ [0, 1)（shape (1, 7)）
  红（NUM 路径）：A(6,1)@B(1,4) → NUM
    max|C − ref| = 9.397e+02（静默算错）
  修复：i 循环上界绑回 %cM（M = A.shape[0]）
  绿：同一 killer 形状用正确绑定重跑 → 与同序参考逐位相等（True）
  回归：全矩阵 15/15 位等价（ST1）＋ ST2~ST6 全 PASS

── M4 k_ub_n：边界错绑：k 循环上界绑到 %cN（应绑 %cK）；K==N 时位相同（隐身） ──
  红（OOB 路径）：A(6,1)@B(1,4) → OOB
    memref.load %a(0, 1)：第 1 维下标 1 ∉ [0, 1)（shape (6, 1)）；线性地址 1 甚至仍在缓冲区（6 格）内——只查线性地址抓不住这类逻辑越界
  红（NUM 路径）：A(4,6)@B(6,3) → NUM
    max|C − ref| = 4.081e+00（静默算错）
  修复：k 循环上界绑回 %cK（K = 内维契约 A.shape[1]==B.shape[0]）
  绿：同一 killer 形状用正确绑定重跑 → 与同序参考逐位相等（True）
  回归：全矩阵 15/15 位等价（ST1）＋ ST2~ST6 全 PASS

诚实声明：四个变异是**故意注入**的探针（Day 89 的 Pattern 在 AT4 预飞 7 组全绿、今天新增 8 组边界形状也全绿）。它们的作用是证明「形状矩阵有牙齿」、并演练修复闭环——不是伪造「昨天就错」的历史。
