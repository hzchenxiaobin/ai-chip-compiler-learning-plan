## 【错误】

#### 1. 3.3 节核心论断：按值形参下“先检查后转移＝强保证、先转移再检查＝基本保证”的差别不存在
- **原文**：“2. **要自己排的**：今天的低级构造函数是 `Tensor(TensorDesc desc, Buffer storage)`，参数按值传入。如果**先 move 进成员再检查**：检查抛异常时内存照样不漏（成员已析构），但调用方传进来的实参**已经被搬空**——只算基本保证。正式版改成**先检查、后转移**：`check_fit(desc, storage)` 在参数还是完好的副本时执行，抛异常时实参原封不动、成员仍是空状态——**强保证**。”
- **依据**：这句话误解了按值形参的初始化时序。C++ 中按值形参在**调用边界**就完成初始化：TensorDesc 左值拷贝、`std::move` 后移动、纯右值直接落位。`Buffer` 的拷贝被删除，具名 Buffer 只能以 `std::move` 传入，因此**构造函数体还没开始执行**，调用方的 Buffer 就已经被搬空——与函数体内“先检查还是先转移”的顺序无关。两种顺序的调用方可观察结果完全相同：都不泄漏（先检查版：栈展开时形参析构释放；先转移版：成员析构释放），`*this` 都从未构造完成；“实参原封不动”只在传入纯右值（如 `Buffer(24)`）时成立，而那时根本没有具名对象可保护。本机双版本实测（g++ 9.4.0，临时目录）：`Buffer buf(24); try { Tensor bad(TensorDesc({2,3}, Dtype::Float32, {5,1}), std::move(buf)); } catch(...{}` 在仓库自带的“先检查后转移”正式版下，catch 之后 `buf.empty()` 为 **yes**、`TensorDesc` 具名实参的 `shape().size()` 为 **0**——实参恰恰不是“原封不动”；把构造函数临时改成“先 move 进成员、再 check_fit”后重跑，两个结果逐项相同。事实上 `err_bad_desc.cpp` 里的 `bad_desc` 在构造失败后也已是 moved-from。教程声称的强／基本保证差别只有在形参改为引用（例如 `Tensor(TensorDesc&&, Buffer&&)`）时才真实存在——那时“先转移”确实会在校验前偷走调用方对象。“先做会抛的工作、再动状态”作为编码习惯仍值得教，但按值形参下它换不来调用方可观察的异常保证差异，本文该论断及由它派生的表述（今日目标第 3 行“能说清……差别（强／弱异常保证）”、3.3 节类比边界、5.2 节 Tensor.h 代码注释、第 7 节选做挑战、第 8 节验收第 3 条、第 9 节总结“也不搬空调用方实参（强保证）”）都需要重写或降格为“编码习惯”层面的表述。
- **置信度**：高（按值形参的初始化语义是标准规定；结论经本机双版本对照实验验证，实验代码在临时目录运行、未改动仓库任何文件）。

#### 2. 选做挑战设计的实验无法呈现所声称的对照，忠实执行反而会推翻 3.3 节结论
- **原文**：“亲手体验一次"弱保证"：把 `Tensor::Tensor(TensorDesc, Buffer)` 临时改成**先 move 进成员、再 check_fit** 的版本，然后在 `err_bad_desc.cpp` 的场景里观察——异常抛出后，调用方传进来的 `Buffer` 实参 `empty()` 是什么？改回正式版再跑一遍对照。用 3～5 句话写下：为什么正式版选择"先检查后转移"，以及在什么代价下这个选择是值得的（提示：参数多一次移动）。”
- **依据**：`err_bad_desc.cpp` 的调用是 `Tensor bad(std::move(bad_desc), Buffer(24));`，`Buffer` 实参是纯右值，完整表达式结束后该对象已不存在，“异常抛出后实参 `empty()` 是什么”无从观察。学生要完成实验只能把 Buffer 改成具名对象——因拷贝被删，只能 `std::move` 传入；而如【错误】1 的实测，正式版（先检查后转移）与“先 move 进成员再 check_fit”版在异常后都是 `buf.empty() == yes`，“改回正式版再跑一遍对照”看不到任何差别，实验无法复现“弱保证”与“强保证”的对照。若希望实验成立，需要把构造函数形参改为引用（先转移才会真正偷走调用方对象），或者观察一个未经 `std::move` 的对象——都与当前代码不符。另外该行末尾的提示“参数多一次移动”同样存疑：两个版本对每个成员都恰好各做一次移动，正文代码里并不存在“多一次移动”的差别（按值形参相对引用形参确实多一次边界移动，但那是两种签名之间的差别，不是两种函数体顺序之间的差别）。
- **置信度**：高（实验无法观察纯右值的状态是语言确定语义；双版本对照实验见【错误】1）。

## 【建议】

#### 1. `ctest --test-dir` 需要 CMake ≥ 3.20，与前置准备声明的“CMake ≥ 3.16”不匹配
- **原文**：“ctest --test-dir build --output-on-failure”
- **依据**：`--test-dir` 是 CMake 3.20 才引入的 ctest 选项，本日三处验证命令（Debug、ASan、UBSan）都在用它；而前置准备写的是“构建环境同前五天（CMake ≥ 3.16、Ninja、g++ 或 clang++）”。在满足声明下限的 3.16～3.19 环境里，`cmake` 配置与构建能成功、`ctest --test-dir` 会因未知参数失败，初学者会卡在验收第一步。建议注明运行命令需要 CMake ≥ 3.20，或补一句 `cd build && ctest` 的等价写法。
- **置信度**：高（已核对 CMake 官方 3.20 发行说明，CTest 一节明确写明“ctest(1) gained a --test-dir option to specify the directory in which to look for tests”；本机仅装有 3.20.5、无法用 3.16 实测复现失败现象，但选项引入版本已有官方文档佐证）。

#### 2. “t 重新赋值再用”的示例出处指向错误
- **原文**：“- 修复：遵守空壳三件事——判空、析构、赋新值（5.3 节第 4 段之后 `t` 重新赋值再用的写法就是合法用法）。要旧数据就别 move，或者先复制。”
- **依据**：`main.cpp`（对应 5.3 节第 4 段的程序）在 `Tensor b = std::move(t);` 之后从未对 `t` 重新赋值，只做了两次误用演示；真正演示“空壳赋新值”的是 `tests/test_tensor.cpp` 第 ⑫ 组（`a = Tensor::zeros({1, 2}, Dtype::Float32);`）。按现行指向，读者在 5.3 节正文找不到这个示例，建议把出处改为测试文件或把示例补进观察程序。
- **置信度**：高（已逐行核对 main.cpp 全文）。

#### 3. “第 4 天 6.1 节”在 day-004 中不存在
- **原文**：“类比边界：货单类比听不出"元素单位"和"字节单位"的换算——技术上 `have` 必须除以 `itemsize` 再比较，单位错了就是第 4 天 6.1 节"字节当元素"的旧坑。”
- **依据**：day-004 的 README 第 6 节是“常见错误与排查”，其下按“错误一／二／三”组织，没有编号为 6.1 的小节；“字节当元素”的坑是第 6 节**错误一**（标题为“把‘字节步长’当成‘元素步长’传进来”）。内容对应正确、小节编号不存在，建议改为“第 4 天第 6 节错误一”。
- **置信度**：高（已列出 day-004 全部标题核对）。

#### 4. “53 条断言”的计数依赖一处落在注释里的 `++checks`，数字脆弱
- **原文**：“`tests/test_tensor.cpp` 按概念分了 19 组、53 条断言：zeros 元信息与其他 Dtype、from_data 逐位核对、读写、边界四方向、秩不匹配、一维／三维、同数据不同 shape、移动、误用空壳两道防线、配套检查正反例、异常后续、非 float32 拒绝、零元素张量、打印冒烟（节选见仓库，全部断言 5.3 节验收）。”
- **依据**：`tests/test_tensor.cpp` 中 `++checks` 共出现 54 处，其中第 ⑮ 组第 137 行（`assert(view.at({1, 1}) == 0.0f);` 行尾）的 `++checks;` 位于 `//` 注释内、不会执行，运行时计数才恰好是 53——正文与真实输出目前一致，但这更像笔误而非刻意设计。一旦有人把这一处挪出注释，计数变为 54，本日所有“53 条断言”的表述（今日目标、今日产出、本行、5.3 节、第 8 节验收、第 9 节总结、图 1 与图 3 的图注）将全部失配。建议修正该行计数位置并全文复核数字（另注：第 32～34 行的三条 `assert` 只对应一个 `++checks`，“53 条断言”实际是“53 次计数”，与断言条数并不一一对应）。
- **置信度**：高（`grep` 统计 54 处＋对每处插桩运行确认仅第 137 行未执行）。

#### 5. “除此之外一行未动”与实际 diff 不完全相符
- **原文**：“最后交代对第 4 天 `TensorDesc` 的两处改动，都是整合逼出来的：**① 补默认构造**——`Tensor` 需要空壳状态（默认构造／moved-from），成员必须可以默认构造（`shape_/strides_` 为空、offset 0、float32）；**② `element_offset` 拆出指针区间版核心**——`to_string` 递归打印时秩是运行期才知道的，拿不出 `initializer_list`，老接口转调新核心。除此之外一行未动——好零件整合时最好不用改。”
- **依据**：与 day-004 的 `TensorDesc.h/.cpp` 逐行 diff，除①②外还有第三处功能性改动未被提及：成员默认初始化（`std::int64_t storage_offset_ = 0;`、`Dtype dtype_ = Dtype::Float32;`）。它是①能给出“offset 0、float32”空状态的必要条件（没有它，`= default` 构造出的 offset／dtype 是未定值），可归入①，但字面“除此之外一行未动”不成立——diff 还显示多处注释改写。读者对照 day-004 源码时会看到未解释的第三处改动，建议把“一行未动”改为“除这两处（及其配套的成员默认初始化）外无其他功能改动”之类的说法。
- **置信度**：高（diff 可复现）；属表述精度问题，不影响技术正确性，故列为建议。
