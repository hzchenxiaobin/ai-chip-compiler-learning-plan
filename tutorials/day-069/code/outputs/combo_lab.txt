== 2. 多步组合用例：10-op 混合链 -> 稳定 IR ==
========================================================================
改写前（10 op：2 arg + 8 计算）：
def @mixed_chain
  %1 = arg                                     ; -> (2, 3)
  %2 = arg                                     ; -> (2, 3)
  %3 = transpose %1, perm=[1, 0]               ; -> (3, 2)
  %4 = transpose %3, perm=[1, 0]               ; -> (2, 3)
  %5 = cast %4, f32->f32                       ; -> (2, 3)
  %6 = add %5, %2                              ; -> (2, 3)
  %7 = relu %6                                 ; -> (2, 3)
  %8 = transpose %7, perm=[1, 0]               ; -> (3, 2)
  %9 = reshape %8, to=[6]                      ; -> (6,)
  %10 = reshape %9, to=[3, 2]                  ; -> (3, 2)
  return %10

op 统计：{'ops': 8, 'transpose': 3, 'reshape': 2, 'cast': 1, 'fused': 0}

推荐顺序跑完：5 轮，verdict=fixpoint
改写后（稳定 IR）：
def @mixed_chain
  %1 = arg                                     ; -> (2, 3)
  %2 = arg                                     ; -> (2, 3)
  %12 = fused_add_relu %1, %2                  ; -> (2, 3)
  %8 = transpose %12, perm=[1, 0]              ; -> (3, 2)
  return %8

op 统计：{'ops': 2, 'transpose': 1, 'reshape': 0, 'cast': 0, 'fused': 1}
[PASS] 混合链-verdict 是 fixpoint（5 轮）
[PASS] 混合链-总 op 10 -> 4（含 2 个 arg；计算 op 8 -> 2）（实际 4（计算 2））
[PASS] 混合链-转置 2 -> 1（卡在 fused 上，传播白名单不认 fused）
[PASS] 混合链-cast 1 -> 0
[PASS] 混合链-reshape 2 -> 0
[PASS] 混合链-fused 0 -> 1
[PASS] 混合链-数值逐位相等（ok）
[PASS] 稳定条件1-二次运行零轮次（幂等）（0 轮）
[PASS] 稳定条件2-状态哈希不变
[PASS] 稳定条件3-数值仍逐位相等

结论：混合链的 5 次触发依次是
  merge_t（r=恒等，透传）→ merge_r → transparent_r → cast → fuse
  剩下的 1 个转置卡在 fused_add_relu 上：C1 白名单只有 relu/neg/floor。

== 3. 合流 vs 竞争：Pattern 顺序研究 ==
========================================================================

顺序只有两类行为（今天全部实测）：
  合流（confluent）：换顺序只影响轮次，终点相同；
  竞争：换顺序换终点——两个不动点都合法，选谁是 Cost Model（第 11 周）的事。

[PASS] 合流-cast×融合 终点相同（哈希相等）（轮次 2 vs 2，终点 相同）
[PASS] 合流-两个终点都是 fused（cast 被消掉）
  cast 先消：2 轮；融合先试：2 轮——轮次相同，因为 run_passes 每轮把 Pattern 集整个试一遍，
  被挡住的模式下一轮还有机会（一次性管道没有这个机会，见第 6 节）。

竞争现场：z = T( relu( add(x, y) ) )——窗口是那个 relu

顺序A（传播在前）：1 轮 fixpoint
def @window
  %1 = arg                                     ; -> (2, 3)
  %2 = arg                                     ; -> (2, 3)
  %3 = add %1, %2                              ; -> (2, 3)
  %6 = transpose %3, perm=[1, 0]               ; -> (3, 2)
  %7 = relu %6                                 ; -> (3, 2)
  return %7
  op 统计：{'ops': 3, 'transpose': 1, 'reshape': 0, 'cast': 0, 'fused': 0}

顺序B（融合在前）：1 轮 fixpoint
def @window
  %1 = arg                                     ; -> (2, 3)
  %2 = arg                                     ; -> (2, 3)
  %6 = fused_add_relu %1, %2                   ; -> (2, 3)
  %5 = transpose %6, perm=[1, 0]               ; -> (3, 2)
  return %5
  op 统计：{'ops': 2, 'transpose': 1, 'reshape': 0, 'cast': 0, 'fused': 1}
[PASS] 竞争-两个终点不同（哈希不等）
[PASS] 竞争-先传播 5 op、先融合 4 op（含 2 个 arg）（5 vs 4）
[PASS] 竞争-两边都剩 1 个卡住的转置
[PASS] 竞争-两个不动点数值都对

机制：融合把 relu 吞进 fused_add_relu，传播的白名单（relu/neg/floor）
认不出 fused；传播把 T 推到 relu 下面，融合的匹配（relu 的输入是 add）
也断了。谁先用掉这个 relu，谁就关掉另一条路。
今天 mini 的裁决：融合在前 op 更少（4 < 5）；但若传播有机会让两个转置
会合（三明治），收益是整段搬运归零——选谁属于 Cost Model（第 11 周）。

混合链上的顺序表（同一条 10-op 链，不同 Pattern 顺序）：
  推荐(消除->融合->传播)   5 轮 fixpoint   ops=2 T=1 cast=0 R=0 fused=1 hash=c784b0c7 数值=对
  传播优先             5 轮 fixpoint   ops=3 T=1 cast=0 R=0 fused=0 hash=c404512b 数值=对
  融合优先             5 轮 fixpoint   ops=2 T=1 cast=0 R=0 fused=1 hash=c784b0c7 数值=对
  倒序               5 轮 fixpoint   ops=3 T=1 cast=0 R=0 fused=0 hash=c404512b 数值=对
[PASS] 顺序表-推荐与倒序终点可以不同（顺序敏感）（2 个不同终点）
[PASS] 顺序表-所有顺序数值都对

== 4. 意外无限变换：三类现场与驯服 ==
========================================================================

交换规则 V(P(x)) -> P(V(x)) 的合法性 = 算子对可交换。
先数值验证（不凭直觉），(relu, neg) 是反例——它不能进交换规则集：
[PASS] 交换律-transpose×relu 可交换
[PASS] 交换律-transpose×neg 可交换
[PASS] 交换律-transpose×floor 可交换
[PASS] 交换律-relu×floor 可交换
[PASS] 交换律-relu×neg 不可交换（反例）（A[0,0,1]=1.02: relu后neg=-1.02, neg后relu=0.00）

现场一（规则环）：三个可交换算子 {T, relu, floor}，每对都配双向交换规则
（共 6 条，优先级 = 列表顺序，first-match-wins）。
链上 3 个算子共 6 种排列——从每个排列出发看调度器的真实轨迹：
  起点排列              轮次  verdict        轨迹尾部
  transpose->relu->floor   2  oscillation    relu -> transpose -> floor ... transpose -> relu -> floor
  transpose->floor->relu   3  oscillation    floor -> relu -> transpose ... floor -> transpose -> relu
  relu->transpose->floor   2  oscillation    transpose -> relu -> floor ... relu -> transpose -> floor
  relu->floor->transpose   3  oscillation    transpose -> relu -> floor ... relu -> transpose -> floor
  floor->transpose->relu   2  oscillation    floor -> relu -> transpose ... floor -> transpose -> relu
  floor->relu->transpose   2  oscillation    floor -> transpose -> relu ... floor -> relu -> transpose

  第一个起点的完整轨迹（每轮后的算子序列，生产者->消费者）：
    轮0: transpose -> relu -> floor
    轮1: relu -> transpose -> floor
    轮2: transpose -> relu -> floor
[PASS] 规则环-6 个起点全部 oscillation（没有可达的不动点）
[PASS] 规则环-每条规则语义正确（振荡中数值始终不变）
[PASS] 规则环-判定 oscillation（不是 fixpoint）（2 轮）

  每条规则单独存在时都能停（各自到不动点或无事可做）；
  6 条共存后 6 个排列全部流入环——状态空间只有 6 个状态，
  每步必有规则可触发（相邻对总能换向），抽屉原理保证必环。

现场二（undo 对）：fuse_add_relu 与 unfuse_add_relu（后端不支持融合算子时的
物化规则）同场——每条各自都「有用」，合在一起互相撤销：
  跑了 2 轮，verdict=oscillation
    轮0: add -> relu
    轮1: fused_add_relu
    轮2: add -> relu
[PASS] undo对-判定 oscillation（2 轮）
[PASS] undo对-数值仍对

现场三（哈希陷阱）：同样的 fuse/unfuse 振荡，改用**原始 SSA 名字**做状态哈希
（render 里 %N 只增不减）——结构上早就转圈了，哈希却每次都「新鲜」：
  规范化哈希：2 轮检出 oscillation（上面实测 2 轮）
  原始名哈希：40 轮，verdict=max_rounds（只有 max_rounds 兜底，
             真实编译器里这就是超时 / 死循环的现场）
[PASS] 哈希陷阱-原始名哈希测不出振荡（只能 max_rounds 兜底）（40 轮 max_rounds）

驯服：给交换规则一个**规范序**（transpose < relu < floor，按秩排），
只在「逆序」时交换——这就是冒泡排序，逆序数是良基测度：
[PASS] 驯服-起始transpose->relu->floor 0 步排好、总逆序 0->0（逆序轨迹 [0]）
[PASS] 驯服-起始transpose->floor->relu 1 步排好、总逆序 1->0（逆序轨迹 [1, 0]）
[PASS] 驯服-起始relu->transpose->floor 1 步排好、总逆序 1->0（逆序轨迹 [1, 0]）
[PASS] 驯服-起始relu->floor->transpose 2 步排好、总逆序 2->0（逆序轨迹 [2, 1, 0]）
[PASS] 驯服-起始floor->transpose->relu 2 步排好、总逆序 2->0（逆序轨迹 [2, 1, 0]）
[PASS] 驯服-起始floor->relu->transpose 3 步排好、总逆序 3->0（逆序轨迹 [3, 2, 1, 0]）
