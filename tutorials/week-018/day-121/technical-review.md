#### 10. 错误 4 的 bash 机制解释与实测不符
- **原文**：“空字段在冒号分隔里产生两个连续冒号，read 分段错位”
- **依据**：实测 `IFS=':' read -r name flags expect <<< "all-on::5"` 得 `name=all-on, flags=, expect=5`——bash 对非空白 IFS 的相邻分隔符会**保留空字段**，变量数与字段数相同时不错位。要复现 `[: :5: integer expression expected`（expect 被吃成 ":5"），需要变量数少于字段数（如两变量 `read -r a b` 得 `b=":5"`）或串里多一个冒号（`"all-on:::5"` 三变量得 `c=":5"`）——即错位的原因是**字段数多于变量数**，不是“空字段”本身。另外标题称“四元组”，而 run_all.sh 现行 CASES 是三元组（name:flags:expect，run_all.sh:39-44），历史版本无法复原，但所述机制按现行代码形状不成立。

## 【建议】

#### 1. 修复公式括号：`clip(round(v/s)+zp,-128,127)-zp)*s` 缺左括号
- **原文**：“clip(round(v/s)+zp,-128,127)-zp)*s”
- **依据**：该式在“今日目标”、6.1 错误 1 及 `images/03-example.svg` 中共出现 3 次，均缺 `clip(` 的配对左括号（按字面无法求值）。正确写法为 `(clip(round(v/s)+zp,-128,127)-zp)*s`；代码实现（graph_passes.py:195 `float(min(max(round(v / sc) + zp, -128), 127) - zp) * sc`）是正确的，仅文字公式有笔误。
- **置信度**：高。

#### 2. “经过 matmul 的放大”对所引例子不成立
- **原文**：“正是"原值 0.3 vs 格点值 0.296875"经过 matmul 的放大”
- **依据**：实测复现：所引 [1][0] 的差 0.13085873−0.12923494=0.00162，等于 x≈0.52×Δw0.003125——是**缩小**（加权系数<1）；真正被放大的是 [2][0]（0.8499614 vs 0.8544133，x≈1.42）。matmul 对常数误差是按输入元素加权求和，可放大也可缩小，建议改为“按输入加权和传播”，避免“matmul 会放大误差”的错误直觉。
- **置信度**：高（数值已复现）。

#### 3. 代码注释与实际版本/内容不一致
- **原文**：“`code/minic.py`（升级 0.2.0：S1 真实接入，`.graph` 输入走五道闸，五开关＋manifest `s1_switches` 字段）”
- **依据**：minic.py 的模块 docstring 首行仍写“第 120 天核心脚本：minic——统一端到端编译入口的 CLI 骨架（第 18 周第一天）”，与 `VERSION = "minic 0.2.0 (day-121: S1 graph passes)"`（minic.py:29）及 README 的“升级 0.2.0”叙事不一致；graph_passes.py:180 的 gate1 docstring 声称“同参尾对删除（R03）”但函数体内没有 R03 实现（D83 有）。二者都会误导读者核对代码与文档。
- **置信度**：高。

#### 4. 练习 5 “Pass 管道本身是 IR”的提法过于随意
- **原文**：“MLIR 为什么允许 Pass 管道本身是 IR？”
- **依据**：mlir-opt 的 `--pass-pipeline='builtin.module(func.func(canonicalize))'` 嵌套语法属实，但它是按 op 名锚定的文本管道描述（解析成 PassManager 的嵌套结构），并不是 IR 操作序列；“管道本身是 IR”字面不成立。作为开放思考题建议改为“形似 IR 嵌套的文本 DSL”，避免学生把 pipeline 语法误当成 IR。
- **置信度**：中（MLIR 文档层面确认 pipeline 为文本格式而非 IR；措辞问题而非事实硬伤）。
