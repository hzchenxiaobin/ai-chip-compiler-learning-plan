迷你图：t=MatMul(x,w) → y=ReLU(t)   （w 为参数，常驻权重区，不进动态工作区）

-- 生命周期表（闭区间 [def, last_use]，步骤 1..2，0=图前，3=图后）--
张量    类别                字节         活跃区间
x     input    1,048,576 B   [0, 1]
w     param    1,048,576 B   [1, 1]
t     mid      1,048,576 B   [1, 2]
y     output   1,048,576 B   [2, 3]
参数 w 合计 1,048,576 B 常驻权重区，不计入下面的动态峰值。

-- 每步活跃（动态张量：输入+中间+输出）--
步骤 0   存活：x              1,048,576 B
步骤 1   存活：x, t           2,097,152 B
步骤 2   存活：t, y           2,097,152 B
步骤 3   存活：y              1,048,576 B

峰值动态内存 = 2,097,152 B（步骤 1 和 2 打平）

-- 工作区规划（D100：按最后使用点排序＋首次适应，对齐 32 B）--
  偏移          0 B   大小  1,048,576 B   先后住客：x→y
  偏移  1,048,576 B   大小  1,048,576 B   先后住客：t

无复用（每张量独占）      3,145,728 B
共享工作区（本次规划）    2,097,152 B   省 1,048,576 B（33.3%）
峰值活跃集合（理论下界）  2,097,152 B   工作区已达下界：是

>> 主角就位：t 的片外房间在 workspace 偏移 1,048,576 B 处，大小 1,048,576 B。
>> MatMul kernel 的 64 个输出块将轮流把结果写进这 1 MiB——
>> C[0,0]（第一个输出块）写进它的开头 16,384 B。

==============================================================================
第二幕（编译期·闸门）：主角的配置过不过资源关   [D101/D104]
==============================================================================
预算 262,144 B（256 KiB，示例值）    DMA 对齐 32 B

候选 64×64×64 fp32·single +bias
  空间明细 : A 16,384 B + B 16,384 B + C 16,384 B + bias 256 B = 49,408 B
  判定     : ✓ 放行（利用率 18.8%）——旅程获准开始

对照组：128³ fp32·double +bias 合计 328,192 B → ✗ SRAM_OVERFLOW（超 66,048 B）
  ——D103 量出它有 1.32× 纸面加速，D104 一票否决：住不下就是住不下。

配置：single 缓冲，tile 64³，fp32；DMA 32,768 B/µs，计算 262,144 MAC/µs
kernel = 512³ MatMul → 64 个输出块（块 b=(i,j)=64×64，每块 8 圈 k 循环）

① 出生——块 (0,0) 的数据清单（编译期已排好）：
   要读 : bias[0] 256 B + A 切片 8×16,384 B + B 切片 8×16,384 B
   要写 : C 槽 16,384 B（片上累加完再写回 t 房间）
   要算 : 8 × 64³ = 2,097,152 MAC
