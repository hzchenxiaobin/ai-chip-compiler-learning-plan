========================================================================
off-by-one 危害演示：t1 [1,2] 与 t2 [2,4] 端点相接，被当作可共享
========================================================================

正确布局（H3）：t1 @0 [0,1024)、t2 @1152 [1152,1280) → 7 项检查全过

[错误示范] 误判「端点相接 = 区间不相交」，把 t2 搬进 t1 的字节（t2 @0）：
  t1   偏移    0  字节范围 [0, 1024)
  t2   偏移    0  字节范围 [0, 128)
  s    偏移    0  字节范围 [0, 512)
  y    偏移  512  字节范围 [512, 1152)
  x    偏移 1024  字节范围 [1024, 1152)

静态两两检查（共 10 对）：
  ✗ s 与 t2 区间重叠却共享字节
  ✗ t1 与 t2 区间重叠却共享字节

投毒模拟（13 次活跃单元校验）：
  ✗ 步骤 2：t1 在字节 0 读到别人的标记
  ✗ 步骤 3：t2 在字节 0 读到别人的标记
  ✗ 步骤 4：t2 在字节 0 读到别人的标记

两层防线同时报警：静态层报「区间重叠却共享字节」；投毒层报步骤 2 的
t1 被覆盖——正是闭区间的含义：步骤 2 执行时 t1 正在被读、t2 正在被写。
端点相接就是相交，共享判据永远只看区间是否相交。
