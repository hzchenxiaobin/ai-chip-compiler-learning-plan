结构账本 state_hash = a05676ce（两个世界共用同一张图）

-- 视图世界（框架前端：transpose 是 0 字节记账）--
    %1   arg      外部输入 buf-1 24B（不计 traffic）

    %4   reshape  物化 alloc buf2 + 搬运 24B×2
  汇总：traffic=144B  中间分配=3  输出=(6,)(1,)  输入被写=无

两个世界的输出值逐位相等吗？ True

[PASS] 1b 两个世界的中间分配数不同（view 1 vs physical 3）
[PASS] 1c 输出值逐位相等（差别只在内存，不在值）
[PASS] 1d 物理世界 traffic = 视图世界的 3 倍（这条链实测）（144B == 3×48B）

2. 反例 1（精度语义）：f32→f16→f32 的 Cast 往返
========================================================================
图（结构视角）：类型一进一出「对消」，输出 shape 与输入相同——
def @r1
  %1 = arg                                       ; -> (2, 3)
  %2 = cast %1, f32->f16                         ; -> (2, 3)
  %3 = cast %2, f16->f32                         ; -> (2, 3)
  return %3

数值证据：x[0,:] = [ 6.1210938 -7.6679688  1.2539062]
roundtrip 与原值逐位相等的元素：0/6（f16 只有 10 位尾数，f32 有 23 位）

诱人改写（类型对消 → 透传）之后的图：
def @r1
  %1 = arg                                       ; -> (2, 3)
  %2 = cast %1, f32->f16                         ; -> (2, 3)
  return %1
[PASS] R1a 诱人改写后数值不再逐位相等（6/6 变值，实测）（不同元素 6/6）
[PASS] R1b Day 67 守卫版拒绝触发（src≠dst 不是无操作）
[PASS] R1c 对照：同 dtype Cast 守卫版能消，物理世界省 48B（96B -> 48B）
守卫清单：Cast 只在 src==dst 时透传；f32→f16 还把后续 buffer 从 24B 缩到 12B——它是「变窄」的物化点，不是改名。

4. 反例 3（别名语义）：copy(x) 值上恒等，消除后写集合漂移
========================================================================
图（结构视角）：copy 是值上的恒等映射，「看似冗余」——
def @r3
  %1 = arg                                       ; -> (2, 3)
  %2 = copy %1                                   ; -> (2, 3)
  %3 = relu %2                                   ; -> (2, 3)
  return %1, %3

-- 后端把逐元素算子编成原地 kernel（in-place）时的内存账本 --
    %1   arg      外部输入 buf-1 24B（不计 traffic）
    %2   copy     alloc buf0 + 拷贝 24B×2（buf-1->buf0）
    %3   relu     原地写 buf0 (读+写 24B×2)
  保留 copy：traffic=96B  中间分配=1  输出=(2, 3)(3, 1) × (2, 3)(3, 1)  输入被写=无

消除 copy 之后（值世界看起来毫无变化）：
def @r3
  %1 = arg                                       ; -> (2, 3)
  %3 = relu %1                                   ; -> (2, 3)
  return %1, %3
    %1   arg      外部输入 buf-1 24B（不计 traffic）
    %3   relu     原地写 buf-1 (读+写 24B×2)  ← 写进了外部输入！
  消除 copy：traffic=48B  中间分配=0  输出=(2, 3)(3, 1) × (2, 3)(3, 1)  输入被写=[-1]
[PASS] R3a 值世界看不见差别（纯函数 eval 逐位相等）
[PASS] R3b 内存世界第一个输出被污染（x ≠ 原 x）
[PASS] R3c 写集合漂移：写 buf1 → 写 buf0（外部输入）（[] -> [-1]）
[PASS] R3d 污染可观测：消除后 return 的 x 变成了 relu(x)
守卫清单：copy 消除需要别名分析——「源缓冲此后只读」或「所有消费者都不原地写」才允许删；这正是 MLIR bufferization 里 bufferizesToMemoryWrite 分析做的事。

6. 反例 5（布局语义）：恒等排列的 transpose，值上照抄、内存上物化
========================================================================
图（结构视角）：第二个 transpose 的 perm=(0,1)，「值上什么都不做」，还有两个 reshape 消费它——
def @r5
  %1 = arg                                       ; -> (2, 3)
  %2 = transpose %1, perm=[1, 0]                 ; -> (3, 2)
  %3 = transpose %2, perm=[0, 1]                 ; -> (3, 2)
  %4 = reshape %3, to=[6]                        ; -> (6,)
  %5 = reshape %3, to=[3, 2]                     ; -> (3, 2)
  return %4, %5

消除恒等转置之后（值世界毫无变化）：
def @r5
  %1 = arg                                       ; -> (2, 3)
  %2 = transpose %1, perm=[1, 0]                 ; -> (3, 2)
  %4 = reshape %2, to=[6]                        ; -> (6,)
  %5 = reshape %2, to=[3, 2]                     ; -> (3, 2)
  return %4, %5

-- 视图世界（p 本来就是 0 字节视图）--
  保留 p：traffic=96B  中间分配=2  输出=(6,)(1,) × (3, 2)(2, 1)  输入被写=无
  消除 p：traffic=96B  中间分配=2  输出=(6,)(1,) × (3, 2)(2, 1)  输入被写=无
  → 消除免费：traffic 不变、还少一个 op。在纯视图世界它确实「看似能消除」而且真能消除。

-- 物化世界（p 是 strided→连续 的布局转换，Day 68 的 linalg 世界）--
  保留 p：traffic=48B  中间分配=1  输出=(6,)(1,) × (3, 2)(2, 1)  输入被写=无   ← p 搬 48B，两个 reshape 全变 0B 视图
  消除 p：traffic=96B  中间分配=2  输出=(6,)(1,) × (3, 2)(2, 1)  输入被写=无   ← 两个 reshape 各自被迫拷贝
  → 同一个改写：traffic 48B→96B 翻倍。物化点的价值是「把布局转换摊销到所有消费者」，删掉它，
    拷贝没有消失，只是搬进每个消费者的实现里、还翻了倍。
[PASS] R5a 视图世界：消除恒等转置 traffic 不变（真的免费）（96B == 96B）
[PASS] R5b 物化世界：消除后 traffic 翻倍（48B -> 96B）（48B -> 96B）
[PASS] R5c 四种执行的输出值全部逐位相等（差别只在内存账本）
[PASS] R5d 物化世界保留 p 时，两个 reshape 都是 0B 视图
[PASS] R5e numpy 佐证：视图与物化值相等、共享关系相反、reshape 权利相反
守卫清单：恒等排列只证明「值语义是照抄」；能不能删要看消费者数量与布局契约——单消费者时消除是 traffic 中性的（拷贝挪个地方），多消费者时物化点摊销布局转换，删了翻倍。图上同一个 transpose 节点，两个世界两种身份。
