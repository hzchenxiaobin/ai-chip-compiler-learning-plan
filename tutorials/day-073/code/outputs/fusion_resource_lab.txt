== 1. 机器假设卡 + 假设清单（今天的产出之一）==
  机器：toy-core v0（全部结论只在这张卡上成立，换卡重算）
  寄存器堆 64 KiB / 片上 SRAM 192 KiB / 并行通道 64 / fp32
  片上总容量 = 64 KiB + 192 KiB = 256 KiB
  A1 机器参数是玩具假设（量级参照真实硬件：GPU 一个 SM 的寄存器堆约 256 KiB、共享存储约 48~228 KiB；NPU 的 Cube/Vector 配 Unified Buffer），可整体替换重算
  A2 活集（live set）= 峰值时刻必须同时在片的中间值字节；输入默认按需流过，不计入活集
  A3 有数据复用的输入（MatMul 的 A/B 分块）驻 SRAM；无复用的输入（如 bias D，每元素只用一次）流式读、不驻留
  A4 spill 按每字节一写一读两趟计（下界）；累加器在 K 循环中反复改写的 RMW 放大不计（真实溢出更贵）
  A5 逐元素 kernel 的活集 = 每通道在飞（输入＋输出）向量，与数据总量无关（流式）
  A6 MatMul 的累加器块（tile_m × tile_n）常驻寄存器跨 K 循环；融合进来的逐元素 epilogue 复用累加器槽，只额外要每通道 1 个在飞槽
  A7 并行度 proxy = 资源允许的并发 tile 数 = min(寄存器堆/每 tile 累加器, SRAM/每 tile 输入分块)，下限 1
  A8 不计 kernel launch、多核分发、跨核 SRAM 竞争、指令缓存与编译时间
  A9 收益口径沿用第 72 天（无缓存复用、compulsory 理想下界）；净收益 = ΔB − spill 流量
  A10 MatMul→MatMul 融合假设好调度（中间行块驻 SRAM、消费者横扫输出 tile），不计重算/重读放大；输入分块的 SRAM 需求今天不建模（记在 A8 的不计项里）
[PASS] 1a 假设清单共 10 项且无空项
[PASS] 1b 片上总容量 = 寄存器堆 + SRAM = 262,144 B

== 5. 反例：融合 MatMul(2048,64)→G(2048,K1)→MatMul(K1,2048) ==
