# 04：数据、证据与后续迭代

> 范围：P1/P2，不属于 P0 上线阻塞项  
> 目标：在不破坏 P0 静态内容层和本地学习层的前提下，逐步增加证据、复习、项目档案、L2 CI 和可选同步。  
> 详细实现以 `07`—`14` 为准；本文保留共享数据边界与架构摘要。

## 1. 版本边界与实施前提

| 能力 | 最早阶段 | 前置条件 | 明确边界 |
|---|---|---|---|
| 结构化自测、复习、卡点 | P1 | P0 进度 Schema 稳定 | 不做公开排名，不用断签惩罚 |
| `evidence.json` 本地导入 | P1 | 独立 Schema、大小与安全校验 | 本地脚本结果只标 L1+ |
| 项目档案 | P1 | 证据模型与五类项目文档映射 | 不默认公开个人代码 |
| L2 CI 复验 | P1 试点 | 固定工作流、commit 绑定、可信验证方 | 静态前端不能仅凭 URL 认证 L2 |
| 账号同步 API | 可选 P1 | 明确隐私与冲突策略 | 不是其他 P1 功能的前置 |
| L3 隔离实验 | P2 | 沙箱、配额、私有测试、安全审计 | 不在 GitHub Pages 前端执行 |

P1 开发应单独建工作包和迁移版本，不为了“兼容未来”在 P0 建立空用户系统。升级前必须能导出 v1 进度，升级失败不得删除原库。

## 2. 证据模型

### 2.1 `evidence.json` 示例

```json
{
  "schema_version": 1,
  "evidence_id": "01J...ULID",
  "level": "L1+",
  "day_id": "day-140",
  "tutorial_commit": "40位教程提交哈希",
  "learner_commit": "40位学习者提交哈希",
  "executed_at": "2026-11-24T09:20:00Z",
  "environment": {
    "os": "Ubuntu 22.04",
    "arch": "x86_64",
    "cpu": "仅记录用户明确提供的型号",
    "memory_gb": 32,
    "llvm": "18.x",
    "compiler": "clang++ 18",
    "mlir_opt": "18.x",
    "runtime": "本地 WSL2"
  },
  "command": "bash run_all.sh",
  "exit_code": 0,
  "summary": {"passed": 1, "failed": 0, "skipped": 0},
  "tests": [
    {"name": "lit lowering", "status": "passed"}
  ],
  "performance": {
    "hardware": "CPU 型号与关键内存信息",
    "input": {"shape": [128, 256, 512], "dtype": "f32"},
    "config": {"tile": [64, 64, 64], "flags": ["--fuse"]},
    "baseline": "未融合、同编译器与同输入",
    "warmup_runs": 10,
    "measured_runs": 50,
    "statistic": "median",
    "baseline_ms": 12.5,
    "optimized_ms": 8.2,
    "environment_commit": "环境或测量脚本提交"
  },
  "ci_url": null,
  "notes": "可选纯文本备注"
}
```

`0.0` 只能作为 Schema 示例中的占位类型说明，真实性能值必须大于 0；不能将占位值导入并参与展示。

### 2.2 字段规则

- `evidence_id` 可使用 ULID、随机 UUID 或 `local-day029-20261124T092000Z` 这类本地标识；限制为 1—128 个安全 ASCII 字符。导入时不信任其唯一性，还需按内容哈希去重。
- `level` 枚举为 `L1/L1+/L2/L3`；学习者自报为 L1，本地脚本自动生成为 L1+。
- `day_id` 必须存在；`tutorial_commit` 必填且为 40 位哈希，`learner_commit` 可为 40 位哈希或 `null`。`environment.os/llvm/compiler/mlir_opt` 必填；无代码文档日不得在 evidence-v1 中暗中省略工具链字段，需另行评审明确的 `kind=document_declaration` Schema。
- `command` 是展示性声明，不在浏览器执行，不作为 shell 参数拼接，不自动打开。
- `exit_code` 为整数；非零时证据可保存，但不能显示“验收通过”。
- `tests.status` 仅允许 `passed/failed/skipped`；存在 failed 时证据状态为“未通过”。
- `ci_url` 仅允许 `https://`，限制 GitHub Actions 或明确支持的 CI 域名；链接本身不构成复验。
- `summary` 为包含 `passed/failed/skipped` 非负整数的摘要对象，并与 tests 汇总一致；`notes` 有长度上限并纯文本渲染，禁止 HTML、Markdown 自动链接和内嵌脚本。

### 2.3 性能证据

性能对象若缺少硬件、工具链、输入 Shape、Tile、基线、预热、重复次数或统计口径，允许保存为“不完整实验记录”，但不能进入“可比较性能证据”视图。已提供的 `baseline_ms/optimized_ms` 必须为正数，非正值导入校验失败；`warmup_runs/measured_runs` 为非负/正整数；`statistic` 支持 `mean/median/p95`，未知统计方式不能进入比较视图。

页面只能显示同一证据内的变化，例如 `(baseline - optimized) / baseline`，并同时展示环境和输入。禁止跨硬件生成总排行榜，禁止只显示“提升 2 倍”而隐藏基线、Shape 和测量次数。

## 3. 证据导入与存储

P1 可将 IndexedDB 升至版本 2，新增：

```text
exercise_attempts:
  keyPath: attempt_id
  indexes: item_id, day_id, answered_at
evidence:
  keyPath: evidence_id
  indexes: day_id, executed_at, evidence_hash
review_items:
  keyPath: item_id
  indexes: due_at, day_id, status
stuck_items:
  keyPath: stuck_id
  indexes: day_id, status, updated_at
```

迁移只新增表和索引，不删除 `progress/meta`。`DayProgress.latest_evidence_id` 仅在证据事务提交成功后更新；证据删除时保留审计选择需另行评审，P1 默认不级联删除进度。

导入限制建议：单文件 1 MiB、单批 200 条证据、每条 tests 不超过 200 项、notes 不超过 10,000 字符。完整控制台日志留在本机或 CI，不塞进导入文件。所有文件先完整预检，再显示级别分布、失败测试、性能条目和未知日课；用户确认后导入。

**级别降级规则：**通过文件导入的 L2/L3 声明，若没有可信验证方的签名或服务器验证记录，一律保存为“声明级别”，展示仍按 L1+ 处理。不能因为 JSON 写了 `level: "L2"` 就显示已复验。

## 4. 本地证据生成脚本

P1 可提供显式本地工具 `tools/learning_evidence.py`，由学习者在教程仓库或自己的分支中主动运行：

```bash
python3 tools/learning_evidence.py \
  --day day-140 \
  --tutorial-commit "$(git rev-parse HEAD)" \
  --learner-commit "$(git -C /path/to/learner rev-parse HEAD)" \
  --output evidence.json \
  -- bash run_all.sh
```

要求：

- `--` 后的命令是用户明确输入的本地命令；脚本使用参数数组，不经过 shell 字符串拼接。
- 默认只保存退出码、测试摘要和必要环境，不收集环境变量、文件路径中的用户名、token 或完整日志。
- 捕获输出设大小上限，密钥模式默认脱敏； stdout/stderr 原文件不自动上传。
- 脚本生成只能标 L1+，即使退出码为 0 也不代表本站复验。
- 性能数据由用户显式提供测量结果文件，脚本校验正数和统计字段，不自动编造基准。

## 5. 复习与结构化自测

### 5.1 数据边界

自测题以 Markdown 或独立结构化内容源维护，不写入学习记录。学习记录只保存题目版本、作答结果和下次复习时间。内容更新采用与 `content_sha` 类似的 `item_version`，保留历史并标记复核。

P1 的复习项至少包含：

```json
{
  "item_id": "day-029:q-01",
  "day_id": "day-029",
  "item_version": "题目内容哈希",
  "due_at": "2026-11-25T09:00:00Z",
  "interval_index": 0,
  "last_result": null,
  "last_reviewed_at": null,
  "revision": 0
}
```

### 5.2 确定性调度

P1 初版采用设计文档规定的可解释间隔序列 `[1, 7, 28]` 天，并允许用户在设置中调整：

- “需重学”：索引归零，1 天后到期。
- “基本掌握”：索引前进一级，最高到 28 天。
- “已掌握”：索引前进两级，最高到 28 天；连续答对可在后续版本评审后延长。

到期时间从用户首次提交本次作答的 UTC 时间计算；显示按本地日期，避免跨时区导致当天列表抖动。离线期间不错过内容，所有过期项排在最前，不做断签惩罚。该算法是 P1 产品规则，如需调整必须升 `review_algorithm_version`，不能静默改写历史。

### 5.3 复习页面

P1 `/review/` 显示今日到期、过期、所属日课和预计项数。作答前隐藏答案，提交后再显示解释；键盘可完成全部操作。完成复习不自动把日课 acceptance 标为 done，两个动作保持独立。

## 6. 卡点管理

卡点记录至少包含 `stuck_id/day_id/task_id/title/details/status/created_at/updated_at/revision`，状态为 `open/resolved`。`details` 仅本地纯文本，默认不上传；限制长度并转义。

将任务标为 `blocked` 时，P1 可提示创建卡点，但不是必填；解除卡点不删除历史，状态改为 resolved 并保留解决说明。`DayProgress.stuck_item_ids` 只保存当前关联 ID，派生日状态仍以四项任务中的 blocked 为准，避免“卡点已开但任务显示完成”的矛盾。

P0 的 `stuck_item_ids=[]` 在迁移时保持不变，不能因用户曾标记 blocked 就伪造一条详细卡点。

## 7. 项目档案 `/portfolio/`

项目档案把第 18 周起的 `minic` 成果组织为个人只读视图：统一编译入口、Runtime 三件套、测试金字塔、Pass 二分定位、性能回归，以及架构、Pass、Lowering、测试、性能五份文档。

数据来源优先级：用户主动关联的本地证据 > 用户填写的本地项目链接 > 教程公开模板。没有证据的槽位显示“待补充”，不能自动生成“已掌握”。

档案默认仅本机可见；导出为 JSON 或 Markdown 前显示将包含的字段。仓库 URL 仅允许 HTTPS 并作为普通链接展示，不抓取私有仓库、不保存访问 token、不把学习记录公开到 GitHub Pages。

## 8. L2 CI 复验

### 8.1 可信条件

L2 必须同时满足：

1. 工作流由课程项目或受信验证仓库固定维护，workflow 文件版本可追踪。
2. 教程 commit、学习者仓库和 learner commit 在工作流输入与检出结果中一致。
3. CI 实际执行指定测试并产生机器可读结果，不是手动填写 success。
4. 验证方通过 GitHub API/签名 artifact 核验 workflow ID、run ID、head SHA、conclusion 和时间。
5. 验证记录与证据 ID 绑定，后续修改 JSON 不会改变已验证摘要。

静态前端没有可信服务端密钥，也无法凭跨域读取的公开 CI 页面防止伪造，因此不能独立完成 L2 认证。

### 8.2 工作流安全

- 使用 `workflow_dispatch` 或受控 `pull_request`，禁止对不可信代码使用 `pull_request_target` 并检出执行。
- `permissions: contents: read`，不传 Pages 部署权限、私有包凭证或云密钥。
- 设置 job 和步骤超时、磁盘/日志上限，禁用不必要的缓存写入。
- 明确检出完整 learner commit，并验证其属于声明仓库；禁止分支名替换 commit。
- 对学习者代码而言，GitHub-hosted runner 是临时环境，但仍按不可信代码处理，不访问内部网络资源。
- 部署工作流与复验工作流完全分离，复验失败不能影响线上教程。

### 8.3 验证记录

验证服务返回独立 attestation：`evidence_hash/day_id/tutorial_commit/learner_commit/workflow_id/run_id/head_sha/conclusion/verified_at/verifier_version`。前端只有同时拿到匹配证据和有效 attestation 才展示 L2。

## 9. L3 隔离实验

L3 属于 P2，需要独立威胁模型和一次性 microVM 或经独立评审的等价强隔离：非 root、只读根文件系统、无特权、无 Docker socket、网络默认关闭、CPU/内存/进程/磁盘/时间配额、独立验证域中的平台私有测试、输出限制、销毁验证和独立签名。普通非 root 容器本身不构成 L3；用户代码不能接触验证服务凭证、私有测试正文或其他学习者数据。

在这些能力实现前，即使网站有“运行”按钮，也不能标 L3；P0/P1 均不开放此入口。

## 10. 可选同步 API

### 10.1 最小接口

```text
GET    /v1/changes?since=<cursor>&limit=100
GET    /v1/progress?since=<cursor>&limit=100
PUT    /v1/progress/{day_id}          If-Match: <revision>
POST   /v1/progress/merge
PUT    /v1/review-items/{item_id}     If-Match: <revision>
POST   /v1/exercise-attempts
PUT    /v1/stuck-items/{id}           If-Match: <revision>
POST   /v1/evidence
GET    /v1/portfolio
PUT    /v1/portfolio/{slot}           If-Match: <revision>
GET    /v1/export
DELETE /v1/account/data

POST   /v1/verification-requests               # WP-11 独立 Verification API
GET    /v1/attestations/by-evidence/{hash}     # 只读证明，不在同步 API 写入
```

同步协议以服务端账号为边界，各实体按 ID＋revision 做整记录乐观锁，写入使用 `If-Match`；409 返回本机与服务端双方版本，由用户选择，不做字段级时间戳拼接。`planned` 的显式唯一化、删除 tombstone 和证据 attestation 需要服务端事务或审计。API 不接收静态站管理密钥，前端只保存短期会话或安全 Cookie。

### 10.2 隐私与降级

- 同步默认关闭，用户明确开启；本地模式继续完整可用。
- 搜索词、完整日志、个人代码默认不上传；笔记和证据分别授权。
- 提供导出和删除账号数据，删除任务可审计。
- 离线变更排队必须有可见状态，不能显示“已同步”直到服务端确认。
- 服务端不可用时不得阻塞阅读和本地保存。

## 11. P1/P2 验收门槛

- v1→v2 数据库迁移不丢失任何 P0 记录，可回滚代码且不破坏旧导出。
- 证据导入不执行命令、不注入 HTML、不自动开窗，L2/L3 声明会按验证结果降级。
- 性能证据字段完整、正值校验有效，不跨硬件排名。
- 复习算法确定、时区测试通过、没有断签惩罚。
- 卡点历史可追溯，项目档案不默认公开。
- L2 有可信 attestation，L3 有真实隔离与配额；否则界面不显示相应可信级别。
