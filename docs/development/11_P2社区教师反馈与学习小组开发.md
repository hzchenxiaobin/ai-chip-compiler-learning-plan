# 11：P2 社区、教师反馈与学习小组开发

> 工作包：WP-14（协作与治理，分独立 feature flag）  
> 对应范围：FR-015 的社区部分，以及教师反馈、cohort 学习  
> 前置：真实协作需求、主站账号、管理员与治理责任人  
> 原则：公开讨论、私密反馈和小组共享是三种不同数据边界，不混用权限。

## 1. 分阶段交付

1. `community.github`：用 GitHub Issue/Discussion 模板承载公开讨论，本站只生成带日课上下文的链接。
2. `community.hosted`：确有审核与检索需求后，在主应用中建立独立 Community 模块或部署独立服务。
3. `teacher.feedback`：教师对被授权的提交做私密结构化反馈。
4. `learning.cohorts`：学习小组、共享节奏与教师查看范围。

任一能力关闭时，公开教程、MySQL 学习记录、P1 证据和复习继续工作。不得用公开排行榜或强制锁课制造活跃度。

## 2. GitHub 讨论模板路径

模板字段：day_id、content_commit、可选 learner_repository/commit、脱敏 environment、symptom、expected/actual、minimal_reproduction、attempts、public_confirmation。

前端只预填 day_id、content_commit、教程链接和脱敏检查清单，不自动附个人笔记、完整日志或私有仓库地址。URL 过长时打开空白模板，不使用第三方短链。发布前明确“发布后公开”；危险 URL 不自动打开。

GitHub 公开讨论不满足私密教师反馈和小组权限需求。该子能力只代表公开讨论入口，不代表 hosted/teacher/cohort 已完成。

## 3. Hosted Community 架构与角色

```text
Django 动态页面 / Community UI
  ↔ Community 模块或独立 Community API
      ├── 独立 Schema/DB：讨论、评论、举报、审核、通知
      ├── 私有附件存储：扫描、隔离、授权下载
      └── 主站账号：短期身份断言，只读取最小用户资料
```

如果独立部署，主站与 Community 使用服务身份和最小 API scope，不共享 MySQL root。默认不把个人进度、卡点、证据或项目档案传给社区。

| 角色 | 公开讨论 | 私密反馈 | 小组数据 | 管理 |
|---|---|---|---|---|
| 匿名 | 可读公开内容 | 无 | 无 | 无 |
| 学习者 | 管理本人内容 | 管理本人提交、读授权反馈 | 仅已授权字段 | 举报 |
| 教师 | 普通参与 | 仅被分配提交 | 仅所在 cohort 授权字段 | 无全局管理 |
| 审核员 | 隐藏/恢复/处理举报 | 默认不可读私密提交 | 默认不可读 | 审核审计 |
| 管理员 | 配置与授权 | 不默认读取正文 | 不默认读取正文 | 权限与审计 |

管理员权限不等于自动内容读取权；紧急访问需要 break-glass、理由和审计。

## 4. 社区数据与 API

表：`CommunityThread`、`CommunityComment`、`Reaction`、`Report`、`ModerationAction`、`NotificationPreference`、`Attachment`。公开内容软删使用 tombstone，作者删除按政策显示“内容已删除”而不保留正文。

API：

- `GET/POST /api/v1/community/threads/`
- `GET/PATCH/DELETE /api/v1/community/threads/{id}/`
- `POST /api/v1/community/threads/{id}/comments/`
- `POST /api/v1/community/reports/`
- `POST /api/v1/moderation/actions/`
- `GET/PATCH /api/v1/me/notification-preferences/`

写操作需要认证、CSRF（浏览器会话）、If-Match、请求大小限制和限流。列表游标稳定，通知可退订。标题、正文、评论和 snippet 全部安全渲染。

## 5. 内容安全与审核

Markdown 采用服务端白名单，链接仅 http/https，图片经代理或受控上传；不允许脚本、表单、iframe 和危险 data URL。附件先进入隔离区，校验真实 MIME、大小、扩展、恶意内容和图片炸弹，扫描通过后才可见。

审核状态：`visible/hidden/removed/appealed/restored`，每次操作记录 actor、原因、时间和目标。用户可举报和申诉；审核员不能修改学习者证据有效级别。速率限制按账号和风险控制，不公开完整 IP。

## 6. 私密教师提交与反馈

### 6.1 提交授权

`TeacherSubmission` 包含 owner、day/project、submission_version、材料清单、状态、assigned_teacher、撤回时间。每个材料 ID 逐项授权，默认不包含全部学习记录。

状态：

```text
draft → submitted → assigned → in_review → returned
           │           │           │
           └────────── withdrawn   └→ resubmitted（创建新 version）
```

撤回后教师不能继续访问新版本；已产生反馈的保留与删除按政策处理。重新提交创建新 submission_version，教师可比较被授权版本，不修改学习者原记录。

### 6.2 反馈

`TeacherFeedback` 包含 rubric、逐项评论、总体建议、draft/returned 状态、submission_version 和教师身份。草稿仅教师可见，returned 后学习者可见。教师修改已返回反馈需保留历史。

教师反馈不是 L2/L3 复验，不能改变 EvidenceRecord effective_level，也不能直接完成学习者的 acceptance。

## 7. Cohort 与字段级共享

表：`Cohort`、`CohortMembership`、`ShareGrant`、`CohortPlan`、`CohortAnnouncement`。

ShareGrant 明确 grantor、grantee/cohort、entity_type、entity_id 或范围、fields、valid_from/to、revoked_at。字段示例：当前日、周完成、是否遇到卡点；卡点正文、笔记、证据附件、项目私密版本默认不共享。

- 加入小组不等于全量共享，逐项展示授权预览。
- 退出或撤销后停止新读取，已有导出/截图不能承诺收回。
- 教师只能看被分配 cohort 和有效授权字段。
- 学习者可以调整自己的节奏；未跟上计划不扣分、不公开羞辱。
- cohort 计划不会静默覆盖 LearningPlan，采用需学习者显式确认。

## 8. 附件、通知与隐私

私密提交和社区附件使用不同对象前缀与权限策略。下载检查当前授权，不传播永久签名 URL。通知只含最小摘要和站内链接，邮件正文不附私密反馈全文。

数据导出包含本人社区内容、提交、反馈和授权历史；删除公开内容、私密提交和账号分别处理。法律/安全保留项必须明确，不借审核名义无限保留全部私密数据。

## 9. 降级与独立回滚

Community API 故障时公开教程、账号和学习进度继续可用；已打开编辑表单显示未保存。教师/cohort 故障不能阻塞证据导入和复习。

各 flag 独立回滚：关闭 GitHub 模板只移除入口；关闭 hosted 不删除已有数据；关闭教师/cohort 先停止新授权并保留导出渠道。不得通过取消权限校验换取可用性。

## 10. 验收

- `P2-TC-COMMUNITY-01`：GitHub 模板真实、安全、公开确认。
- `P2-TC-COMMUNITY-02`：Markdown/附件注入和恶意文件被拒绝。
- `P2-TC-COMMUNITY-03`：举报、隐藏、恢复、申诉和审计。
- `P2-TC-COMMUNITY-04`：CRUD、If-Match、分页、限流、通知退订。
- `P2-TC-COMMUNITY-05`：删除 tombstone、私密删除和主站降级。
- `P2-TC-TEACHER-01`：材料逐项授权、分配、撤回和版本隔离。
- `P2-TC-TEACHER-02`：rubric、草稿/返回、重交历史、不提升证据等级。
- `P2-TC-COHORT-01`：字段级授权、撤销、退出和教师范围。
- `P2-TC-COHORT-02`：非惩罚计划、采用确认和不覆盖个人计划。
- 每个子能力独立灰度，只声明实际通过的范围。
