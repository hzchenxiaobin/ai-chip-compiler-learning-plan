# 11：P2 社区、教师反馈与学习小组开发

> 工作包：WP-14（协作与治理，分独立 feature flag）  
> 对应范围：FR-015 的社区部分，以及指南中的教师反馈、cohort 学习  
> 前置：真实协作需求、管理员与治理责任人；个人数据同步不是公开分享的前置  
> 原则：公开讨论、私密反馈和小组共享是三种不同数据边界，不混用权限。

## 1. 分阶段交付

WP-14 不一次性上线综合社区，按以下独立开关交付：

1. `community.github`：先用 GitHub Issue/Discussion 模板承载公开讨论，本站只生成带日课上下文的链接。
2. `community.hosted`：确有审核与检索需求后，部署独立 Community API。
3. `teacher.feedback`：教师对被授权的提交做私密结构化反馈。
4. `learning.cohorts`：学习小组、共享节奏与教师查看范围。

任一能力关闭时，公开教程、本地进度、P1 证据和复习继续工作。不得用公开排行榜或强制锁课制造小组活跃度。

## 2. GitHub 讨论模板路径

日课“报告内容问题/讨论本日”生成仓库 Issue 或 Discussion 入口，模板字段：

```text
day_id（自动带入，可改）
content_commit（默认当前提交）
learner_repository + learner_commit（可选，公开前确认）
environment（OS/工具链，脱敏）
symptom / expected / actual
minimal_reproduction
attempts
public_confirmation（必须主动勾选）
```

前端只预填 day_id、content_commit、教程链接和脱敏检查清单，不自动附本地笔记、完整日志或私有仓库地址。URL 长度超限时打开空白模板让用户粘贴，不通过第三方短链。

验收：链接指向真实仓库模板，无 token；预览明确“发布后公开”；危险 URL 不自动打开。GitHub 路径不满足私密教师反馈和小组权限需求，后两者必须使用独立服务。

## 3. Hosted Community 架构与角色

```text
Pages 静态社区外壳
  ↔ Community API（独立域名/服务）
  ├── Community DB：讨论、评论、举报、审核、通知
  ├── Object Storage：经检查的文本/图片附件
  └── Learning API：仅验证用户身份，不默认读取私密学习记录
```

角色权限：

| 角色 | 公开讨论 | 私密反馈 | 小组数据 | 管理 |
|---|---|---|---|---|
| learner | 发帖/评论/编辑自己的内容/举报 | 查看本人提交及已返回反馈 | 只看自己加入小组及主动共享材料 | 无 |
| teacher | 同 learner | 对分配提交写反馈 | 只看自己负责小组和共享字段 | 不能管理全站用户 |
| moderator | 审核、隐藏、处理举报 | 默认不可看私密反馈 | 只看审核必需元数据 | 审核动作留痕 |
| admin | 配置角色、保留策略、关闭功能 | 不默认读取内容 | 小组配置 | 高权限操作需审计和二次确认 |

社区用户 ID 与 Learning API user_id 映射，但数据库和权限边界独立。教师不是全站超级用户，公开 attestation 也不代表教师评价。

## 4. 讨论与附件模型

```text
Discussion:
  id, author_id, day_id, content_commit, learner_commit?,
  title, body, environment_json, minimal_repro?, error_excerpt?,
  status[visible|under_review|hidden|deleted],
  created_at, updated_at, edited_at, revision, moderation_state

Comment:
  id, discussion_id, author_id, parent_id?, body,
  status, created_at, updated_at, edited_at, revision

Attachment:
  id, owner_id, kind[text_log|image], storage_key,
  size_bytes, mime_detected, sha256, scan_status, created_at

Report / ModerationAction:
  reporter_id, target_type, target_id, reason, status,
  moderator_id?, action, note_internal, created_at, appeal_status
```

body 使用受限 Markdown：允许段落、列表、代码块和安全链接，不允许原始 HTML、脚本、data:text/html 或自动图片代理到任意内网 URL。编辑保留 revision 和 edited_at；删除是内容 tombstone，审核记录不随用户删除而隐蔽消失。

附件初版只允许纯文本日志（最大 1 MiB）和 PNG/JPEG/SVG 安全处理后的图片（最大 5 MiB）。SVG 默认转 PNG 或按严格 sanitizer 处理，禁止脚本、外部资源和 foreignObject。附件上传先隔离扫描，通过后才公开；不提供可执行二进制下载。

## 5. 讨论 API 与防滥用

| 接口 | 用途 | 权限与限制 |
|---|---|---|
| `GET /v1/discussions?day_id=&cursor=` | 公开列表 | 分页，隐藏内容不泄露 |
| `POST /v1/discussions` | 创建讨论 | 登录、公开确认、正文长度和频率限制 |
| `GET/PATCH /v1/discussions/{id}` | 查看/编辑 | If-Match；仅作者或审核权限 |
| `POST /v1/discussions/{id}/comments` | 评论 | 登录、公开确认、限流 |
| `POST /v1/reports` | 举报 | 防止重复举报和恶意刷屏 |
| `POST /v1/moderation/actions` | 隐藏/恢复/处理举报 | moderator，双人复核可配置，必留审计 |
| `POST /v1/attachments` | 创建受控上传 | 类型/大小限制、扫描后发布 |

初始速率预算：每用户每分钟创建 3 个讨论、10 条评论、20 次举报操作之外还需异常行为限流；这些是配置默认值，按真实使用调整。API 使用 CSRF/CORS 防护、请求体限制、分页上限和服务端授权，不能靠前端隐藏按钮。

通知默认只向本人相关讨论发送，营销提醒默认关闭；邮件/ webhook 不包含完整私密内容，退订无需管理员介入。

## 6. 私密教师反馈

### 6.1 提交与授权

学习者创建 `FeedbackSubmission`：选择 day_id、learner_commit、artifact/evidence_ids、希望获得的反馈和可见教师/小组。只有显式关联的材料进入提交，不自动上传全部 DayProgress、复习、卡点或仓库。

状态机：

```text
draft → submitted → assigned → in_review → returned
           │          │             └→ changes_requested → submitted（新版本）
           │          └→ cancelled
           └→ cancelled
```

每次重新提交产生新的 submission_version，旧反馈不可覆盖。教师只能看到分配给自己的版本；学习者可在 returned 前撤回未开始评审的提交。

### 6.2 反馈结构

```text
TeacherFeedback:
  id, submission_id, submission_version, teacher_id,
  rubric_items[{criterion_id, rating, comment}],
  strengths, next_experiment, references[{day_id, anchor}],
  status[draft|returned], created_at, updated_at, returned_at, revision
```

rubric 由课程维护，例如正确性、最小复现、数值验证、性能口径、文档解释。教师反馈是人工学习建议，不能将 L1+/L2 自动提升为 L3；只有平台隔离私有测试满足 WP-16 才能标 L3。

接口包括 `POST /v1/feedback-submissions`、`POST /v1/feedback-submissions/{id}/assign`（教师协调者）、`PUT /v1/feedback/{id}`、`POST /v1/feedback/{id}/return`。所有读写按 submission 的 learner/assigned_teacher 做行级权限。

## 7. Cohort 学习小组

`Cohort` 包含 owner_teacher_id、title、timezone、start/end、join_policy、status；`CohortMember` 包含 user_id、role、joined_at、left_at、sharing_consent_version。小组可配置计划周和关键产出，但不修改个人 DayProgress，不强制每日锁课。

学习者共享按字段授权：可选择“当前日/周状态”“指定证据”“指定项目槽位”“open 卡点”。教师和其他成员只能看到共享字段；私有 notes、未共享证据、完整学习历史默认不可见。退出小组后停止新访问，已有教师反馈和公开讨论按各自保留策略处理，不假装所有副本瞬间消失。

小组仪表盘显示关键产出完成、待补和自愿求助，不显示跨硬件性能排名、学习时长排名或连续打卡羞辱。节奏调整只对小组未来计划生效，不改教程权威源。

## 8. 治理、隐私与删除

- 发布前显示公开范围、日课/commit、日志与代码脱敏预览；公司专有代码默认禁止公开。
- 社区规则、举报、审核、申诉和 moderator 审计必须在公开上线前可用。
- 用户删除自己的讨论采用 tombstone；他人回复保留上下文时显示“作者内容已删除”。
- 私密反馈与小组数据导出/删除接口独立于公开讨论，说明保留期限和法律/安全审计例外。
- 管理后台不返回完整个人学习记录，敏感操作有审计、二次确认和最小权限。
- Community API 故障时静态日课和本地卡点可用；用户可导出本地内容稍后重试。

## 9. 测试与验收

| 编号 | 场景 | 通过条件 |
|---|---|---|
| P2-TC-COMMUNITY-01 | GitHub 模板 | 日课/commit 正确，公开确认与脱敏提示有效，不自动上传 |
| P2-TC-COMMUNITY-02 | Markdown/附件 | XSS、SVG 脚本、危险 URL、超限文件被安全处理或拒绝 |
| P2-TC-COMMUNITY-03 | 审核权限 | learner/teacher/moderator/admin 越权用例全部拒绝，动作留痕 |
| P2-TC-COMMUNITY-04 | 并发与滥用 | If-Match、分页、限流、重复举报和通知退订有效 |
| P2-TC-TEACHER-01 | 私密提交 | 教师只见分配版本，未共享学习数据不可见 |
| P2-TC-TEACHER-02 | 反馈版本 | 重交保留旧反馈，人工反馈不提升 L3 |
| P2-TC-COHORT-01 | 小组共享 | 按字段授权，退出后停止访问，无私密 note 泄露 |
| P2-TC-COHORT-02 | 非惩罚机制 | 无强制锁课/跨硬件排名，小组计划不改个人进度 |
| P2-TC-COMMUNITY-05 | 降级与删除 | API 故障不影响教程，本地可导出，公开/私密删除语义清楚 |

WP-14 的每个 feature flag 独立准出；GitHub 模板上线不能证明 hosted 社区、教师反馈或 cohort 已完成。
