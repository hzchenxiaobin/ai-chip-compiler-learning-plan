# 07：P1 自测、复习与卡点开发

> 工作包：WP-08（P1 内容与存储基础）、WP-09（自测/复习/卡点）  
> 对应需求：FR-010、FR-012  
> 前置：P0 的 26 个用例通过，`days.json`、`DayProgress` 和 Store v1 已稳定  
> 原则：公开答案只用于自测；复习帮助回忆，不自动替代日课验收。

## 1. 交付范围与模块边界

本迭代交付结构化题包、先答后看解析、尝试记录、1/7/28 天复习、错题重试、卡点记录和周复盘联动。不交付防作弊考试、公开分数榜、AI 自动评分和强制每日复习。

```text
题包 JSON/Markdown（Git 权威源）
  → tools/learning_assessments.py
  → public/learning/assessments/manifest.json
  → public/learning/assessments/phase-N.json

static/js/learning/
  assessment.js  # 题目渲染、答案校验、尝试记录
  review.js      # 确定性调度、到期队列、复习页
  stuck.js       # 卡点 CRUD、解决历史、周复盘联动
  store.js       # v2 迁移与统一导出，不另开数据库
```

WP-08 先冻结 Schema 和迁移；WP-09 再开发交互。题包正文不进入 IndexedDB，浏览器只保存版本、答案和调度状态。

## 2. 题包内容契约

### 2.1 文件组织

题目优先与日课同目录维护：

```text
tutorials/week-005/day-029/
├── README.md
├── assessment.json       # 无题日可不创建
└── ...
schemas/assessment-pack-v1.json
config/learning/review-policy.json
tools/learning_assessments.py
```

每题必须引用真实日课和已生成锚点。初始题型：`single_choice`、`multiple_choice`、`short_answer`。短答案只提供评分要点和自评，不用字符串相似度宣称自动判对。

```json
{
  "schema_version": 1,
  "day_id": "day-029",
  "items": [{
    "item_id": "day-029:q-01",
    "kind": "single_choice",
    "skill_ids": ["MLIR", "JIT"],
    "prompt": "哪项检查最能证明当前 mlir-opt 与预期工具链一致？",
    "options": [
      {"option_id": "a", "text": "只看命令能否在 PATH 中找到"},
      {"option_id": "b", "text": "核对版本并运行一个已知输入的最小测试"},
      {"option_id": "c", "text": "只要终端没有立即报错即可"}
    ],
    "answer": {"option_ids": ["b"]},
    "explanation": "版本与最小闭环需要同时验证，具体步骤回到本日环境检查。",
    "source_anchor": "环境检查",
    "review_eligible": true,
    "difficulty": "foundation"
  }]
}
```

`item_version` 不手写在源文件中，构建器对单个题目的规范 JSON（排除该字段）计算 SHA-256。选项顺序在源文件中有意义，运行时如需洗牌必须保存本次 `option_order`，不能用当前时间做不可复现随机种子。

### 2.2 构建产物

`manifest.json` 包含 `schema_version/content_commit/review_algorithm_version/phases`；每个阶段分片包含该 28 天题目、日课 URL、来源锚点和 `item_version`。首页不加载题包；日课页只加载当日或所在阶段分片，复习页按到期 item_id 再加载对应阶段。

构建校验：

- `item_id` 全站唯一且属于当前 `day_id`；选项 ID 在题内唯一。
- 单选答案恰一项，多选至少一项且答案均存在；短答案必须有评分要点。
- `source_anchor` 在日课 HTML 中存在，`skill_ids` 非空，`review_eligible` 为布尔值。
- prompt、选项、解析和评分要点长度受限；原始内容可含 Markdown，但渲染器只允许白名单标记。
- 修改题干、答案、选项、解析或来源均改变 `item_version`；仅修改构建时间不改变。

## 3. IndexedDB v2 与导出升级

### 3.1 统一迁移

P1 核心版本在 WP-08 一次性完成 v1→v2，避免自测与证据分别升级造成版本交错：

```text
progress            # P0 原表保留
meta                # P0 原表保留
exercise_attempts   # keyPath attempt_id；索引 item_id、day_id、answered_at
review_items        # keyPath item_id；索引 due_at、day_id、status
stuck_items         # keyPath stuck_id；索引 day_id、status、updated_at
evidence            # keyPath evidence_id；索引 day_id、executed_at、evidence_hash
```

升级事务只新增表和索引，不重算、不清空 P0 任务，不把历史 blocked 伪造成详细卡点。`meta.schema_migrations` 记录版本、时间和结果；升级失败整个事务 abort，旧数据库仍可打开。

P1 备份使用 `learning-backup-v2.json`，顶层包含 `days/exercise_attempts/review_items/stuck_items/evidence`。v2 尚无可信证明时，证据仅保存声明和导入状态。v1 备份继续可导入，缺失的新实体按空数组处理；v2 导出不能被 P0 旧前端假装识别，应显示版本不支持。

### 3.2 导入策略

先完整预检全部实体，再复用 P0 的合并/替换预览。`DayProgress` 仍按 day_id＋revision；新实体按各自 ID＋revision；ExerciseAttempt 以追加为主，同 ID 不同内容列为冲突。替换前备份扩展为完整 v2 数据，不只保存 days。

所有导入文本纯文本或受限 Markdown 渲染，不执行命令、不自动打开链接。单实体未知字段被报告并忽略，未来主版本整批拒绝。

## 4. `ExerciseAttempt` 与自测逻辑

```json
{
  "schema_version": 1,
  "attempt_id": "01J...ULID",
  "item_id": "day-029:q-01",
  "day_id": "day-029",
  "item_version": "64位题目哈希",
  "answer": {"option_ids": ["b"]},
  "option_order": ["a", "b", "c"],
  "result": "correct",
  "answered_at": "2026-11-24T09:20:00Z",
  "explanation_viewed_at": "2026-11-24T09:20:01Z",
  "duration_ms": 12400,
  "revision": 0
}
```

`result` 为 `correct/incorrect/self_reported`；多选只有完全匹配才 correct，不做部分分避免误导。短答案提交后展示评分要点，由用户选择“需要重学/基本掌握/已掌握”，记录 self_reported，不计算客观正确率。

核心纯函数：

```javascript
gradeChoice(item, answer) -> "correct" | "incorrect"
createAttempt(item, answer, now, optionOrder) -> ExerciseAttempt
shouldOfferReview(attempt) -> boolean
getItemVersionState(attempts, currentVersion) -> "current" | "needs_review"
```

答案提交后才解锁解析；解析查看时间单独记录。重新作答新增 attempt，不覆盖旧尝试。题目版本变化时保留旧题答案并显示“题目已更新”，不把旧 correct 算到新版本正确率。

## 5. 复习调度

### 5.1 数据模型

```json
{
  "schema_version": 1,
  "item_id": "day-029:q-01",
  "day_id": "day-029",
  "item_version": "当前复习的题目版本",
  "status": "active",
  "algorithm_version": "interval-1-7-28-v1",
  "interval_days": [1, 7, 28],
  "interval_index": 0,
  "due_at": "2026-11-25T09:20:00Z",
  "last_result": "again",
  "last_reviewed_at": "2026-11-24T09:20:00Z",
  "needs_review": false,
  "revision": 1
}
```

`status` 为 `active/suspended`；暂停不删除历史。自定义间隔必须为 1—365 天的严格递增整数，最多 5 级，修改后只影响下一次调度，不批量重写已有 due_at。

### 5.2 纯函数与规则

```javascript
createReviewItem(item, now, policy) -> ReviewItem
scheduleReview(reviewItem, result, now, policy) -> ReviewItem
getDueQueue(items, now, currentWeek) -> ReviewItem[]
rescheduleOverdue(items, now) -> ReviewItem[]  # 仅显式“重排”时调用
```

初始加入复习时 `interval_index=0`，`due_at=now+interval_days[0]`。提交复习结果：

- `again`：索引归零，`due_at=now+interval_days[0]`。
- `good`：索引加一，最大到最后一级，`due_at=now+interval_days[新索引]`。
- `easy`：索引加二，最大到最后一级，`due_at=now+interval_days[新索引]`；在 `[1,7,28]` 中不会创造文档之外的间隔。

到期队列先按过期时长降序，再按 due_at、item_id 排序；当前周与前几周轻度交错，但不得把大量过期项隐藏。离线期间不惩罚、不归零、不自动生成断签提示。用户显式“重排本周复习”时可把过期项分布到未来 7 天，操作前预览，原调度历史通过 revision 保留。

## 6. 复习页与日课集成

`/review/` 分为“今日到期、错题、卡点、历史实验”四组；历史实验只链接证据模块，不在 WP-09 提前实现证据导入。页面先显示问题，提交后显示答案、解析、来源日课和代码/IR 链接。

日课页增加“开始自测”和“加入复习”。加入复习只创建/恢复 review_item，不修改 DayProgress；复习答对也不自动把 exercise/acceptance 标为 done。若用户从自测发现困难，可显式创建卡点或将练习标 blocked。

周复盘页显示本周到期题、最近错题和未解决卡点，允许把 open 卡点加入下周首项任务。该动作只调整展示优先级或 planned，不删除原卡点、不强制锁课。

## 7. 卡点模型与状态联动

```json
{
  "schema_version": 1,
  "stuck_id": "01J...ULID",
  "day_id": "day-097",
  "task_id": "experiment",
  "title": "调整 Tile 后数值结果不一致",
  "symptom": "优化前后输出出现超出预期的差异",
  "environment": {"os": "Ubuntu 22.04", "toolchain": "LLVM 18"},
  "minimal_repro": "最小输入、Shape 与命令说明，不包含个人绝对路径",
  "error_excerpt": "脱敏后的关键错误，最多4000字符",
  "attempts": [{"text": "回退单个 Pass 后结果恢复", "created_at": "2026-11-24T09:20:00Z"}],
  "links": ["https://github.com/example/example/issues/1"],
  "status": "open",
  "resolution": null,
  "created_at": "2026-11-24T09:00:00Z",
  "updated_at": "2026-11-24T09:20:00Z",
  "resolved_at": null,
  "revision": 2
}
```

创建 open 卡点时询问是否将对应任务标 blocked；不强制。解决时保存 `resolution` 和 `resolved_at`，任务需用户另行选择 in_progress/done，防止“关闭了文本卡点”自动伪造验收。重新打开保留原解决历史并新增 revision。

标题、环境、最小复现、报错、尝试和解决均限制长度；链接仅 HTTPS 白名单，不自动抓取。默认只存本机，公开到社区前必须进入 P2 脱敏预览。

## 8. 事务、性能与无障碍

- 提交答案在一个事务写 attempt＋可选 review_item；任何失败都回滚，并保留表单内容供重试。
- 复习页首屏最多 50 项，分页加载；统计按 item_id 和 item_version 聚合，不全量渲染正文。
- 所有选项使用原生表单，解析区域用 `aria-live="polite"` 适度通知，不自动把焦点跳到页面底部。
- 320 px、200% 字体、键盘和读屏可完成作答、自评、查看来源与创建卡点。
- 离线时内容分片已缓存才可作答；未加载题包明确提示，不用本地旧题冒充当前版本。
