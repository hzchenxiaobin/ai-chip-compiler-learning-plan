## 1. 交付范围与模块边界

交付结构化题包、先答后看解析、尝试记录、`[1,7,28]` 复习、错题重试、卡点记录和周复盘联动。不交付防作弊考试、公开分数榜、AI 自动评分和强制每日复习。

```text
题包 JSON（Git 权威源）
  → tools/learning_assessments.py / manage.py import_tutorial
  → QuestionSet / QuestionVersion（MySQL 可重建内容读模型）

学习者操作
  → /api/v1/me/attempts/、/api/v1/me/reviews/、/api/v1/me/stuck-items/
  → ExerciseAttempt / ReviewItem / StuckItem（MySQL 权威业务数据）
  → 日课、复习页、周复盘和我的学习
```

WP-08 冻结 Schema、Django migration 和导出扩展；WP-09 开发交互。题包不进入个人导出正文，只记录 question_version_id、答案和结果。

## 2. 题包内容契约

### 2.1 文件组织

```text
tutorials/week-005/day-029/
├── README.md
├── assessment.json       # 无题日可不创建
└── ...
schemas/assessment-pack-v1.json
config/learning/review-policy.json
tools/learning_assessments.py
```

题型为 `single_choice`、`multiple_choice`、`short_answer`。短答案只提供评分要点和自评，不用字符串相似度宣称自动判对。所有 source_anchor 必须存在于同一 active release 的日课锚点。

```json
{
  "schema_version": 1,
  "day_id": "day-029",
  "items": [{
    "item_id": "day-029:q-01",
    "type": "single_choice",
    "skill": "MLIR",
    "prompt": "验证工具链时，最先应该确认哪一组信息？",
    "source_anchor": "环境检查",
    "options": [
      {"option_id": "a", "text": "mlir-opt、FileCheck 与 JIT 的版本和可用性"},
      {"option_id": "b", "text": "直接跳过环境并开始编写大型 Dialect"}
    ],
    "answer": ["a"],
    "explanation": "先固定工具版本和最小运行结果，再定位后续问题。",
    "review_eligible": true
  }]
}
```

`item_version = SHA256(JCS(去除导入时间后的完整 item))`。答案变更会生成新 QuestionVersion，旧 ExerciseAttempt 保持原版本。

### 2.2 校验

- item_id 在日课内唯一且不允许复用到不同语义。
- 单选 answer 恰一项；多选至少一项且去重；option_id 全部有效。
- 短答案没有 `answer`，必须有 rubric 数组和自评选项。
- prompt、选项、解释和 rubric 为纯文本或严格白名单 Markdown，不注入 HTML。
- 每题引用真实 day_id、source_anchor、skill；review_eligible 为布尔。
- 未配置题包的日课不显示空自测按钮。

## 3. MySQL 模型与迁移

| 表 | 关键字段与约束 |
|---|---|
| `question_set` | release、day_id、pack_sha；`(release,day_id)` 唯一 |
| `question_version` | set、item_id、item_version、payload_json；同版本唯一 |
| `exercise_attempt` | user、question_version、answers_json、score、passed、self_rating、created_at |
| `review_item` | user、day、question_version NULL、step、due_at、state、algorithm_version、revision；按策略唯一 |
| `stuck_item` | id/user/day、title、description、state、revision、created/updated/deleted_at |
| `stuck_event` | stuck、event_type、safe_metadata_json、created_at |

迁移按 expand→migrate→contract：先新增表和索引，再启用读写。导出 Schema 升主版本只影响导出文件，不把 Django migration 重命名为“Store v2”。P1 必须继续读取 P0 的 v1 导出；旧 P0 应用遇到不支持的 v2 文件应明确拒绝或只读，不得静默丢弃新增实体。

## 4. 自测 API 与事务

- `GET /api/v1/days/{day_id}/assessment/`：返回当前题包，不含不应提前显示的答案/解析。
- `POST /api/v1/me/attempts/`：提交 question_version_id、answers 和客户端 attempt UUID。
- `GET /api/v1/me/attempts/?day_id=&cursor=`：本人历史。
- `POST /api/v1/me/reviews/from-attempt/`：把可复习题加入队列。

服务端取题时校验版本，客观题在服务端判分。响应再返回答案、解析、得分和 source URL。提交事务写 ExerciseAttempt 并可创建 ReviewItem；attempt UUID 唯一防止双击重复。

失败不显示“已记录”；版本过期返回 409，让用户对新版本作答，旧历史不删除。

## 5. 复习调度

配置：

```json
{
  "schema_version": 1,
  "algorithm_version": "interval-v1",
  "intervals_days": [1, 7, 28],
  "again_minutes": 10,
  "max_daily_new": 20,
  "overdue_penalty": false
}
```

`good` 使用当前 step 对应间隔并前进一步；`easy` 使用下一档间隔并最多前进两步；`again` 保持 step，10 分钟后到期。超过最后一档后循环 28 天或采用明确配置的长期间隔。暂停使用 state，不通过修改历史伪造完成。

所有完成时间保存 UTC，同时保存用户 IANA 时区用于“本地学习日”展示。算法输入为完成时间、step、评分和 algorithm_version；不得读取当前随机数。离线未使用不扣分、不清空队列、不制造断签惩罚。

- `GET /api/v1/me/reviews/?due_before=&cursor=`
- `POST /api/v1/me/reviews/{id}/grade/`，使用 revision/If-Match。
- `POST /api/v1/me/reviews/{id}/pause/`，`DELETE` 或显式 resume 按路由约定实现。

到期队列按 due_at、day、id 稳定排序，可配置周交错。超过 50 项分页，不把全部记录塞入首页。

## 6. 自测与复习界面

自测按“作答→提交→查看解释→加入复习”顺序；未提交前不通过 DOM 隐藏字段泄露客观题答案。解释链接回真实日课锚点。短答案展示 rubric 后由用户选择“未掌握/部分掌握/已掌握”，记录 self_rating，不称自动评分。

复习页显示到期数、逾期数和暂停状态，不显示负面 streak。作答后可选择 again/good/easy，按钮有快捷键和读屏名称。复习通过不会自动把 DayProgress acceptance 设为 done。

网络失败保留未提交答案于内存并显示未保存；P0 默认刷新会丢失未提交答案，需要页面明确提示。只有 WP-13 开启时才支持离线 outbox。

## 7. 卡点模型与 API

字段包括：day_id、标题、环境、最小复现、预期/实际、报错摘录、已尝试、下一步、解决记录和关联证据 ID。报错与描述按纯文本渲染，URL 仅允许 http/https 且用户主动点击，不自动打开或 fetch。

状态：`open→investigating→resolved`，可 reopened；归档与软删分开。每次状态/解决变更写 StuckEvent，保留历史。列表按日、状态和周筛选，敏感内容默认仅本人可见。

API：

- `GET/POST /api/v1/me/stuck-items/`
- `GET/PATCH /api/v1/me/stuck-items/{id}/`
- `POST /api/v1/me/stuck-items/{id}/resolve/`
- `DELETE /api/v1/me/stuck-items/{id}/`

PATCH 使用整记录 revision＋If-Match。删除采用 tombstone 以便未来离线防复活；公开社区和教师反馈需要另行显式授权，不因创建卡点自动共享。

## 8. 周复盘与数据管理

周复盘列出本周新增/解决卡点、复习到期和关键产出缺口。用户可以把未解决卡点转为下周行动项，但 action item 只是个人计划备注，不自动完成 Day 6/7 或改写主计划。

导出 v2 增加 attempts、reviews、stuck 和事件，不包含题包正文、其他用户数据或内部密钥。导入先预检：题包版本不存在时保留记录并标记 unresolved_reference，不猜映射到最新题。替换前快照覆盖所有新增实体。

删除日课关联学习数据时按明确范围处理 attempts/reviews/stuck；删除卡点不删除证据。功能 flag 关闭后只隐藏写入口，用户仍可导出和请求删除。
