# 09：P1 L2 CI 复验与证明开发

> 工作包：WP-11（L2 CI 试点）  
> 对应需求：支撑 FR-011，服务公开项目证据  
> 前置：WP-10 证据哈希、声明/有效级别分离  
> 原则：L2 是“指定 commit、受信工作流与公开测试的复验”，不是防作弊考试或平台证书。

## 1. 可信边界与部署形态

L2 由三部分共同成立：学习者仓库中的准确 commit、固定维护的验证工作流/测试清单、独立验证方读取 GitHub 元数据与 artifact 后签发的 attestation。只有 CI 链接、绿色徽章或导入 `level:L2` 都不够。

```text
学习者公开仓库/准确 commit
  → 调用固定 commit 的受信 reusable workflow
  → 临时 GitHub-hosted runner 执行公开验证测试
  → 上传 evidence.json + run metadata（无秘密）
  → Verification API 校验 repo/run/head SHA/workflow/artifact/hash
  → 使用验证方私钥签发 attestation
  → 前端按 evidence_hash 关联并把有效级别提升为 L2
```

Pages 静态站只保存验证方公钥和 API 地址。签名私钥、GitHub App 私钥、artifact 下载凭证和限流管理密钥只存在验证服务或密钥管理系统中。

## 2. 试点范围与验证清单

首批只选 Day 029、Day 097、Day 160，分别覆盖 MLIR 环境、性能实验和干净复现。每日清单由受信仓库维护：

```text
verification/
├── manifests/day-029.json
├── manifests/day-097.json
├── manifests/day-160.json
├── .github/workflows/learning-verify.yml
├── runner/                  # 固定测试驱动，不采用学习者可改的证据生成器
└── verifier-version.json
```

```json
{
  "manifest_version": 1,
  "day_id": "day-029",
  "tutorial_commit": "允许的教程提交或明确兼容列表",
  "test_suite": "public-mlir-smoke",
  "test_suite_sha": "测试套件内容哈希",
  "caller_template_sha": "受信caller工作流模板规范化后的SHA-256",
  "image": "ghcr.io/example/learning-verify@sha256:固定摘要",
  "timeout_seconds": 300,
  "artifact_retention_days": 30
}
```

教程兼容列表必须显式维护，不能让任意 tutorial_commit 都套用同一测试。性能日复验只确认测量流程和结果文件，不把不同学习者硬件上的数字变成统一排名。

## 3. 受信工作流

### 3.1 调用约定

首批只支持 `workflow_dispatch`。学习者仓库的 caller 必须使用受信模板，唯一的 `verify` job 通过 `uses` 引用**完整 commit SHA** 的 reusable workflow；输入只有 day_id 和 tutorial_commit。learner_commit 必须由 runner 根据本次 run 的 `github.sha` 和实际检出结果重新解析，不能信任调用方手填。

```yaml
name: learning-verify
on:
  workflow_dispatch:
    inputs:
      day_id:
        required: true
        type: string
      tutorial_commit:
        required: true
        type: string
permissions:
  contents: read
concurrency:
  group: learning-verify-${{ github.repository }}-${{ github.ref }}
  cancel-in-progress: true
jobs:
  verify:
    uses: trusted-org/learning-verifier/.github/workflows/learning-verify.yml@40位受信工作流提交SHA
    with:
      day_id: ${{ inputs.day_id }}
      tutorial_commit: ${{ inputs.tutorial_commit }}
```

受信 reusable workflow 内部依次解析准确仓库/head SHA、检出 learner commit、按固定 SHA 检出 runner/manifest、验证教程兼容、执行公开测试、生成并校验 evidence、计算哈希和上传 artifact。服务器还校验 caller 规范化模板哈希与 job 图；新增 caller step/job、改变 `uses`、权限或输入都会使模板不匹配，不能获得证明。

### 3.2 安全规则

- 禁止 `pull_request_target` 检出并执行不可信代码；不使用自托管 runner。
- 不传 Pages、包发布、云账号、签名或学习 API 密钥；`permissions` 只读。
- 固定 action、runner 脚本和容器 digest；禁止从 learner 配置动态扩展 action。
- 测试命令由受信 runner 决定，学习者可修改被测产品代码，但不能替换测试清单、结果 Schema 或 artifact 上传步骤。
- job/step 超时、日志大小和 artifact 大小设上限；缓存只读或不使用，禁止不可信代码写受信缓存。
- 依赖下载与测试阶段分开；测试阶段无凭证。GitHub-hosted runner 是临时环境，但不因此宣称能抵御所有恶意代码或侧信道。
- 复验工作流与教程部署完全分离，复验失败不能阻断或覆盖公开教程。

## 4. Artifact 与服务器校验

artifact 至少包含 `evidence.json`、`run-context.json` 和 `manifest.json`，不包含完整环境变量、私有日志或学习者秘密。验证服务执行：

1. 通过 GitHub API 读取 `repository.id/full_name`、`run.id/run_attempt/head_sha/event/conclusion/workflow_id`。
2. 确认 run 属于声明仓库且 conclusion=success，head_sha 与 evidence.learner_commit 相同。
3. 读取本次 run 实际使用的 caller 文件，重算规范化 `caller_template_sha`，确认只有一个调用受信 reusable workflow 的 job，且仓库、路径、完整 SHA、权限和输入均在允许列表。
4. 下载当前 run_attempt 中由该受信 job 按固定名称产生的 artifact，检查 run/attempt 绑定、ZIP 路径、大小、条目数、文件 hash 和 Schema；同名多余 artifact、来源不明或缺失均拒绝。
5. 重算 caller_template_sha、test_suite_sha、evidence_hash、image digest 与 tutorial/day 绑定。
6. 确认该 evidence_hash 未被不同 repo/commit/run 的冲突证明占用。
7. 校验成功后签发；任何字段不一致都拒绝并记录不含秘密的原因码。

公开仓库优先使用 GitHub App 的只读安装或受控 API 凭证；私有仓库不是默认试点范围。API 限流、缓存和 backoff 不能改变验证结果，也不能把 rate limit 当作“无数据”。

## 5. Attestation Schema

```json
{
  "schema_version": 1,
  "attestation_id": "01J...ULID",
  "level": "L2",
  "evidence_hash": "64位证据哈希",
  "day_id": "day-029",
  "tutorial_commit": "40位教程提交",
  "learner_repository": "owner/repo",
  "learner_repository_id": 123456789,
  "learner_commit": "40位学习者提交",
  "workflow": {
    "repository": "trusted-org/learning-verifier",
    "path": ".github/workflows/learning-verify.yml",
    "ref": "40位受信工作流提交",
    "caller_template_sha": "64位caller模板哈希",
    "run_id": 123456,
    "run_attempt": 1,
    "head_sha": "40位学习者提交"
  },
  "test_suite_sha": "64位测试套件哈希",
  "image_digest": "sha256:固定镜像摘要",
  "conclusion": "success",
  "verified_at": "2026-11-24T10:00:00Z",
  "expires_at": "2027-11-24T10:00:00Z",
  "verifier_version": "l2-verifier-v1",
  "key_id": "l2-2026-01",
  "signature": "对规范化payload的Ed25519签名，Base64URL编码"
}
```

签名输入为剔除 `signature` 后的 JCS payload。验证方使用独立 L2 密钥，发布 `kid` 对应公钥和密钥轮换清单；L3 密钥不得复用。attestation 默认有效期一年是初始产品策略，不代表结果永久有效；过期后证据仍保留，但 L2 标识改为“证明已过期，需重新复验”。

## 6. Verification API

| 接口 | 请求 | 响应与权限 |
|---|---|---|
| `POST /v1/verification-requests` | repository、run_id、run_attempt、evidence_hash、day_id | 创建校验任务；匿名也限流，不能传管理 token |
| `GET /v1/verification-requests/{id}` | 请求 ID | queued/validating/verified/failed 及公开原因码 |
| `GET /v1/attestations/by-evidence/{hash}` | evidence_hash | 已签证明或 404；不泄露私有仓库信息 |
| `GET /v1/attestations/{id}` | attestation ID | payload、签名、公钥 kid 与状态 |
| `POST /internal/verification-jobs/{id}/complete` | 内部 worker 结果 | 仅服务间认证，浏览器不可调用 |

创建请求做幂等：repository/run/attempt/evidence_hash 相同返回已有任务。状态机为 `queued→validating→verified|failed`；verified 不可变，重新运行产生新 run_attempt 和新证明。

错误码至少包括 `RUN_NOT_SUCCESS`、`HEAD_SHA_MISMATCH`、`WORKFLOW_UNTRUSTED`、`CALLER_TEMPLATE_MISMATCH`、`ARTIFACT_INVALID`、`ARTIFACT_SOURCE_INVALID`、`EVIDENCE_HASH_MISMATCH`、`MANIFEST_UNSUPPORTED`、`RATE_LIMITED`。失败信息不返回 artifact 原文或凭证。

## 7. 前端关联与展示

`attestation.js` 只负责下载证明、检查 Schema、使用公钥验签和匹配证据哈希；有效级别由 store 事务更新。验签失败、key 不存在、证明过期或 repo/commit/day 不匹配时保持原级别并显示原因。

页面展示：L2、测试类型（公开测试）、指定教程/学习者 commit、受信 workflow/run、验证方版本、验证时间和 CI 链接。不能简化为“官方认证”“防作弊通过”。用户删除本地证据不删除服务器公开 attestation；撤销策略需验证服务记录 key/run/evidence 撤销状态并在前端显示。

## 8. 测试、发布与回滚

- 单元测试覆盖 JCS、签名、kid 轮换、过期、撤销和所有原因码。
- 集成测试使用模拟 GitHub API/artifact，验证 run_attempt 重跑、fork、错误 workflow、篡改 head_sha 和 hash。
- 安全测试确认 learner 修改自身 caller、测试脚本、证据文件或 artifact 名称都不能获得有效证明。
- E2E 从 L1+ 导入→请求校验→获得证明→刷新后 L2 保留；API 失败不丢本地证据。
- 验证服务独立灰度，先只开放三天；签名密钥轮换可回滚公钥清单，旧证明按 kid 可验证。
- 服务故障不阻断 Pages、证据导入或本地学习；永不通过“跳过验签”维持可用性。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| P1-TC-CI-01 | 正常公开 CI | repo/run/head/workflow/artifact/hash 全部匹配后签发 |
| P1-TC-CI-02 | 篡改 commit/caller/workflow | 任一不匹配均拒绝，新增 caller step/job 也不能签发，原因码明确 |
| P1-TC-CI-03 | 修改学习者测试 | 受信测试清单不依赖学习者修改，伪造证据无效 |
| P1-TC-CI-04 | 重跑与幂等 | run_attempt 绑定正确，重复请求不重复签发 |
| P1-TC-CI-05 | 验签与轮换 | 旧 kid 可验，未知 key/坏签名/过期/撤销不显示有效 L2 |
| P1-TC-CI-06 | 权限与秘密 | 工作流只读，无部署/签名密钥，日志无敏感值 |
| P1-TC-CI-07 | 服务降级 | API/GitHub 限流不影响本地学习，不伪造 L2 |
