# 10：P1 项目档案与可选同步开发

> 工作包：WP-12（项目档案）、WP-13（可选账号同步）  
> 对应需求：FR-013、FR-014  
> 前置：WP-10；L2 展示依赖 WP-11  
> 原则：项目档案默认本机私有；同步默认关闭，两者互不强制绑定。

## 1. 项目档案范围

`/portfolio/` 将第 18 周后的 `minic` 成果、五份项目文档、性能、干净复现和表达材料组织为个人证据视图。公开静态模板可以展示“应该交付什么”，个人证据只在本地渲染，不进入 GitHub Pages 产物。

```text
config/learning/portfolio-slots.json
tools/learning_portfolio.py          # 只生成公共模板和槽位定义
static/js/learning/portfolio.js      # 私有聚合、导出与视图模型
schemas/portfolio-v1.json
IndexedDB v3: portfolio_items
```

WP-12 将数据库升至 v3，只新增 `portfolio_items`（keyPath `slot_id`，索引 `updated_at`），不重写 v2 证据和复习数据。

```json
{

    "source_day_ids": ["day-159"],
    "required": true,
    "accepted_artifacts": ["document", "evidence"],
    "minimum_evidence": "L1+"
  }, {
    "slot_id": "reproduction",
    "title": "干净环境复现",
    "source_day_ids": ["day-160"],
    "required": true,

```

完整槽位为 `project_entry/architecture/passes/lowering/testing/performance/reproduction/presentation/final_assessment`，并补充 `runtime/regression` 项目能力。日课映射集中在注册表，不散落在 JS 条件语句中。Day 155—159 对应架构、Pass、Lowering、测试、性能五份文档，Day 167/168 对应表达和最终验收；实际 URL 仍由 days.json 提供。

`minimum_evidence` 只表示可进入档案的最低材料级别，不自动证明掌握。性能比较仍需 WP-10 的 comparisonKey；L2/L3 只有有效 attestation 才能显示。

## 3. `PortfolioItem` 与派生状态

```json
{
  "schema_version": 1,
  "slot_id": "performance",
  "artifact_url": "https://github.com/owner/repo/blob/commit/docs/performance.md",
  "artifact_hash": "可选的文档内容SHA-256",
  "evidence_ids": ["local-day159-20261124T092000Z"],
  "learner_commit": "40位提交或null",
  "note": "私有简短说明",
  "visibility": "private",
  "updated_at": "2026-11-24T10:00:00Z",
  "revision": 1
}
```

URL 只允许 HTTPS 和经过校验的站内路径；站点不抓取私有仓库、不保存访问 token。`visibility` 初版只有 `private/public_preview`，后者仅用于生成用户主动导出的公开预览，不会触发上传。

`getPortfolioStatus(slot, item, evidence)` 返回：

- `missing`：无 artifact 且无证据。
- `declared`：只有链接或 L1 自声明。
- `local_evidence`：存在有效 L1+ 证据。
- `ci_verified/platform_verified`：存在匹配且未过期/撤销的 L2/L3 证明。
- `incomplete`：性能或复现材料缺关键字段，不能进入“可复现”视图。

总览同时显示材料完整度与最高可信级别，不能把“所有槽位都有链接”写成“项目已复现”。缺失槽位提供对应日课链接，不自动复制教程模板充当个人成果。

## 4. 档案编辑、导出与公开预览

编辑操作包括关联证据、填写 HTTPS artifact 链接、修改 note、移除槽位材料；所有操作在 v3 事务中完成并增加 revision。证据删除后槽位状态重新派生，不级联删除证据本体。

导出 JSON 使用 `portfolio-v1.json`，包含槽位、artifact 元数据、证据摘要和 attestation 引用，不包含签名密钥或完整日志。Markdown 导出前显示逐字段预览：用户可取消私有 note、个人路径、失败记录和未公开仓库链接；Markdown 链接、代码块和表格内容必须转义，防止导出后产生意外 HTML/链接。

公开预览是下载到本机的静态文件，不自动部署。默认不包含个人学习进度、复习、卡点和完整环境信息。分享前再次提示移除密钥、用户名路径和公司专有代码。

## 5. 可选同步架构

WP-13 只有在真实跨设备需求成立后启动。参考实现为独立 `learning-api`（Hono＋Drizzle＋MySQL），也可替换技术栈，但 API、权限和同步语义不变。公开教程继续由 Pages 提供，API 故障不影响本地模式。

```text
浏览器本地 Store v4 + sync_outbox
  ↔ HTTPS Learning API（HttpOnly 会话）
  ↔ MySQL：用户、记录、版本、删除标记、审计
Verification API / L3 服务：独立部署，不与同步 API 共享执行权限
```

新增 IndexedDB v4：`sync_outbox`（keyPath operation_id，索引 state/created_at）与 `sync_state`（keyPath entity_key）。不同步的用户不需要登录，也不创建云端账号数据。

## 6. 登录、会话与授权

采用 GitHub OAuth Authorization Code＋PKCE，由后端完成 code 交换；不得把 client secret 放静态前端。服务端校验 state、nonce、PKCE 和回调地址，会话写入 `HttpOnly; Secure; SameSite=Lax` Cookie，浏览器不保存 OAuth access token 到 localStorage。

跨域 Pages 与 API 使用精确 CORS origin、允许凭证和 CSRF token；写请求校验 Origin/CSRF。Session 表只存哈希后的随机会话 ID、user_id、过期时间和撤销时间。账号默认只保存 GitHub 用户 ID、登录名和必要会话信息，真实姓名、生日等不采集。

授权以 `user_id` 为行级边界，所有查询必须带所有者条件；attestation 可公开读取，但不能通过同步 API 修改。教师/社区角色属于 WP-14，不给普通同步用户隐含教师权限。

## 7. 服务端数据表

| 表 | 关键字段 | 约束与用途 |
|---|---|---|
| `users` | id、github_id、login、created_at、deleted_at | github_id 唯一，最小资料 |
| `sessions` | id_hash、user_id、expires_at、revoked_at | 只存会话哈希 |
| `progress` | user_id、day_id、payload、revision、updated_at、deleted_at | `(user_id,day_id)` 唯一 |
| `exercise_attempts` | user_id、attempt_id、payload、revision、created_at、deleted_at | 尝试追加，ID 防重 |
| `review_items` | user_id、item_id、payload、revision、updated_at、deleted_at | 保存调度，不复制题目正文 |
| `stuck_items` | user_id、stuck_id、payload、revision、updated_at、deleted_at | 默认私密 |
| `evidence` | user_id、evidence_id、evidence_hash、payload、created_at | 内容不可变，hash 防重 |
| `portfolio_items` | user_id、slot_id、payload、revision、updated_at、deleted_at | 私有档案材料 |
| `sync_changes` | user_id、cursor、entity_type、entity_id、revision、change_type、changed_at | 增量游标和删除标记 |
| `account_jobs` | id、user_id、type、status、requested_at、completed_at | 导出/删除任务 |

payload 是已经客户端 Schema 校验且服务端再次校验的 JSON；业务字段仍需提取用于约束和索引，不能只靠 JSON 绕过权限。删除采用带 revision 的 tombstone，防止旧设备把已删记录复活。

## 8. API 契约

| 方法与路径 | 语义 | 并发/错误 |
|---|---|---|
| `POST /v1/auth/github/start` | 创建 OAuth state/PKCE | 限流，不返回 secret |
| `GET /v1/auth/github/callback` | 建立会话 | 校验 state/nonce |
| `POST /v1/auth/logout` | 撤销当前会话 | CSRF |
| `GET /v1/changes?since=cursor&limit=100` | 按已授权实体增量读取，含 tombstone | 游标签名、行级权限、稳定分页 |
| `GET /v1/progress?since=cursor&limit=100` | 进度资源增量读取，含 tombstone | 游标签名、防越权 |
| `PUT /v1/progress/{day_id}` | 写入整日记录 | `If-Match: revision`，409 返回双方 |
| `POST /v1/progress/merge` | 批量整记录合并 | 同事务、逐项结果 |
| `PUT /v1/review-items/{item_id}` | 写复习项 | If-Match，算法版本校验 |
| `POST /v1/exercise-attempts` | 追加尝试 | 同 ID 幂等，不同 hash 409 |
| `PUT /v1/stuck-items/{id}` | 写私密卡点 | If-Match |
| `POST /v1/evidence` | 保存证据元数据 | 不可变，不能声明已验证 |
| `GET /v1/portfolio` / `PUT /v1/portfolio/{slot}` | 读取/写档案 | If-Match，不公开 |
| `GET /v1/export` | 创建/获取完整导出 | 仅本人，含 Schema 版本 |
| `DELETE /v1/account/data` | 删除账号数据 | 近期重认证＋明确确认 |

`GET /v1/attestations/*` 仍由 WP-11 Verification API 提供，不在 Learning API 增加伪造证明的写入口。

## 9. 同步协议与冲突

### 9.1 Outbox 状态机

```text
本地事务提交 → queued → sending → acknowledged
                    │        ├→ retry_scheduled（可重试网络/5xx）
                    │        └→ conflict（409，等待选择）
                    └→ paused（离线/用户关闭同步）
```

operation 包含 `operation_id/entity_type/entity_id/base_revision/payload_hash/created_at/attempt_count/last_error`。先在本地保存业务数据，再在**同一 IndexedDB 事务**写 outbox；只有服务端确认后才标 synced。指数退避加 jitter，超过次数进入人工重试，不无限刷新页面。

下行同步通过 `GET /v1/changes` 拉取已授权实体和 tombstone，服务端游标只有完整应用一个本地事务后才写入 `sync_state.last_server_cursor`。远端记录与本地待发送 outbox 冲突时保留双方并标记 conflict，不能用下行覆盖静默丢弃本地修改；无冲突时按 ID＋revision 整记录应用。游标必须防篡改且分页顺序稳定，重放同一游标应幂等。

### 9.2 冲突规则

- 各实体按 ID＋revision 做整记录乐观锁，不做字段级时间戳拼接。
- `If-Match` 失败返回 409 和本机/服务端双方 payload、revision；用户选择保留本机、使用云端或稍后处理。
- 选择本机后以服务端 revision 为新 base 重放完整本机记录，生成新 revision，不绕过锁。
- `planned=true` 的显式设置可在服务端事务中将旧计划日设 false；浏览旧课只更新访问时间，不能触发该操作。
- 删除以 revision＋tombstone 同步；旧 revision 写入返回 409，不复活。
- evidence 不可变，attestation 只能由验证服务关联；同步不能提升证据级别。

## 10. 隐私、导出、删除与降级

同步按实体类型分别授权：进度、复习/尝试、卡点、证据、档案可独立开关；默认不搜索词、完整日志或个人代码。卡点/档案 note 在上传前显示字段预览。

导出包含用户请求的全部实体和版本，不提供伪造的“已验证”数据。删除要求近期重认证，立即撤销会话，后台删除进度、证据元数据、档案和对象引用；备份保留期限、公开 attestation 是否撤销及不可删除审计字段必须在隐私说明中如实列出。初始备份清除目标可设 30 天，但这是工程策略，不是法律结论。

API 离线时阅读和本地保存完全可用；界面区分“已保存到本机”“等待同步”“已同步”“冲突”。关闭同步只停止上传，不自动删除本地或云端，两个删除动作分开。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| P1-TC-PORTFOLIO-01 | 槽位聚合 | 五份文档、性能、复现、表达映射正确，缺失显示待补充 |
