# 10：P1 项目档案与可选离线开发

> 工作包：WP-12（项目档案）、WP-13（可选离线编辑与冲突恢复）  
> 文件名保留“可选同步”仅为兼容已有链接，实际不再是独立账号同步服务。  
> 对应需求：FR-013、FR-014  
> 原则：项目档案默认服务端私密；主站已有在线跨设备，离线 outbox 只在真实需求下启用。

## 1. 项目档案范围

`/portfolio/` 将第 18 周后的 `minic` 成果、五份项目文档、性能、干净复现和表达材料组织为个人证据视图。公开页面只展示槽位说明和用户主动发布的 ProjectRelease；个人材料默认保存在 MySQL 和私有对象存储，不进入公开静态产物。

```text
config/learning/portfolio-slots.json    # Git 中的公共槽位定义
apps/portfolio/                         # MySQL 模型、权限、聚合和发布
static/js/learning/portfolio.js         # 编辑、预览和冲突交互
schemas/portfolio-v1.json
schemas/portfolio-export-v1.json
```

WP-12 通过独立 Django migration 新增项目表，不重写 WP-08 的复习和 WP-10 的证据。L2 展示可以依赖 WP-11，但 L1/L1+ 档案可以独立使用。

## 3. MySQL 模型与 API

### 3.1 模型

- `Project`：owner、slug、title、默认 private、current_revision、时间戳。
- `ProjectVersion`：project、version、manifest_json、metrics_json、source_commit、created_at。
- `ProjectSlot`：version、slot_id、artifact_kind、value_json、note、evidence_id NULL。
- `ProjectRelease`：project、version、visibility、公开摘要、published_at、unpublished_at。
- 私有附件用独立对象键和资产元数据，下载走本人授权或发布快照的公开资源。

ProjectVersion 发布后不可原地修改；修改创建新 version。EvidenceRecord 通过 ID 和 evidence_hash 关联，不复制其有效级别到可编辑文本。

### 3.2 API

- `GET/POST /api/v1/me/projects/`
- `GET/PATCH /api/v1/me/projects/{id}/`，使用 If-Match。
- `POST /api/v1/me/projects/{id}/versions/`
- `PUT /api/v1/me/project-versions/{id}/slots/{slot_id}/`
- `POST /api/v1/me/projects/{id}/releases/`
- `DELETE /api/v1/me/project-releases/{id}/`
- `GET /portfolio/{public_slug}/`：只读已发布快照。

所有 `/me/` 接口行级鉴权。公开 slug 不存在、未发布和私有项目统一返回 404，避免泄露。公开前预览逐字段列出将公开内容，不包含私密笔记、完整日志、签名 URL 和其他槽位默认值。

## 4. 聚合与有效复现

材料状态：`missing/draft/attached/needs_review/ready_for_review`。最高有效证据级别从匹配 source_day、learner_commit 和 evidence_hash 的 Attestation 派生。

“已复现”至少需要明确的源码 commit、环境、运行结果和对应证据；仅所有槽位有链接只能称“材料齐全”。不同硬件性能不直接排名；缺 baseline、sample_count 或单位时显示不完整。

编辑 evidence 关联时重新验证所有权。删除证据后项目保留历史引用状态为 unavailable，并重算当前最高有效级别；不把已删除证据继续宣传为有效。

## 5. 导出与公开

私有导出包含项目、版本、槽位、证据引用和公开状态；JSON/Markdown 生成器统一转义。用户可选择生成脱敏公开草稿，但草稿不等于发布。

发布事务冻结 ProjectVersion 和公开字段，创建 ProjectRelease。撤销发布只关闭公开路由，不删除私有档案。账号删除时先撤销公开 release，再按策略清理对象和记录。

验收：默认私有、越权拒绝、字段预览、Markdown 安全、删除重派生和发布快照均可测试。未启用 WP-13 时项目仍完整在线跨设备可用。

## 6. WP-13 启动条件与边界

只有证明用户经常断网且在线表单草稿不足时才启动 WP-13。它不提供第二套 OAuth 用户系统，也不重复 P0 的在线同步；复用主站 Session/CSRF 和服务端 API。

范围可限定为 DayProgress、StuckItem 和 Project 草稿。证据 attestation、有效级别、账号删除、公开 release、教师反馈和 Lab 操作禁止离线执行。

功能关闭时不创建 IndexedDB outbox，不影响在线功能。离线只是一组待提交操作，页面始终显示“仅保存在此浏览器，尚未同步”。

## 7. Outbox 数据结构

```text
数据库：learning-offline-v1（按站点、用户隔离）

outbox:
  operation_id UUID, user_id, entity_type, entity_id,
  base_revision, full_record, created_at,
  state queued|sending|retry|conflict|acknowledged

tombstones:
  user_id, entity_type, entity_id, base_revision, created_at

sync_state:
  user_id, stream, server_cursor, last_ack_at
```

敏感笔记是否允许落盘由独立隐私评审决定；默认只离线支持进度，不复制证据附件、项目私密长文和账号信息。浏览器存储加密若不能安全管理密钥，不宣称能抵御本机攻击。

本地同一操作的状态转换与 outbox 入队保持一致；应用崩溃后可恢复 queued，不能丢失“尚未提交”的标识。

## 8. 重连协议

1. 重新验证会话和账号；账号不匹配立即隔离，不提交。
2. 拉取下行 `GET /api/v1/me/changes/?cursor=...`，游标绑定用户和实体范围。
3. 按 created_at/operation_id 串行提交 outbox。
4. 新建使用 If-None-Match；已有记录使用 `If-Match: "<base_revision>"` 和完整记录。
5. 成功返回新 revision 和 operation_id，标记 acknowledged；确认后才删除 outbox。
6. 412 保存服务端当前记录和本机完整草稿，状态 conflict；不字段级自动拼接。
7. 409 planned 等业务冲突由用户明确选择当前计划。
8. 删除有 tombstone；旧上行操作不能复活已删除实体。

批量请求每项独立结果，但同一实体的更新必须有序。operation_id 在服务端设唯一幂等记录和合理保留期。

## 9. 冲突与计划唯一性

冲突界面显示本机版本、服务端版本、base revision、双方更新时间和实体范围。选择“采用服务端”丢弃草稿前需确认；选择“保留本机”以新 revision 重发完整记录；取消则保留冲突。

planned 始终由 LearningPlan 单记录维护。离线“设为当前日”作为单独计划操作发送，不允许多个 DayProgress planned=true。冲突时不能自动以最新 last_visited_at 决定主计划。

删除账号、远程会话撤销或安全下线时停止 outbox 发送并清除该用户私有缓存。普通删除实体需同步 tombstone 后才视为完成。

## 10. 隐私、导出和降级

在线导出由服务端完成；离线未同步草稿如果用户要求导出，应明确标记 pending，不混入已确认服务端记录。导入数据不自动重放 outbox 操作，避免旧操作重复执行。

API 不可用时在线模式保留当前表单并明示未保存；WP-13 开启时才允许显式“离线保存到此浏览器”。服务恢复不自动公开项目、提交教师材料或创建远程实验。

功能回滚不能删除高版本 outbox。旧前端无法识别时保持只读并提示导出/升级，不调用 `deleteDatabase()`。

## 11. 验收

项目：`P1-TC-PORTFOLIO-01` 聚合状态，`P1-TC-PORTFOLIO-02` 有效证据与复现口径，`P1-TC-PORTFOLIO-03` 私有导出/公开预览与转义。

离线沿用既有编号：

- `P1-TC-SYNC-01`：复用主站身份、撤销、账号隔离和 CSRF。
- `P1-TC-SYNC-02`：双设备/双标签整记录 412 冲突和显式选择。
- `P1-TC-SYNC-03`：outbox 崩溃恢复、operation_id 幂等和游标。
- `P1-TC-SYNC-04`：planned 唯一、删除 tombstone 防复活。
- `P1-TC-SYNC-05`：pending 导出、退出清理和账号生命周期。
- `P1-TC-SYNC-06`：断网、重连、服务故障、灰度与旧版本只读。
- `P1-TC-MIGRATE-02`：MySQL 项目迁移＋可选 outbox v1 升级，不混为同一版本。

WP-13 未开启时上述离线用例标为“不适用”，不能伪装通过，也不阻塞 WP-12 项目档案上线。
