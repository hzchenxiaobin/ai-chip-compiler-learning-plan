# 01：内容导入与发布契约

> 工作包：WP-01、WP-02、WP-05  
> 主要模块：`apps/content/`、`apps/search/`、`config/learning/day-overrides.json`  
> 核心原则：Markdown/Git 是唯一权威源；MySQL 只保存可重建读模型，发布失败不切换线上版本。

## 1. 内容导入流水线

```text
读取指定 Git commit 的 tutorials/week-*/day-*/
  → 校验标题、周号、日号和本地图片
  → 解析元数据 + day-overrides
  → 计算 content_sha
  → 创建 ContentRelease(validating)
  → 写入 Day / DayVersion / ContentChunk / SearchPosting
  → 渲染并消毒正文 HTML
  → 生成源码 ZIP 并上传公开对象存储
  → 全量 Schema、链接、资源和样例搜索校验
  → Release(ready)
  → 单独 publish 命令事务切换 active_release
```

导入和激活是两个命令，避免校验尚未完成就线上部分可见：

```bash
python manage.py import_tutorial --commit 53b62f1c84223bb6ca466bb8177921ccd5d8ef72
python manage.py publish_tutorial --release-id <id> --expected-checksum <sha256>
```

任一必填校验失败即非零退出，release 标为 failed。CI 只有在内容、应用、E2E 和迁移预检全部通过后才允许 publish。

## 2. 日课元数据解析

### 2.1 来源优先级

| 字段 | 默认来源 | 覆盖 | 校验 |
|---|---|---|---|
| `day_id/day/week/phase` | 目录和标题 | 否 | 日号、周号、阶段一致 |
| `title` | README 一级标题 | 否 | 与现有解析一致 |
| `objective` | “今日目标”引用块 | 紧急修复优先改 README | 非空纯文本 |
| `time` | “预计时间” | 可修正解析例外 | 两个正整数 |
| `prerequisites/deliverable` | 前置准备/今日产出 | 可，但建议同步正文 | 非空、不注入 HTML |
| `type` | Day 6/7 与阶段规则 | 是 | 七种枚举 |
| `key_output` | 类型默认 | 是 | 布尔值 |
| `skills` | 人工配置 | 是 | 1—12 个去重短标签 |
| `source_path/code_path` | 日课目录 | 否 | POSIX 相对路径 |
| `run_all` | 普通文件 `code/run_all.sh` | 否 | 非符号链接 |
| `content_sha` | 导入器计算 | 否 | 64 位小写十六进制 |

建议函数：

```python
def extract_labeled_quote(markdown: str, label: str) -> str: ...
def parse_estimated_minutes(text: str) -> dict[str, int]: ...
def infer_day_type(day: int, phase: int, title: str) -> str: ...
def build_day_record(tutorial, overrides, content_sha) -> dict: ...
def import_release(commit: str, actor_id: int | None) -> ContentRelease: ...
```

引用块逐行扫描，收集同一连续块，去除粗体和列表标记但保留命令、下划线和反引号文本。重复或缺失标签报告 source_path 和行号。无法解析两个正整数时读取覆盖，仍失败则导入失败。

### 2.2 类型推断

```python
if day == 168:
    type = "final_assessment"
elif day % 7 == 0:
    type = "review"
elif day % 7 == 6:
    type = "integration"
elif phase == 6:
    type = "documentation"
else:
    type = "concept_lab"
```

`environment_lab/presentation` 由人工覆盖。Day 029 标为 environment_lab；Day 161—168 无代码围栏不判无效。

### 2.3 覆盖配置

```json
{
  "schema_version": 1,
  "days": {
    "day-029": {
      "type": "environment_lab",
      "skills": ["MLIR", "LLVM 18", "FileCheck", "JIT"]
    },
    "day-165": {
      "type": "presentation",
      "skills": ["项目表达", "性能归因", "技术演示"]
    }
  }
}
```

只接受 `schema_version/days` 顶层字段和 `type/key_output/skills/time/prerequisites/deliverable/source_include` 日级字段。未知字段、重复 JSON 键、未使用覆盖、目录通配符均失败。

## 3. MySQL 内容模型

### 3.1 表和约束

| 模型/表 | 关键字段 | 约束 |
|---|---|---|
| `ContentRelease` | id、commit、config_sha、status、checksum、error_report、timestamps | `(commit,config_sha)` 唯一 |
| `ContentDay` | day_id、day、week、phase、current_version | day_id/day 唯一 |
| `DayVersion` | release、day、metadata_json、rendered_html、content_sha | `(release,day)` 唯一 |
| `ContentChunk` | version、chunk_id、heading、anchor、text、code_paths | `(version,chunk_id)` 唯一 |
| `ContentAsset` | version、kind、storage_key、sha256、size、visibility | 存储键唯一 |
| `SiteState` | active_release、updated_at、updated_by | 单行 |

状态：`validating→ready→active→retired`，失败为 `failed`。不允许 validating/failed 直接激活。激活事务需读取并锁定 SiteState、复核 ready/checksum、更新 active_release、写审计；事务提交后失效公开缓存。

### 3.2 日课 API 读模型

`GET /api/v1/days/` 从 active release 输出：

```json
{
  "schema_version": 1,
  "content_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "release_id": "01J...ULID",
  "days": [{
    "day_id": "day-029",
    "day": 29,
    "week": 5,
    "phase": 2,
    "type": "environment_lab",
    "key_output": false,
    "title": "搭好 MLIR 工作台——让 mlir-opt、FileCheck 和 JIT 都听你指挥",
    "objective": "从 README 的今日目标解析",

    "prerequisites": "从 README 的前置准备解析",
    "deliverable": "从 README 的今日产出解析",
    "url": "/tutorials/week-005/day-029/",
    "source_path": "tutorials/week-005/day-029/README.md",
    "source_asset_id": "公开源码资源ID或null",
    "code_url": "https://github.com/hzchenxiaobin/ai-chip-compiler-learning-plan/tree/53b62f1c84223bb6ca466bb8177921ccd5d8ef72/tutorials/week-005/day-029/code",
    "outputs_url": "https://github.com/hzchenxiaobin/ai-chip-compiler-learning-plan/tree/53b62f1c84223bb6ca466bb8177921ccd5d8ef72/tutorials/week-005/day-029/code/outputs",
```

不再生成 `public/learning/days.json`，不包含 base_path。URL 由 Django 路由生成；站外链接固定到 content_commit。无 code/outputs/source 时字段为 null，页面隐藏按钮。

## 4. 内容哈希

输入包含当日 README 原始字节、images 所有普通文件、code 下源码/脚本/IR/outputs，以及该日有效覆盖的规范 JSON。不包含构建时间、域名、ZIP 本身、其他日课或全局 CSS/JS。

```text
遍历当日普通文件，拒绝符号链接
路径转为相对当日目录的 POSIX 形式并按 UTF-8 字节排序
逐项写入 path + NUL + 文件大小 + NUL + 单文件 SHA-256 + LF
追加规范化覆盖 JSON
对字节流计算 SHA-256
```

文件遍历与读取之间变化则失败。日志只输出路径、数量和哈希，不输出疑似秘密。

## 5. 源码包与对象存储

### 5.1 ZIP 内容

每个有源码日生成以 `code/` 为根的 ZIP，包含 `run_all.sh`、CMake、源码、测试和 IR。默认排除 outputs、build、.cache、.git、临时文件、core dump、二进制和对象文件。运行必需的小型冻结输入只能在 `source_include` 逐项列入。

```bash
unzip day-029-source.zip -d day-029-source
cd day-029-source
bash run_all.sh
```

没有 run_all 时展示 README 实际步骤，不伪造一键运行。

### 5.2 安全和可重复性

- 只加入普通文件，拒绝绝对路径、`..`、反斜杠逃逸、符号/硬链接和设备文件。
- 条目排序、固定 1980-01-01 时间戳、统一压缩级别，保留 POSIX 执行权限。
- 初始预算：单文件 20 MiB、单日未压缩 100 MiB、2,000 项；超限失败评审。
- 扫描疑似密钥；构建后重读 ZIP 校验 CRC、权限和条目数。
- 对象键为 `public/releases/<commit>/day-NNN-source.zip`，数据库保存 SHA、大小和 mime。
- 私有证据与导出不得使用该公开前缀或 bucket。

## 6. 服务端搜索读模型

### 6.1 Chunk

```json
{
  "chunk_id": "day-029:0002",
  "day_id": "day-029",
  "content_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "heading": "环境检查",
  "anchor": "环境检查",
  "text": "去除脚本、样式和代码围栏标记后的可搜索正文",
  "code_paths": ["code/run_all.sh", "code/CMakeLists.txt"],
  "error_tokens": []
}
```

按二/三级标题切分，超过 4,000 字符按段落继续，目标 500—2,000 字符。保留命令、错误码、IR 操作和文件名。168 天、六阶段并集、chunk_id 和锚点必须完整。

### 6.2 Token 与 MySQL 查询

`SearchToken(token_norm,token_display)` 唯一；`SearchPosting(token,chunk,field,weight,positions_json)` 建 `(token,field)`、`(chunk)` 索引。CJK 连续文本生成二元词，英文/数字/下划线/点/斜杠/连字符组成的完整技术 token 同时规范化小写。

MySQL ngram 可用于中文正文召回，技术精确词使用 posting。查询先按 release 和筛选限制，再聚合评分、同日最多 3 chunk、稳定分页。首页不下载索引；浏览器只调用 `/api/v1/search/`。

## 7. 动态页面与模板输入

内容模块只提供 DayVersion、资源与搜索读模型，页面由 Django view 渲染：

```python
def home(request): ...
def tutorial_day(request, week: int, day: int): ...
def week_detail(request, week: int): ...
def phase_detail(request, phase: int): ...
def search(request): ...
```

模板通过 `{% url %}` 生成链接，通过 `{% static %}` 引用静态资源。日课正文只能使用导入阶段 sanitizer 后的 HTML；个人进度通过独立 context/API 注入，不能进入公开缓存。

## 8. 发布校验与错误报告

`ReleaseValidator` 至少执行：

1. 168 天、元数据 Schema、日号/周号/阶段和任务映射。
2. 图片、内部路由、章节锚点和安全 HTML。
3. ZIP 安全、CRC、权限、对象存储 SHA 和存在性。
4. chunk 覆盖、token 样例和 release 一致性。
5. 渲染代表页面并通过 Nginx 深链检查。
6. 对比当前 active release，输出新增/修改/删除日课与资产摘要。

错误格式 `[LEARNING_E###] 文件:行号 — 问题；修复建议`。错误报告避免完整正文、环境变量或秘密。

## 9. 回滚与完成定义

内容回滚选择历史 ready/retired 且校验仍有效的 release，重新执行冒烟后激活；若其对象资源已清理则先重建。回滚不修改 DayProgress，旧内容 SHA 仍能追溯。

- 168 天内容可重复导入，所有校验通过后才 ready。
- active_release 切换原子，失败版本线上不可见。
- 源码 ZIP 可重复、权限正确、无私密文件。
- 搜索 chunk/token 完整，中文与技术样例可命中。
- 动态模板和 Nginx 深链正确，无 GitHub Pages/base path 依赖。
