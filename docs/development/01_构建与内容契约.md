# 01：构建与内容契约

> 工作包：WP-01、WP-02、WP-05  
> 主要文件：`tools/build.py`、`tools/learning_*.py`、`config/learning/day-overrides.json`  
> 核心原则：现有 Markdown 是唯一权威源；构建器只派生产物，不回写教程。

## 1. 构建流水线

在现有 `load_tutorials()` 和日课页面生成逻辑之后增加学习产物编排，不另起一个平行站点构建器。

```text
读取 tutorials/week-*/day-*/
  → 沿用现有标题、周号、图片校验
  → 解析有效元数据 + 读取 day-overrides
  → 计算 content_sha
  → 校验 168 天唯一性和跨字段一致性
  → 生成 days.json
  → 生成源码 ZIP 与冻结输出清单
  → 生成轻量搜索索引 + 六阶段正文分片
  → 生成周/阶段/搜索/设置页
  → 复制静态学习模块
  → 校验全部产物与内部链接
  → 一次性输出 public/
```

任一必填校验失败即返回非零退出码。CI 只能在完整构建和测试成功后上传 `public/`。

### 1.1 `build.py` 接入要求

保留 `build_home()`、`build_plan()`、`build_tutorials()` 等现有职责，新增一个聚合函数即可：

```python
def build_learning(tutorials, repo_root, output_dir, content_commit, base_path=""):
    days = build_day_collection(tutorials, repo_root, content_commit)
    validate_day_collection(days)
    write_days_json(days, output_dir)
    build_source_archives(tutorials, output_dir)
    build_search_indexes(tutorials, days, output_dir)
    build_learning_pages(tutorials, days, output_dir, base_path)
    copy_learning_assets(repo_root, output_dir)
    validate_learning_output(output_dir, days, base_path)
```

实际参数可以适配现有 `Tutorial` 数据结构，但构建顺序和失败语义不得改变。`base_path` 写入 `days.json` 顶层并影响 HTML 注入和测试链接，但不拼入日课的永久 `url` 字段；`generated_at` 只用于构建诊断，不参与 `content_sha`。

## 2. 日课元数据解析

### 2.1 来源优先级

| 字段 | 默认来源 | 是否允许覆盖 | 校验 |
|---|---|---|---|
| `day_id/day/week/phase` | 目录和标题 | 否 | 日号、周号、阶段派生一致 |
| `title` | README 一级标题 | 否 | 与现有构建标题一致 |
| `objective` | “今日目标”引用块 | 仅紧急修复，优先改 README | 非空，去除 Markdown 标记后非空 |
| `time` | “预计时间” | 可通过覆盖配置修正解析例外 | 两个整数均大于 0 |
| `prerequisites` | “前置准备” | 是，但建议同步修订正文 | 纯文本，不注入 HTML |
| `deliverable` | “今日产出” | 是，但建议同步修订正文 | 非空 |
| `type` | Day 6/7 和阶段规则 | 是 | 七种枚举之一 |
| `key_output` | integration/review/final_assessment 默认 true，其余默认 false | 是 | 布尔值，用于周/阶段关键产出完成口径 |
| `skills` | 无可靠通用来源 | 是，主要人工维护 | 1—12 个短标签，去重 |
| `source_path/code_path` | 日课目录 | 否 | POSIX 相对路径，禁止逃逸 |
| `run_all` | `code/run_all.sh` 是否存在 | 否 | 普通文件且非符号链接 |
| `content_sha` | 构建计算 | 否 | 64 位小写十六进制 |

不允许在覆盖文件中修改日号、周号、阶段、路径和哈希，防止内容结构被配置静默改变。

### 2.2 引用块解析器

建议函数：

```python
def extract_labeled_quote(markdown: str, label: str) -> str: ...
def parse_estimated_minutes(text: str) -> dict[str, int]: ...
def infer_day_type(day: int, phase: int, title: str) -> str: ...
def build_day_record(tutorial, repo_root, overrides, content_sha) -> dict: ...
```

`extract_labeled_quote()` 使用逐行扫描，不依赖某一 Markdown 渲染库：

1. 找到以 `>` 开头且去掉引用标记后以 `**标签**` 开头的行。
2. 收集同一连续引用块中的后续行，保留换行。
3. 遇到下一个已知标签或引用块结束时停止。
4. 去掉粗体标记、列表前缀和多余空白，但保留命令、下划线、反引号内文本。
5. 同一标签出现多次或目标标签缺失时失败，错误中包含 `source_path` 和行号。

预计时间支持当前“学习 X 分钟；练习 Y 分钟”格式。可兼容中文冒号、全角分号和额外空格，但不要用一个过宽正则吞掉整个段落。无法得到两个正整数时，读取 `day-overrides.json` 的时间覆盖；仍失败则终止构建。

### 2.3 类型推断顺序

```python
if day == 168:
    type = "final_assessment"
elif day % 7 == 0:
    type = "review"
elif day % 7 == 6:
    type = "integration"
elif phase == 6:
    type = "documentation"  # 表达/展示日由覆盖配置改为 presentation
else:
    type = "concept_lab"
```

`environment_lab` 和 `presentation` 依靠人工覆盖。Day 029 至少应标记为 `environment_lab`；最终展示类日课根据真实 README 评审后标记为 `presentation`。Day 161—168 没有代码围栏不代表数据无效，不得按“是否有代码”推断类型。

### 2.4 覆盖配置格式

```json
{
  "schema_version": 1,
  "days": {
    "day-029": {
      "type": "environment_lab",
      "skills": ["MLIR", "LLVM 18", "FileCheck", "JIT"]
    },
    "day-165": {
      "type": "presentation",
      "skills": ["项目表达", "性能归因", "技术演示"]
    }
  }
}
```

校验规则：顶层只能有 `schema_version/days`；日课键必须真实存在；技能名去除首尾空白后长度为 1—40；单日技能不超过 12 个；未知字段、重复 JSON 键和未使用覆盖均失败。JSON 解析器应启用重复键检测，避免后一个同名键静默覆盖前一个。允许的日级字段为 `type/key_output/skills/time/prerequisites/deliverable/source_include`；`source_include` 只能是当日 `code/outputs/` 下的显式相对文件路径，不得写目录通配符。

## 3. `days.json` 契约

产物路径：`public/learning/days.json`。

```json
{
  "schema_version": 1,
  "content_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "generated_at": "2026-11-24T00:00:00Z",
  "base_path": "/ai-chip-compiler-learning-plan",
  "days": [
    {
      "day_id": "day-029",
      "day": 29,
      "week": 5,
      "phase": 2,
      "type": "environment_lab",
      "key_output": false,
      "title": "搭好 MLIR 工作台——让 mlir-opt、FileCheck 和 JIT 都听你指挥",
      "objective": "从 README 的今日目标解析",
      "time": {"learning_min": 25, "practice_min": 45},
      "prerequisites": "从 README 的前置准备解析",
      "deliverable": "从 README 的今日产出解析",
      "source_path": "tutorials/week-005/day-029/README.md",
      "code_path": "tutorials/week-005/day-029/code",
      "url": "tutorials/week-005/day-029/",
      "source_zip": "downloads/day-029-source.zip",
      "code_url": "https://github.com/hzchenxiaobin/ai-chip-compiler-learning-plan/tree/53b62f1c84223bb6ca466bb8177921ccd5d8ef72/tutorials/week-005/day-029/code",
      "outputs_url": "https://github.com/hzchenxiaobin/ai-chip-compiler-learning-plan/tree/53b62f1c84223bb6ca466bb8177921ccd5d8ef72/tutorials/week-005/day-029/code/outputs",
      "run_all": true,
      "skills": ["MLIR", "LLVM 18", "FileCheck", "JIT"],
      "required_tasks": ["reading", "exercise", "experiment", "acceptance"],
      "content_sha": "由构建器计算"
    }
  ]
}
```

`code_url/outputs_url` 是站外浏览链接，必须由当前 `content_commit` 生成，不使用会随时间移动的 `main` 链接，也不由 base path 拼接。若某天没有 `code/` 或 `outputs/`，对应字段为 `null`，页面隐藏该入口而不是制造 404。`source_zip` 在没有可发布源码时也为 `null`。

构建校验：

- 顶层日课数严格为 168，日号连续且 `day_id` 唯一。
- 数组按 `day` 升序；`week == ((day - 1) // 7) + 1`；`phase == ((day - 1) // 28) + 1`。
- `content_commit` 为 40 位提交哈希；本地无 Git 元数据时可用显式构建参数，禁止编造全零提交。`generated_at` 仅用于诊断，`base_path` 为空字符串或以单斜杠开头且不以斜杠结尾。
- `required_tasks` 与日课类型推导结果完全一致，前端不依赖另一套手工任务清单。
- 所有站内路径不含 `..`、反斜杠、绝对路径和 URL 编码后的逃逸形式。
- `days.json` 使用 UTF-8、非 ASCII 原样输出、稳定缩进和末尾换行。

## 4. 内容哈希

### 4.1 输入范围

`content_sha` 表示“学习者需要复核的日课版本”。输入包含：

1. 当日 `README.md` 原始字节。
2. 当日 `images/` 下所有被引用和未被引用的普通文件。
3. 当日 `code/` 下源码、脚本、配置、IR、冻结 `outputs/`。
4. 该日有效覆盖配置的规范 JSON，包括类型、技能和时间等。

不包含构建时间、站点 base path、输出 ZIP 文件本身、其他日课内容和全局 CSS/JS。前端功能升级不应把 168 天全部标成待复核。

### 4.2 确定性算法

```text
遍历 tutorials/week-NNN/day-NNN/ 下所有普通文件
排除符号链接；路径统一为相对当日目录的 POSIX 形式
按 UTF-8 路径字节排序
对每项依次写入：path + NUL + 十进制文件大小 + NUL + 单文件 SHA-256 + LF
最后写入规范化的有效覆盖 JSON
对以上字节流再计算 SHA-256
```

单文件哈希避免把大文件全部同时读入内存。文件在遍历和读取之间变化时构建失败并提示重试。哈希输入列表可在 `--debug-learning` 下输出路径和单文件哈希，但不得输出疑似密钥内容。

## 5. 源码包与冻结输出

### 5.1 ZIP 内容

每个有可发布源码的日课生成 `public/downloads/day-NNN-source.zip`，ZIP 以当日 `code/` 为根：

```text
run_all.sh
CMakeLists.txt
src/
tests/
...源码、配置、测试与 IR...
```

默认排除 `outputs/`、`build/`、`.cache/`、`.git/`、编辑器临时文件、core dump、可执行二进制、对象文件和疑似密钥。冻结输出通过独立入口查看，避免学习者误以为必须修改冻结结果。若某个小型冻结输入确为运行必需，只能在该日覆盖配置的 `source_include` 中逐项列入，并校验大小与用途；不得整体打包 `outputs/`。页面运行说明统一使用：

```bash
unzip day-029-source.zip -d day-029-source
cd day-029-source
bash run_all.sh
```

没有 `run_all.sh` 时显示 README 中的实际步骤，不伪造“一键运行”。ZIP 内不复制 README，教程说明始终由日课页和仓库原文提供。

### 5.2 ZIP 安全和可重复构建

- 仅递归加入普通文件；拒绝绝对路径、`..`、反斜杠逃逸、符号链接、硬链接和设备文件。
- 条目按 POSIX 路径排序，固定 ZIP 时间戳为 `1980-01-01 00:00:00`，使用统一压缩级别。
- 外部属性保留源文件 POSIX 权限，至少保留所有者可执行位；同时显式创建目录项。
- 单文件、单日总大小和条目数设上限。初版建议：单文件 20 MiB、单日未压缩总计 100 MiB、2,000 项；超过时构建失败并评审，不静默跳过。
- 扫描 `.env`、私钥、访问令牌和云密钥等疑似秘密。教学占位符必须明显写成 `YOUR_TOKEN_HERE`，不设置隐蔽绕过列表。
- 构建后重新打开 ZIP，逐项验证规范化路径、CRC、权限和条目数。

### 5.3 冻结输出

`outputs_url` 指向 GitHub 对应目录，P0 不复制 1,568 个冻结产物到每个 HTML。若需要站内浏览，可在 P1 增加只读清单；不得把输出文件作为可执行脚本加载，也不得将其 HTML 内容注入页面。

## 6. 搜索索引

### 6.1 轻量索引

路径：`public/learning/search/lite-index.json`。

```json
{
  "schema_version": 1,
  "content_commit": "与 days.json 相同",
  "days": [
    {
      "day_id": "day-029",
      "day": 29,
      "week": 5,
      "phase": 2,
      "type": "environment_lab",
      "key_output": false,
      "title": "搭好 MLIR 工作台——让 mlir-opt、FileCheck 和 JIT 都听你指挥",
      "objective": "纯文本目标",
      "deliverable": "纯文本产出",
      "skills": ["MLIR", "LLVM 18", "FileCheck", "JIT"],
      "url": "tutorials/week-005/day-029/"
    }
  ]
}
```

轻量索引包含 168 天，但不包含正文。首页只需加载它或 `days.json` 之一，不得 preload 六个正文分片。

### 6.2 正文分片

路径：`public/learning/search/phase-1.json` 至 `phase-6.json`，每片 28 天。

```json
{
  "schema_version": 1,
  "content_commit": "与 days.json 相同",
  "phase": 2,
  "days": [
    {
      "day_id": "day-029",
      "code_paths": ["code/run_all.sh", "code/CMakeLists.txt"],
      "error_tokens": [],
      "chunks": [
        {
          "chunk_id": "day-029:0002",
          "heading": "环境检查",
          "anchor": "环境检查",
          "text": "去除脚本、样式、代码围栏标记后的可搜索正文"
        }
      ]
    }
  ]
}
```

切分以二级/三级标题为边界；超过 4,000 字符的章节按段落继续切分，单块目标 500—2,000 字符。保留代码命令、错误码、IR 操作、文件名的原始 token；可以为节省体积去掉重复空白，但不能只索引自然语言而删掉代码。

### 6.3 分词与索引文本

构建器输出已清洗的文本，浏览器在查询时使用同一套 tokenizer：

- 连续 CJK 字符生成二元词片段；单字查询保留单字。
- 英文、数字、下划线、点、斜杠、连字符组成的命令/路径/IR token 保留完整形式，并建立小写匹配形式。
- `mlir-opt`、`LLVM ERROR`、`C++`、`%.0` 等不能全部被拆成无意义单字符。
- Markdown 链接保留显示文字，不索引跟踪参数；图片保留有意义的 alt。
- 搜索词默认不写入日志、不上传、不加入分析系统。

### 6.4 索引校验

- 六阶段并集仍为 168 天，日课无重复、无缺失。
- 每片 `content_commit` 与 `days.json` 完全一致。
- `day_id/chunk_id` 唯一，`phase` 与分片文件一致；`code_paths` 来自真实文件，`error_tokens` 来自正文和代码中的明确错误样例，不从外部猜测。
- 所有 chunk 非空；目标章节标题和锚点可映射到生成的日课 HTML。
- 用固定样例验证“MLIR”“run_all.sh”“FileCheck”“内存规划”“Roofline”和中文二字词能命中预期日课。

## 7. 周、阶段和设置页构建

`learning_pages.py` 提供：

```python
def build_week_pages(days, output_dir, base_path): ...
def build_phase_pages(days, output_dir, base_path): ...
def build_search_page(output_dir, base_path): ...
def build_settings_page(output_dir, base_path): ...
```

周页静态输出 7 天的标题、类型、目标、预计时间和链接；阶段页静态输出 4 周导航、阶段说明和 28 天清单。进度百分比由前端根据本地记录补充，不在构建时写死。

搜索页和设置页必须有完整静态标题、说明和 `<noscript>` 提示。无 JavaScript 时仍提供总计划、日课和 GitHub 仓库链接。新周/阶段页加入 `sitemap.xml`，各页保留 canonical、Open Graph、面包屑和由今日目标生成的描述；长文图片使用 lazy-load，新增静态资源文件名或查询参数带内容哈希以便缓存。

## 8. 页面数据注入

日课页在 `<body>` 输出：

```html
<body
  data-page-type="tutorial"
  data-day-id="day-029"
  data-base-path="/ai-chip-compiler-learning-plan"
  data-content-sha="实际内容哈希"
  data-days-url="../../learning/days.json">
```

其他页面使用 `home/plan/week/phase/search/settings` 等 `data-page-type`；周页和阶段页另加 `data-week`、`data-phase`。`data-days-url` 根据现有 `root_prefix` 计算，禁止所有页面统一写成 `/learning/days.json`。

`app.js` 以 `type="module"` 加载并设置 `defer` 语义的模块加载方式；`vp-solution.js` 保留原有加载顺序。学习模块不得重写 Markdown 渲染、数学公式或代码高亮。

## 9. 构建校验与错误报告

`learning_validate.py` 至少执行：

1. JSON Schema 校验及额外业务规则校验。
2. 所有站内资源存在性、日课链接和锚点校验。
3. ZIP 安全、权限、CRC 和输出清单校验。
4. 索引覆盖、提交一致性、分片和样例查询校验。
5. HTML 中 `data-day-id/data-content-sha` 与 `days.json` 一致。
6. base path 为空和 `/ai-chip-compiler-learning-plan` 两种构建均通过链接检查。

错误格式：`[LEARNING_E###] 文件:行号 — 问题；修复建议`。一次构建可收集彼此独立的内容错误，但遇到目录结构不安全时立即停止。成功日志只报告数量、产物目录和提交，不打印完整正文或敏感文件内容。

## 10. 本模块完成定义

- 168 天 `days.json` 完整、稳定、通过 Schema 和业务校验。
- 类型、技能和时间例外可追溯至覆盖配置；修改覆盖会改变对应 `content_sha`。
- 源码 ZIP 可重复生成，保留 `run_all.sh` 权限，无冻结输出、路径逃逸和疑似密钥。
- 轻量索引不携带正文，六阶段分片完整且提交一致。
- 周/阶段/搜索/设置页和日课数据属性齐全，项目子路径资源可访问。
- 所有解析、哈希、ZIP 和索引测试通过后，才允许下游 WP-04/WP-05 联调。
