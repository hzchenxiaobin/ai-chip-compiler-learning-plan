# 06：工作包拆解与追踪

> 目的：把 WP-01—WP-07 分解为可领取、可评审、可验收的任务，并追踪 FR 与 28 个验收用例。  
> 规则：任务完成必须有代码、测试和产物证据；不能只以“页面已出现”作为完成标准。

## 1. 依赖与里程碑

```text
WP-01 内容清单
  ├── WP-02 资源发布 ─────────────┐
  ├── WP-03 页面骨架              │
  │     └── WP-04 本地进度 ───────┤
  └── WP-05 搜索                  │
                                  └── WP-07 体验与发布
WP-04 └── WP-06 数据管理 ─────────┘
```

WP-02 与 WP-03 可并行；WP-04 与 WP-05 可并行。WP-05 只需要 WP-01 的契约，不必等 WP-03 全部完成，可用静态搜索测试页先联调。WP-06 必须复用 WP-04 的 Store，不能另建数据读写路径。

| 里程碑 | 准入 | 准出 |
|---|---|---|
| M1 内容与资源契约 | WP-01 启动 | `days.json` 168 天完整，ZIP/索引契约冻结，TC-B01/B03/B05—B08 通过 |
| M2 静态学习闭环 | M1，WP-03 可用 | 源码下载、任务状态、继续学习、本地备份走通，TC-F01—F06/F09—F12 通过 |
| M3 首版发布 | WP-01—06 完成 | P0 的 26 个用例通过，子路径、无障碍、性能和回滚证据齐全 |
| M4 P1 试点 | M3 稳定 | 代表日课证据、复习、卡点、项目档案试点；TC-F13/F14 通过 |
| M5 同步决策 | 真实跨设备需求成立 | 独立评审 API、账号、隐私与冲突；不以技术完整性为理由提前建设 |

## 2. 开发环境与通用完成定义

### 2.1 环境

- Python 3.11：现有构建器、内容测试和产物校验。
- Node.js 20 LTS：只用于 Playwright 和无障碍测试，不进入生产运行时。
- Chromium：每次 PR 必测；Firefox/WebKit：发布前必测。
- 本地/WSL C++、LLVM/MLIR 环境：仅在执行代表日课源码复现时安装，不是浏览网站的依赖。
- `TUTORIAL_COMMIT`：构建使用当前 Git commit；`LEARNING_BASE_PATH`：本地为空，仓库 Pages 为 `/ai-chip-compiler-learning-plan`。

### 2.2 每个任务的 Definition of Done

1. 代码位于本文指定模块，未把职责塞进 `build.py` 或 `vp-solution.js`。
2. 新正常、边界、错误路径都有测试；错误消息可定位文件、日课或字段。
3. 不改变未声明的 JSON 字段、URL、状态语义和现有教程正文。
4. 构建、相关单元测试和相关 E2E 通过，生成产物不提交到 `main`。
5. PR 描述列出 FR、TC、手工检查、产物截图或日志，以及数据/安全影响。
6. 若触及契约，同步修改 `01/02`、Schema、fixtures 和本文追踪矩阵。
