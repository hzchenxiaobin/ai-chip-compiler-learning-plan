# 12：P2 AI 助教开发

> 工作包：WP-15（基于教程证据的苏格拉底式助教）  
> 对应范围：FR-015 的 AI 部分  
> 前置：P0 搜索内容契约；接入个人证据时需先完成 WP-10；独立成本、隐私和质量评审  
> 原则：先提问与提示，引用真实日课；无可靠来源就明确不知道，不代做最终项目。

## 1. 产品边界与提示阶梯

AI 助教用于概念澄清、排错结构化、复习提问和下一步实验建议。它不是自动判题器、性能实测工具、完整项目生成器或 L2/L3 验证方。

默认提示阶梯：

1. **澄清**：询问学习者观察到的现象、假设、输入 Shape、Tile、环境和最小复现。
2. **定位**：指向具体日课段落、IR 操作、测试或错误检查点。
3. **实验**：建议一次只改变一个变量，并说明应观察什么。
4. **部分提示**：在学习者已提供尝试后给出局部伪代码或检查清单，不直接生成完整最终验收答案。

学习者主动要求完整答案时可以解释概念，但对 Day 155—168 项目文档、干净复现和最终验收，不生成可直接提交的整套个人成果。教师 rubric 和私有测试不进入检索库。

## 2. 架构与模块

```text
Git 教程内容 → ingestion → 内容块 + day_id/content_commit/content_sha/anchor
                         → embedding/关键词索引（仅公开内容）
用户问题＋主动选择的卡点/证据摘要
  → AI Gateway（认证、限流、脱敏提示、预算）
  → 查询分类 → 混合检索 → 重排 → 提示策略 → 模型
  → 引用校验 → 输出安全渲染 → 反馈与质量抽样

server/ai-gateway/
static/js/learning/ai-tutor.js
config/learning/ai-policy.json
tests/ai/golden/
```

模型供应商密钥只在 AI Gateway。静态站不保存 key，不直接调用供应商管理 API；教师私有反馈、私有测试、未共享笔记和完整代码默认不进入索引或提示上下文。

## 3. 内容摄取与检索契约

复用 P0 的标题/chunk/anchor，但增加 AI 专用元数据：

```json
{
  "chunk_id": "day-029:0002",
  "day_id": "day-029",
  "content_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "content_sha": "日课内容哈希",
  "heading": "环境检查",
  "anchor": "环境检查",
  "text": "公开教程正文",
  "code_paths": ["code/run_all.sh"],
  "skills": ["MLIR", "JIT"]
}
```

每次 content_commit 构建新索引版本，索引不可变；查询固定到当前站点 commit，旧对话保留旧引用。混合检索使用关键词＋向量，初始 topK=8、重排后最多 4 个 chunk、最多来自 2 个日课；这些是配置预算，需按质量评测调整。

`retrieve()` 只读，支持 day/week/phase 限制。无达到最低相关度阈值的 chunk 时返回空，模型不得凭记忆补造教程引用。引用 URL 由服务端根据已验证 day_id/anchor 生成，模型不能直接创造链接。

## 4. 对话与响应 Schema

### 4.1 API

| 接口 | 用途 | 约束 |
|---|---|---|
| `POST /v1/tutor/sessions` | 创建会话，绑定 content_commit 和模式 | 登录或受控匿名预算，默认私密 |
| `POST /v1/tutor/sessions/{id}/messages` | 发送问题，SSE 流式返回 | 长度、速率、token 预算和 CSRF |
| `GET /v1/tutor/sessions/{id}` | 读取本人会话 | 行级权限，不返回系统提示 |
| `DELETE /v1/tutor/sessions/{id}` | 删除会话 | 本人，删除审计最小化 |
| `POST /v1/tutor/responses/{id}/feedback` | 错误引用/无帮助反馈 | 不默认公开问题内容 |

```json
{
  "schema_version": 1,
  "response_id": "01J...ULID",
  "mode": "hint",
  "message": "先比较融合前后各一个操作的输入与输出，暂时不要改 Tile。",
  "citations": [{
    "day_id": "day-097",
    "content_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
    "anchor": "先问怎么测",
    "url": "tutorials/week-014/day-097/#先问怎么测"
  }],
  "suggested_experiment": {
    "hypothesis": "数值差异来自某个优化步骤，而不是测量波动",
    "change_one_variable": "只回退一个 Pass",
    "observe": "逐条比较输出与测试退出码"
  },
  "uncertainty": null,
  "model_policy_version": "socratic-v1"
}
```

流式协议先发送 metadata，再发送 message delta，最后发送完整 citations 和 usage；最终响应必须经引用校验，不能只流式输出模型原始 JSON 让用户页面执行。

## 5. 提示与工具安全

系统策略、检索内容、用户内容和工具结果使用结构化字段隔离。教程、代码、错误日志中的“忽略之前指令”“调用工具”“输出系统提示”等文字均视为不可信数据，不作为指令执行。

默认不开放 shell、文件写入、Git 写操作、HTTP 任意抓取、学习进度修改和证据级别修改。只读工具白名单：

```text
get_day_chunk(day_id, content_commit, anchor)
search_public_tutorial(query, filters)
get_user_selected_evidence_summary(evidence_id, selection_token)
```

工具输入由服务端 Schema 校验，证据选择 token 限定单条、单次、短时有效，模型不能遍历其他证据。任何执行命令请求都返回本地操作建议和排错清单，不触发 WP-16；只有用户显式进入独立实验流程才可创建 L3 job。

## 6. 引用与性能结论约束

- 每个教程事实性回答至少附一个可解析引用；无引用时显示“我没有在当前教程中找到足够依据”。
- `citations` 必须来自本次检索返回的 chunk，模型自造 day_id/anchor 会被丢弃并标记质量失败。
- 引用链接由后端生成，前端只渲染允许站内路径；引用文本短摘需与源 chunk 一致。
- 性能回答必须先有硬件、输入、Tile、基线、预热、重复次数和统计口径；缺字段时先提问，不生成精确提升数字。
- 模型不能声称执行了测试、访问了 CI 或验证了 commit，除非本次工具结果明确提供且仍可追溯。
- 用户要求猜测 LLVM/MLIR 行为而当前教程无依据时，可给一般性背景但必须标注“非本教程内容/需本地验证”，不能伪造成日课结论。

## 7. 隐私、成本与降级

### 7.1 数据最小化

默认只发送当前问题和用户主动选择的文本片段；页面显示将发送的日课、卡点或证据摘要，支持取消。客户端先做 home 路径、URL userinfo、token 等提示性脱敏，服务端再检查，但不能承诺识别所有秘密。

会话默认私密，保留期限初始 30 天并可配置；删除入口与反馈分开。默认不使用用户对话训练模型，供应商的数据保留和训练条款上线前必须评审。质量抽样需要单独同意或仅使用人工构造 golden 数据。

### 7.2 预算

初始每会话最多 20 轮、单次用户输入 8,000 字符、检索上下文 4 chunk、输出 800 tokens；每用户每日 token/费用配额和全站熔断均由服务端配置。超出预算时提示缩小问题或明日重试，不自动切换更贵模型。

模型/检索失败时返回相关日课搜索链接或“查看 Day N”的静态建议，不能显示编造答案。AI 功能关闭不影响教程、搜索、复习和证据导入。

## 8. 前端交互与无障碍

日课页提供“询问本日助教”，复习页提供“给我一次回忆提示”，卡点页提供“整理下一步实验”。打开面板时显示当前日课和将共享内容；不默认上传完整卡点。

流式区域使用 `aria-live="polite"` 分批汇总，不逐 token 打断读屏；键盘可停止生成、复制带引用回答、打开来源和提交反馈。停止生成 abort 请求并停止计费侧继续上下文累积，已产生费用按真实 usage 记录。

## 9. 质量评测与验收

建立至少 30 道 golden 问题，六阶段各 5 道，覆盖概念、排错、性能口径、无答案拒答和提示注入。自动检查所有引用 URL 可解析、content_commit 一致、无伪造执行声明；人工评审提示是否苏格拉底式、是否超出教程、是否泄露系统策略。

上线门槛：引用链接可解析率 100%，伪造引用零容忍；无来源问题必须拒答或明确不确定性；性能数字无数据不得生成。正确性/有用性阈值由试点前评审记录，不用主观“看起来不错”替代。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| P2-TC-AI-01 | 有源回答 | 回答引用真实日课/段落/commit，链接可打开 |
| P2-TC-AI-02 | 无源与过时内容 | 无可靠 chunk 时拒答，不编造，旧对话引用旧版本 |
| P2-TC-AI-03 | 提示注入 | 教程/用户日志中的指令不能触发工具、泄密或改证据 |
| P2-TC-AI-04 | 性能证据 | 缺环境/基线先提问，不生成实测或排名结论 |
| P2-TC-AI-05 | 防代做 | 最终验收请求得到提示/检查清单，而非整套个人成果 |
| P2-TC-AI-06 | 隐私与预算 | 发送前预览、会话删除、限流/熔断、默认不训练策略生效 |
| P2-TC-AI-07 | 故障与无障碍 | 模型失败有静态回退，键盘/读屏可停止和访问引用 |

WP-15 准出必须附 golden 评测报告、成本上限演练和隐私数据流，不接受只演示一条成功回答。
