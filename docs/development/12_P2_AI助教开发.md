# 12：P2 AI 助教开发

> 工作包：WP-15（基于教程证据的苏格拉底式助教）  
> 对应范围：FR-015 的 AI 部分  
> 前置：P0 MySQL 内容读模型与搜索；接入个人证据需 WP-10；独立成本、隐私和质量评审  
> 原则：先提问与提示，引用真实日课；无可靠来源就明确不知道，不代做最终项目。

## 1. 产品边界与提示阶梯

AI 助教用于概念澄清、排错结构化、复习提问和下一步实验建议。它不是自动判题器、性能实测工具、完整项目生成器或 L2/L3 验证方。

提示阶梯：

1. 澄清现象、假设、输入 Shape、Tile、环境和最小复现。
2. 指向具体日课段落、IR 操作、测试或错误检查点。
3. 建议一次只改变一个变量，并说明观察指标。
4. 在学习者已提供尝试后给局部伪代码或检查清单。

对 Day 155—168 项目文档、干净复现和最终验收，不生成可直接提交的整套个人成果。教师 rubric、私有测试、未共享笔记和完整私有代码默认不进入检索或提示上下文。

## 2. 架构与模块

```text
MySQL active release 的 ContentChunk / DayVersion
  → 只读导出/事件 → AI 专用不可变索引（公开教程）
用户问题＋用户主动选择的卡点/证据摘要
  → Django 授权入口 → AI Gateway
  → 认证、限流、脱敏、预算、查询分类
  → 混合检索 → 重排 → 提示策略 → 模型
  → 引用校验 → 输出安全渲染 → 质量抽样

services/ai-gateway/
static/js/learning/ai-tutor.js
config/learning/ai-policy.json
tests/ai/golden/
```

模型供应商密钥只在 AI Gateway 的密钥系统。动态 Web 前端同样不得保存 key，不直接调用供应商管理 API。Django 只持有调用 Gateway 的最小服务凭据，Gateway 不获得 MySQL 全库权限。

主站故障不影响已有公开教程的静态缓存；Gateway 故障时学习、搜索和进度正常工作，AI 面板显示不可用而非编造回答。

## 3. 内容摄取与检索契约

从 ContentChunk 只读导出：

```json
{
  "chunk_id": "day-029:0002",
  "day_id": "day-029",
  "content_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "content_sha": "日课内容哈希",
  "heading": "环境检查",
  "anchor": "环境检查",
  "url": "/tutorials/week-005/day-029/#环境检查",
  "text": "公开正文",
  "skills": ["MLIR", "LLVM 18", "FileCheck", "JIT"]
}
```

索引键包含 release_id/chunk_id/content_sha，切换与主站 active release 对齐。AI 索引是可删除重建的副本，不在后台编辑正文。摄取时移除疑似秘密、个人数据和隐藏教师内容。

检索使用关键词＋embedding topK、阶段/日课过滤和重排。相关度低于阈值或引用不可解析时返回无源结果。检索 topK、重排模型、阈值和索引版本记录在安全运行元数据中。

## 4. 引用与回答契约

模型只能使用返回的 `ref_id` 引用。Gateway 在输出前检查 ref_id 属于本轮检索、chunk 存在、URL 与 active release 匹配，并验证引用片段确实支持声明。

无法校验的引用被删除或整个回答转为拒答，不能让模型自行构造 URL。UI 显示日号、章节和真实锚点，点击前不自动 fetch 外部链接。

性能问题缺少硬件、工具版本、baseline/candidate、单位和样本时先提问。AI 不声称“已运行”“性能提升 X%”或“通过验收”，除非结构化工具返回了可验证结果且仍标明证据等级。

无可靠来源的回答示例：“我在当前教程版本中没有找到足够依据。请提供实际报错、工具版本和最小复现，或查看相关日课后继续排查。”

## 5. 防注入与工具边界

教程 chunk、用户问题、笔记、证据和日志均是不可信数据，不是系统指令。提示层明确隔离数据与指令；对“忽略规则、输出密钥、执行命令、编造引用”等请求进行测试。

工具默认无；若确有需要，只开放只读白名单：

- `search_public_tutorial(query, filters)`。
- `get_public_chunk(ref_id)`。
- `get_own_evidence_summary(evidence_id, one_time_grant)`。

证据 grant 由主站对用户显式选择签发的短期单条 token，Gateway 不能遍历用户全部记录。禁止 shell、文件写、网络任意 fetch、GitHub 写、数据库管理和 attestation 修改。

工具输出再次按不可信文本处理；AI 不直接执行 `evidence.command`，不访问 ci_url。

## 6. AI Gateway 与接口

- `POST /api/v1/ai/sessions/`：创建本人会话。
- `POST /api/v1/ai/sessions/{id}/messages/`：SSE 流式回答，含 client_message_id 幂等。
- `POST /api/v1/ai/sessions/{id}/stop/`。
- `DELETE /api/v1/ai/sessions/{id}/`。
- `GET /api/v1/ai/limits/`：只显示用户必要配额。

Gateway 校验主站短期身份断言和 scope；浏览器不直接持有长期 Gateway token。SSE 断线不自动重复扣费，重连用 message ID 查询状态。

设置每日 token/成本、并发、超时、单会话上下文和全站预算。达到阈值停止新请求并提示，不通过降低引用校验维持回答率。模型超时、内容过滤和供应商错误分类记录。

## 7. 隐私与前端

发送前显示将共享的字段：问题、选中日课、可选卡点/证据摘要。默认不发送完整项目、私有笔记、环境秘密或完整日志。提供移除附件/上下文、删除会话和停止生成。

会话正文按保留策略短期保存或仅 transient；质量抽样需要单独授权和脱敏。默认不将私密输入用于训练，供应商的数据保留条款需评审。

前端用文本节点渲染模型输出，不直接 innerHTML。Markdown 若支持则再消毒，代码复制不执行。键盘、读屏、移动端和 reduced-motion 可用；停止生成始终可达。

## 8. 质量、成本和安全评测

六阶段至少 30 道 golden，覆盖概念、排错、性能信息不足、无源拒答、引用有效性、防代做、提示注入和隐私。指标包括引用解析率、引用支持率、无源拒答率、最终项目代做拦截、平均/尾延迟和单次成本。

发布前固定模型、系统提示、检索配置和索引版本，保存人工评审。模型或提示更新必须重跑 golden，不能只比较“回答更像真人”。

## 9. 验收

- `P2-TC-AI-01`：引用全部来自真实 chunk，Day 029 示例指向“环境检查”。
- `P2-TC-AI-02`：性能字段不足先问，不伪造运行和提升。
- `P2-TC-AI-03`：提示注入、工具白名单和单条证据授权。
- `P2-TC-AI-04`：无可靠来源拒答，不构造 URL。
- `P2-TC-AI-05`：最终项目防代做和学习者尝试优先。
- `P2-TC-AI-06`：发送预览、上下文移除、会话删除和供应商保留。
- `P2-TC-AI-07`：SSE 停止/断线、预算熔断、键盘读屏和主站降级。
- 密钥扫描、成本报告、golden 人工评审和小规模试点全部通过后才开放。
