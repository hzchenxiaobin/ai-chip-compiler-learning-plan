## 2. 任务状态机

子任务枚举保持：

```text
reading / exercise / experiment / acceptance
not_started / in_progress / done / blocked / not_applicable
```

日状态只派生、不单独持久化：

```python
def derive_day_state(tasks: dict[str, dict], required: set[str]) -> str:
    applicable = [tasks[k] for k in required if tasks[k]["status"] != "not_applicable"]
    if any(x["status"] == "blocked" for x in applicable):
        return "blocked"
    if applicable and all(x["status"] == "done" for x in applicable):
        return "completed"
    non_acceptance = [tasks[k] for k in required - {"acceptance"}
                      if tasks[k]["status"] != "not_applicable"]
    if non_acceptance and all(x["status"] == "done" for x in non_acceptance):
        return "ready_for_review"
    if any(x["status"] != "not_started" for x in applicable):
        return "in_progress"
    return "not_started"
```

全部 `not_applicable` 返回 not_started；验收不适用而其他适用项全完成时返回 completed。所有 transitions 在服务端再次校验，前端枚举不能替代权限与 Schema。

合法转换：`not_started↔in_progress`、二者与 `done/blocked` 的显式转换、`not_applicable` 的显式切换。撤销 done 后重派生；周完成、阶段证书不由“已读”自动得到。

## 3. 进度 API 契约

### 3.1 记录

`GET /api/v1/me/progress/{day_id}/` 返回：

```json
{
  "schema_version": 1,
  "day_id": "day-029",
  "content_sha": "最后复核的日课SHA",
  "planned": true,
  "tasks": {
    "reading": {"status": "done", "updated_at": "2026-11-24T09:00:00Z"},
    "exercise": {"status": "in_progress", "updated_at": "2026-11-24T09:10:00Z"},
    "experiment": {"status": "blocked", "updated_at": "2026-11-24T09:20:00Z"},
    "acceptance": {"status": "not_started", "updated_at": "2026-11-24T09:20:00Z"}
  },
  "last_visited_at": "2026-11-24T09:20:00Z",
  "needs_review": false,
  "revision": 3
}
```

`planned` 是当前用户 LearningPlan 的 API 映射，不允许批量把多条 DayProgress 写为 true。`content_sha` 是学习者确认该版本的标记，不随内容发布自动改写；发布只设置 needs_review。

响应带 `ETag: "3"`。完整更新：

```http
PATCH /api/v1/me/progress/day-029/
If-Match: "3"
Content-Type: application/json
X-CSRFToken: <由安全页面上下文获取>
```

### 3.2 创建、更新和冲突

- 已存在记录：必须 `If-Match: "<revision>"`；更新成功 revision＋1 并返回新 ETag。
- 首次创建：约定 `If-None-Match: *`；已有记录时返回 412，避免两个标签同时初始化覆盖。
- 缺失或格式错误的并发头返回 428/400，不以“无版本”默认覆盖。
- 412 响应包含当前完整记录、新 ETag 和 `REVISION_CONFLICT`。
- planned 不是当前日、任务不适用、content release 不存在等使用 409/422 和明确错误码。
- 多字段更新在同一 MySQL 事务完成；读取聚合响应使用一致快照。

最小客户端：

```javascript
export async function patchDayProgress(dayId, expectedRevision, patch) {
  const headers = { "Content-Type": "application/json" };
  if (expectedRevision === null) headers["If-None-Match"] = "*";
  else headers["If-Match"] = `"${expectedRevision}"`;
  return apiFetch(`/api/v1/me/progress/${dayId}/`, {
    method: "PATCH", headers, body: JSON.stringify(patch)
  });
}
```

前端以完整任务映射提交，避免局部请求语义不一致。成功后用服务端响应替换本地视图，不自行加 revision。

## 4. ProgressController

```javascript
class ProgressController {
  async load(dayId) {}
  async setTask(dayId, taskId, status) {}
  async setPlanned(dayId) {}
  async acknowledgeContent(dayId, contentSha) {}
  async resolveConflict(dayId, choice, localDraft) {}
}
```

推荐流程：

1. 加载时从 dashboard 或 day API 取得记录、ETag 和当前内容 SHA。
2. 勾选时保留 `before` 快照，更新按钮 pending 状态；可以乐观显示，但必须可见“保存中”。
3. 成功使用服务端 revision；网络失败回滚并提示“未保存”，保留可重试的本地表单草稿。
4. 401/会话过期跳转登录前保存非敏感表单草稿于内存；不得写入明文持久存储。
5. 412 打开冲突面板，展示“本机尝试”“服务端当前”逐任务状态与时间，不做字段级自动合并。
6. 用户选择采用服务端或基于新 ETag 重试完整本机版本；再次 412 可重试但不无限循环。
7. 当前计划修改走 `PUT /api/v1/me/plan/`，有自己的 plan revision；浏览旧课只更新 last_visited_at，不回退计划。

同一页面串行化写操作；不同日可并行，但显示各自状态。

## 5. 周、阶段与继续学习

`derived.js` 为无 I/O 纯函数：

- 周完成：Day 1—5 的 key_output 达到 completed/ready_for_review，Day 6 集成完成且 Day 7 复盘完成；配置缺关键产出时按服务端返回规则处理。
- 阶段完成：关键产出＋阶段集成＋复盘＋阶段综合验收满足规则。
- 进度条同时显示任务粒度与周门禁，不把 `reading=done` 当练习或实验完成。
- 待复核日单独计数，不自动清零历史。

继续学习使用 MySQL 当前计划：

1. 计划日适用且未完成：提示“继续 Day N”。
2. 计划日已完成：提示“复习 Day N”。
3. 无计划：选择第一个服务端状态为 not_started/in_progress 且 planned 为空的适用日，按钮写“从 Day N 开始”。
4. 有最近访问但未完成任务：可提供次级“返回最近学习”，不能悄悄改主计划。
5. 无记录匿名用户：Day 1 开始或登录后恢复，措辞明确区分。

## 6. 通用 API 客户端

`apiFetch` 负责 JSON、CSRF、超时、错误规范化和 AbortController，不自动重试非幂等写：

```javascript
export async function apiFetch(path, options = {}) {
  const response = await fetch(path, {
    credentials: "same-origin",
    ...options,
    headers: {
      Accept: "application/json",
      ...(options.method && options.method !== "GET" ? csrfHeaders() : {}),
      ...options.headers
    },
    signal: options.signal
  });
  // 按 content-type 解析，统一抛出携带 status/code/payload 的 ApiError
}
```

CSRF token 从 Django 的受信 cookie 或模板 meta 获取，不输出到日志。`GET` 超时可有限重试；PATCH/POST/DELETE 只有在服务端提供 idempotency key 且明确安全时才重试。

存储不可用、5xx 和超时显示“未保存/加载失败”；空结果与错误必须视觉区分。Abort 是用户导航，不显示服务故障。

## 7. 服务端搜索客户端

```javascript
export async function searchContent(query, filters, cursor, signal) {
  const params = new URLSearchParams({ q: query });
  if (filters.phase) params.set("phase", filters.phase);
  if (cursor) params.set("cursor", cursor);
  const response = await apiFetch(`/api/v1/search/?${params}`, { signal });
  return response;
}
```

输入 150ms 防抖、最少 1 个有效字符；新查询 abort 旧请求，以 request sequence 防止旧响应覆盖。结果来自 active release，点击真实日课 URL＋锚点。

加载、无结果、查询错误、筛选和“加载更多”分别呈现。游标由服务端签名或绑定查询哈希，不能伪造任意外部 URL。默认不上传原始搜索词做行为日志。

## 8. 导出与导入客户端

### 8.1 导出

`POST /api/v1/me/exports/` 创建 Celery 任务，轮询或刷新任务状态；完成时从私有对象存储获取短时签名 URL。文件类型为 `application/json`，文件名含日期和 schema_version，不暴露服务器本地路径。

### 8.2 导入

浏览器只读取用户选择的文件并上传；JSON 大小、深度、重复键、类型和业务冲突均由服务端权威校验。前端可先提示文件过大，但不能据此前置信任。

- 预检：新增、更新、同值、冲突、删除计划和数据范围。
- 合并：逐日展示差异后提交预检 ID＋resolution＋预检 checksum。
- 替换：二次确认完整范围并输入指定文字；服务端先创建替换前私有快照。
- 失败：不显示部分成功；任务级错误列出可读字段路径，不输出原始秘密。
- 重复点击 apply 使用幂等键；已成功任务重放返回原结果。

P0 导入不包含 L2/L3 attestation 的写入能力。证据导入在 WP-10 单独实现。

## 9. 匿名、缓存和隐私

- 匿名页面可公开缓存，但模板中的登录状态、CSRF 和个人数据必须分块或禁用共享缓存。
- 认证 dashboard、progress、export、import 响应设置 `Cache-Control: private, no-store`。
- 退出后清空内存中的用户数据和 abort 未完成私有请求，不依赖浏览器后退保护隐私。
- 多标签通过 `BroadcastChannel` 只发送“某日已变化”通知，收到后重新 GET；消息不含完整个人记录。
- 无跨源业务 API 时收紧 CORS；若未来独立域名客户端接入，另行设计 OAuth，不放宽 Session Cookie。
