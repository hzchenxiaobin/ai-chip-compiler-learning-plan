# 02：前端学习模块

> 工作包：WP-04、WP-05、WP-06  
> 主要文件：`static/js/learning/app.js`、`store.js`、`progress.js`、`search.js`  
> 运行环境：现代浏览器原生 ES Modules；P0 无前端框架、无生产构建步骤、无服务端。

## 1. 模块边界

```text
app.js（唯一组合入口）
  ├── 读取 body 数据属性、加载 days.json、连接现有页面 DOM
  ├── store.js（有副作用）
  │     ├── IndexedDB 打开、事务、迁移、读写
  │     ├── localStorage 轻量 UI 偏好
  │     └── 导入导出、Schema 校验、非破坏合并
  ├── progress.js（纯函数）
  │     ├── 日课类型 → 适用任务
  │     ├── 四项子状态 → 整体状态
  │     ├── 内容版本复核、计划当前日、周/阶段汇总
  │     └── 首页继续学习与页面视图模型
  └── search.js（有网络副作用，查询为纯函数）
        ├── lite/phase 索引按需加载、提交一致性检查
        ├── 查询解析、评分、去重、排序、取消过期请求
        └── 返回结果视图模型，不直接操作学习记录
```

`vp-solution.js` 继续负责 Markdown 渲染、公式、代码复制、页内目录、主题、SVG 缩放和返回顶部。学习模块只新增独立组件，不 monkey-patch 其全局函数，不重复实现主题存储。

## 2. `progress.js`：纯状态与派生规则

### 2.1 常量

```javascript
export const TASK_IDS = Object.freeze([
  "reading", "exercise", "experiment", "acceptance"
]);

export const TASK_STATUSES = new Set([
  "not_started", "in_progress", "done", "blocked", "not_applicable"
]);

export const DAY_STATES = Object.freeze({
  NOT_STARTED: "not_started",
  IN_PROGRESS: "in_progress",
  READY_FOR_REVIEW: "ready_for_review",
  COMPLETED: "completed",
  BLOCKED: "blocked"
});
```

`not_applicable` 由日课类型派生，不允许导入文件把某个本应适用的任务永久改成不适用。导入时该字段必须按当前日课类型重新规范化。

### 2.2 类型与适用任务

| 日课类型 | reading | exercise | experiment | acceptance |
|---|---|---|---|---|
| `concept_lab` | 适用 | 适用 | 适用 | 适用 |
| `environment_lab` | 适用 | 适用 | 适用 | 适用 |
| `integration` | 适用 | 适用 | 适用 | 适用 |
| `review` | 适用 | 适用 | 不适用 | 适用 |
| `documentation` | 适用 | 适用 | 不适用 | 适用 |
| `presentation` | 适用 | 适用 | 不适用 | 适用 |
| `final_assessment` | 适用 | 适用 | 适用 | 适用 |

实现 `getApplicableTasks(type)` 返回新数组，调用方不得修改共享常量。未知类型抛出 `CONTENT_TYPE_UNSUPPORTED`，构建阶段本应拦截，前端不得默认为“全部完成”。

### 2.3 整体状态机

`deriveDayState(dayType, tasks)` 只读取适用任务，按以下优先级计算：

1. 任一适用任务为 `blocked`：`blocked`。
2. 所有适用任务均为 `done`：`completed`。
3. `acceptance` 适用，除验收外其他适用任务均为 `done`，且验收为 `not_started` 或 `in_progress`：`ready_for_review`。
4. 任一适用任务为 `in_progress` 或 `done`：`in_progress`。
5. 其余情况：`not_started`。

因此“验收已 done、练习未 done”只能是 `in_progress`，不能是 `completed`。复盘日不要求新实验，但回忆/错题归到 exercise、复盘清单归到 acceptance，不能仅以“已读”完成复盘。整体状态永不写入 IndexedDB，避免四项子状态与总状态不一致。

提供 `assertValidTransition()` 仅校验输入枚举，不强迫学习者按固定顺序操作。用户可以标记后续任务、解除卡点或重新打开已完成任务；每次修改保留对应 `updated_at` 和 `revision`。

### 2.4 默认记录和版本复核

```javascript
export function createDayProgress(day, now) {
  return {
    schema_version: 1,
    day_id: day.day_id,
    content_sha: day.content_sha,
    planned: false,
    tasks: normalizeTasks(day.type, {}, now),
    latest_evidence_id: null,
    stuck_item_ids: [],
    last_visited_at: now,
    needs_review: false,
    revision: 0
  };
}
```

字段语义：

- `content_sha`：学习者**最后确认复核过**的内容版本，不一定是当前构建版本。
- 新建记录时直接确认当前版本，故等于当前 SHA。
- 已有记录遇到不同 SHA：设置 `needs_review=true`，保留旧 `content_sha`、所有任务和证据引用。
- 用户点击“已复核新版内容”：只更新 `content_sha` 为当前值、`needs_review=false`、`revision+1`，不自动把任务改为完成。
- `planned` 表示主学习计划的当前日，与 `last_visited_at` 完全分离。浏览旧课只更新访问时间，不静默回退计划。

### 2.5 更新函数

```javascript
setTaskStatus(record, dayType, taskId, status, now) -> newRecord
setPlanned(record, planned, now) -> newRecord
acknowledgeContent(record, currentSha, now) -> newRecord
touchVisited(record, now) -> newRecord
summarizeDays(days, recordsById) -> Summary
getContinueTarget(days, recordsById) -> ContinueTarget
```

所有函数返回新对象，不原地修改调用方对象。`setTaskStatus()` 对不适用任务抛错；相同状态重复写入可直接返回原对象，避免无意义事务。`touchVisited()` 在同一会话同一日只写一次，由 `app.js` 控制。

`getContinueTarget()` 规则：

1. 有 `planned=true` 的日课：返回该日；多条计划记录属于数据异常，选择最近更新的一条并在设置页提示修复。
2. 若用户正在周复盘，优先返回该周 Day 7，不被普通旧课浏览打断。
3. 无计划日：按四项任务最近 `updated_at` 选择最近更新且未完成的日课，以 `last_visited_at` 作为次序平局条件。
4. 从未访问：返回 `day-001`。
5. 全部完成：返回 Day 168 或项目成果说明，不再显示“继续第 1 天”。

### 2.6 周/阶段汇总

`summarizeDays()` 同时输出辅助日课统计和关键产出主状态，二者不得混用：

- 辅助日课完成率分母为 168 个日课，不是四项任务总数；周页分母为 7，阶段页分母为 28。百分比向下取整，`ready_for_review` 不计完成。
- 周主状态输入为 `key_output=true` 日课、Day 6 集成和 Day 7 复盘。任一关键项 blocked 为 `blocked`；所有关键产出和 Day 6 完成、Day 7 未完成为 `ready_for_review`；关键项与 Day 7 均完成为 `completed`；其余按是否已有活动区分 `not_started/in_progress`。
- 普通日课未完成列为待补项，但是否阻断周 completed 由 `key_output` 决定；P0 不强制锁课。
- 阶段主状态由四个周主状态和该阶段 Day 28 综合复盘派生；日课百分比只作辅助，不能单独显示“阶段已掌握”。

页面同时给出“已完成 X 天、进行中 Y 天、卡点 Z 天”和“关键产出 A/B、集成状态、复盘状态”，避免单百分比掩盖真实闭环。

## 3. `store.js`：IndexedDB 与本地偏好

### 3.1 数据库定义

```text
database: ai-chip-compiler-learning
version: 1
object stores:
  progress:
    keyPath: day_id
    indexes:
      last_visited_at: last_visited_at，非唯一
  meta:
    keyPath: key
```

`progress` 保存 `DayProgress`；`meta` 只保存数据库内部信息，例如 `schema_initialized_at`，WP-06 还可保存替换导入前的可恢复备份。P0 不创建 `evidence/review/stuck/users` 空表。UI 偏好仍由现有主题机制保存；新增侧栏折叠等偏好使用 `localStorage` 键 `learning.ui.v1`，值只能是经过校验的少量布尔值/枚举。

### 3.2 公开接口

```javascript
openStore() -> Promise<Store>
store.isPersistent -> boolean
store.getDay(dayId) -> Promise<DayProgress|null>
store.getAllDays() -> Promise<DayProgress[]>
store.putDay(record) -> Promise<DayProgress>
store.updateDay(dayId, mutator) -> Promise<DayProgress>
store.clearProgress() -> Promise<void>
store.exportProgress(days) -> Promise<Blob>
store.importProgress(file, days) -> Promise<ImportReport>
store.close() -> void
```

UI 不直接访问原生 `IDBRequest`。所有 Promise 必须同时处理 `success/error/abort/blocked`；事务完成才表示保存成功，`put` 请求成功不等于事务已提交。

### 3.3 打开与升级

1. `indexedDB` 不存在或打开异常：返回 `isPersistent=false` 的内存 Store 并报告 `STORAGE_UNAVAILABLE`。app 显示“仅本次会话有效”，允许临时操作和导出，不声称已持久保存。
2. `onupgradeneeded` 只执行版本 1 的建表；升级事务失败不得继续使用半初始化数据库。
3. `onblocked` 提示用户关闭同站其他旧标签页；设置超时，不无限等待。
4. `onversionchange` 关闭当前连接并提示刷新。
5. 隐私模式或配额为 0 时按真实能力降级，不写入 localStorage 冒充完整进度。

未来迁移必须逐版本执行 `1→2→3`，先备份可导出数据；不能删除旧库重建。

### 3.4 事务和并发

`updateDay()` 使用 `readwrite` 事务读取最新记录、调用纯 `mutator`、写回并在 `oncomplete` 返回。`mutator` 必须是同步函数，不能在网络请求后继续使用已自动提交的事务。

同一页面用串行 Promise 队列保证点击顺序；跨标签页最后提交会覆盖同日的整个记录，因此需做乐观检查：

- mutator 返回时写入 `revision = old.revision + 1`。
- 监听 `BroadcastChannel("learning-progress-v1")`，收到外部更新后重新渲染。
- 不支持 `BroadcastChannel` 时使用 `window.storage` 仅发送轻量失效通知，不在 localStorage 保存进度正文。
- 若未来检测到高冲突，再引入字段级合并；P0 不假装已实现跨标签无冲突协作。

### 3.5 存储失败

写入 `abort`、QuotaExceeded 或连接突然关闭时：

- 保留服务器静态正文和当前页面已渲染内容。
- 不更新“已保存”标记；明确显示“本次更改未保存”。
- 可让用户重试一次或导出已有数据；不能反复自动写满配额。
- 若持久化从一开始就不可用，使用内存 Map 实现同一 Store 接口，所有进度区域持续显示临时状态并允许导出；刷新前提醒，搜索、源码下载和课程导航仍可用。localStorage 不保存这些进度正文。

## 4. 导出格式

文件：`learning-progress-v1.json` 对应的 `DayProgress` 记录集合。

```json
{
  "schema_version": 1,
  "kind": "ai-chip-compiler-learning-progress",
  "exported_at": "2026-11-24T09:30:00Z",
  "content_commit": "导出时 days.json 的提交",
  "days": [
    {
      "schema_version": 1,
      "day_id": "day-029",
      "content_sha": "最后复核版本",
      "planned": true,
      "tasks": {
        "reading": {"status": "done", "updated_at": "2026-11-24T09:00:00Z"},
        "exercise": {"status": "in_progress", "updated_at": "2026-11-24T09:10:00Z"},
        "experiment": {"status": "blocked", "updated_at": "2026-11-24T09:20:00Z"},
        "acceptance": {"status": "not_started", "updated_at": "2026-11-24T09:20:00Z"}
      },
      "latest_evidence_id": null,
      "stuck_item_ids": [],
      "last_visited_at": "2026-11-24T09:20:00Z",
      "needs_review": false,
      "revision": 1
    }
  ]
}
```

只导出实际存在记录的天，不强制补满 168 条。导出 Blob 类型为 `application/json`，默认文件名为 `ai-chip-compiler-learning-backup-YYYYMMDD.json`。对象 URL 在下载后撤销。

## 5. 导入校验

### 5.1 两阶段策略

**阶段 A：完整预检，不写入数据库。**

- 文件上限 5 MiB，按 UTF-8 严格解析 JSON；拒绝重复键、BOM 异常和无效时间。
- 校验 `kind`、主版本、记录数不超过 500、字段类型、枚举、时间戳、SHA、revision 范围。
- `revision` 为 0—2,147,483,647 的整数；字符串长度和数组长度按 Schema 限制。
- 未知字段不进入页面或数据库：预检报告“忽略 N 个扩展字段”，随后仅用白名单构造新记录。未来主版本仍直接拒绝，不能靠忽略字段猜测迁移。
- 同一天重复出现视为无效，不采用最后一条覆盖。
- 未知 `day_id` 不导致有效记录全部丢失，但也不写入：预检报告列出“将跳过 N 条其他课程版本记录”。若用户确认，导入仅处理当前 168 天交集。
- 按 `day_id/revision` 生成新增、更新、未变化、跳过和冲突预览。相同 revision 但规范化内容不同的记录必须等待用户选择。

**阶段 B：用户确认模式和冲突处理后，在一个事务中写入。**

默认“合并模式”不删除导入文件之外的现有记录。导入前显示文件版本、导出时间、可导入天数、跳过天数和冲突天数。malformed 文件整批拒绝；合法但含未知日课的文件允许确认后部分导入，并给出明确结果。

“替换模式”用导入集合替换当前进度集合，属于破坏性操作：必须单独确认，并在同一 IndexedDB 事务中先把当前完整进度写入 `meta.last_pre_replace_backup`，再执行替换。事务 abort 时备份和替换一起回滚；同时提供下载备份入口，替换后可恢复最近一次替换前状态。

### 5.2 安全处理

导入内容永远是不可信输入：不用 `innerHTML` 渲染，不执行字符串中的命令，不自动打开 URL，不把对象原型合并进全局配置。使用显式字段拷贝，忽略并报告 `__proto__/constructor/prototype` 等危险扩展键。JSON 即使通过 Schema，也只取白名单字段构造新记录。

## 6. 冲突合并与替换

`mergeDayProgress(existing, incoming, day)` 以整条 `DayProgress` 为单位，采用确定性规则：

| 比较结果 | 默认动作 | 用户可见结果 |
|---|---|---|
| 本机无此 `day_id` | 新增导入记录 | 新增＋1 |
| 导入 `revision` 更大 | 用导入整记录替换本机记录 | 更新＋1 |
| 导入 `revision` 更小 | 保留本机 | 跳过＋1 |
| revision 相同且规范化内容相同 | 不写数据库 | 未变化＋1 |
| revision 相同但内容不同 | **不静默覆盖，等待选择** | 冲突＋1 |

冲突记录提供“保留本机”“使用导入”“稍后手动处理”。“稍后手动处理”表示本次跳过，并允许下载包含双方记录的冲突 JSON；界面不得把它显示成已合并。选择“使用导入”后仍按当前日课类型规范化不适用任务，不能把导入的任意状态直接带入。

P0 不做字段级时间戳合并。只有revision较大的整记录才会覆盖较小版本，避免把四项任务拼成从未真实存在过的组合。内容 SHA 与当前构建不同时，导入完成后的统一复核扫描设置 `needs_review=true`，但不会清除任务或证据引用。

替换模式不复用上述逐条合并，而是“备份当前全量记录→清空 `progress`→写入导入集合”，三步必须在同一事务中完成。导入完成后报告新增、更新、未变化、跳过、冲突、失败数量；事务失败则全部回滚并报告失败，不出现半批替换。

## 7. 清空与重置

设置页提供两个不同操作：

- “清空学习记录”：只清空 `progress` object store，不修改主题和 UI 偏好；替换前备份是否保留必须在确认文案中单独说明。
- “清除全部本地偏好”：清除 `learning.ui.v1` 和现有主题等明确列出的 UI 偏好键，不碰学习记录。不得调用 `localStorage.clear()` 误删同源其他应用数据。

清空需要二次确认，确认文案明确“此操作不可撤销，建议先导出”。事务完成后再次读取计数为 0 才显示成功。P0 不提供按日删除，减少误操作和合并复杂度。

## 8. `search.js`：查询运行时

### 8.1 公开接口

```javascript
createSearchController({ daysUrl, basePath, fetchImpl }) -> Controller
controller.loadLite() -> Promise<LiteIndex>
controller.searchLite(query, {phase = null, week = null, type = null} = {}) -> Promise<SearchResponse>
controller.searchFull(query, {phase = null, week = null, type = null} = {}, signal) -> Promise<SearchResponse>
controller.cancel() -> void
```

每次调用返回 `{ query, scope, filters, results, truncated, loadedPhases }`。结果项包含 `dayId/title/url/heading/anchor/snippet/score/matchedFields`，snippet 必须由纯文本节点渲染。阶段和类型过滤在评分前执行；全文阶段筛选只加载目标分片，全部阶段才按需加载六片。

### 8.2 加载与版本检查

1. 先请求 `days.json` 或从 app 共享已验证数据。
2. 轻量索引和正文分片均检查 `schema_version` 与 `content_commit`。
3. 正文查询按需加载分片；若用户选择“全部阶段”，并发最多 2 个请求，避免六个大文件同时抢占带宽。
4. `AbortController` 取消旧查询；另加递增查询序号，防止忽略 abort 的实现返回旧结果。
5. 索引失败显示失败阶段和重试按钮。轻量结果存在时可保留，但必须标注“正文结果不完整”。
6. fetch 对 `days.json` 和轻量索引使用 `cache: "no-cache"`；正文分片 URL 可附 `?v=<content_commit>`，不使用 Service Worker。

### 8.3 查询和评分

查询按空白拆分，默认各词 AND；CJK 连续片段生成二元词，ASCII 保留完整 token 并小写匹配。基础权重：

| 匹配位置 | 权重 |
|---|---:|
| 标题完整 token | 12 |
| 技能 | 8 |
| 目标或今日产出 | 5 |
| 章节标题 | 4 |
| 代码路径 | 3 |
| 正文 | 1 |
| 命令、错误码、文件名精确匹配 | 额外 10，且精确匹配排在分词匹配前 |

同一天最多取分数最高的 3 个 chunk，日课总分为字段分加 chunk 分，避免长文因出现次数无限霸榜。排序依次按总分、较早日号、标题，保证结果确定。 snippet 截取命中词前后各约 60 个字符，不高亮未经转义的 HTML。

首屏最多 50 个日课结果，`truncated=true` 时提供“显示更多”，不一次创建数千 DOM 节点。空查询返回空结果和搜索提示，不返回全部正文。

## 9. `app.js`：启动流程

```text
读取并校验 body data-*
  → 初始化与页面无关的轻量导航
  → 加载 days.json（失败时静态页面仍可浏览）
  → tutorial/home/week/phase/settings 页面尝试 openStore()
  → 读取本页所需记录，不额外读取无关大数据
  → 计算纯视图模型并渲染
  → 绑定事件，使用事件委托和 AbortController 管理生命周期
  → search 页另初始化 search.js
```

页面模块可按 `data-page-type` 动态 `import()`，但 P0 不需要复杂路由。`app.js` 在所有页面加载时不能假设任务卡、搜索框或设置按钮一定存在。

渲染使用 `textContent`、`createElement` 和静态模板；教程 Markdown 不由学习模块再次渲染。所有异步事件在按钮处理期间设置 `aria-busy`，结束后恢复，并防止重复提交。

## 10. 单元测试要求

`progress.js` 至少覆盖：

- 七种日课类型的适用任务和全部状态分支。
- blocked 优先级、ready_for_review、验收先完成但练习未完成、复盘日完成。
- 内容 SHA 变化保留任务和证据引用；复核后仅更新版本字段。
- 浏览旧课不改变 planned；多条 planned 异常处理。
- 周/阶段/168 天汇总和继续学习选择。
