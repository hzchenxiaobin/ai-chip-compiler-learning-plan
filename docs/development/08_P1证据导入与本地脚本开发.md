## 2. 单条证据 Schema

```json
{
  "schema_version": 1,
  "evidence_id": "local-day029-20261124T092000Z",
  "level": "L1+",
  "day_id": "day-029",
  "tutorial_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "learner_commit": null,
  "executed_at": "2026-11-24T09:20:00Z",
  "environment": {
    "os": "Linux x86_64",
    "llvm": "18.x",
    "compiler": "clang 18.x",
    "mlir_opt": "18.x",
    "arch": "x86_64",
    "cpu": "可选且由用户明确提供",
    "memory_gb": 32,
    "runtime": "本地 WSL2"
  },
  "command": "bash run_all.sh",
  "exit_code": 0,
  "summary": {"passed": 1, "failed": 0, "skipped": 0},
  "tests": [{"name": "minimal-mlir-jit", "status": "passed"}],
  "performance": null,
  "ci_url": null,
  "notes": "可选、脱敏后的短说明"
}
```

必填环境键为 `os/llvm/compiler/mlir_opt`。`arch/cpu/memory_gb/runtime` 可选但类型固定。summary 计数必须与 tests 逐项状态一致；有失败测试时 exit_code 不应伪装成功。`tests` 为空时三项计数均为 0，并显示“未提供测试明细”。

performance 为 null 或对象：指标名、baseline、candidate、unit、sample_count 和测量口径完整，数值有限且为正；缺少基线不能计算提升百分比，不跨硬件排名。

URL 仅允许 https（localhost 开发可配置例外），不自动请求。command、报错和测试名按不可信纯文本处理。

## 3. 规范化与 evidence_hash

哈希输入固定为以下字段组成的对象：

```text
schema_version, level, day_id, tutorial_commit, learner_commit,
executed_at, environment, command, exit_code, summary, tests,
performance, ci_url, notes
```

`notes` 可省略；省略或显式 `null` 时统一规范化为 `null`，提供时必须是长度受限的纯文本。规范化对象始终包含 `notes` 键，避免不同实现因缺省值不同产生哈希分叉。

不包含 evidence_id、上传时间、用户 ID、本站 ID 或 attestation。步骤：

1. 严格 JSON 解析，拒绝重复键、NaN/Infinity、超深嵌套和未知字段。
2. 校验字符串不自行 trim 改动命令语义；路径统一 Schema 约定的文本形式。
3. 使用 RFC 8785 JCS 或经过等价性验证的规范化实现。
4. `evidence_hash = SHA256(JCS(canonical_input))`，输出 64 位小写十六进制。
5. Python 与 JavaScript 对同一 fixtures 得出相同哈希。

同用户同 evidence_hash 视为重复；同 evidence_id 不同 hash 返回冲突，不覆盖。不同用户相同证据可分别关联，但不互相暴露。

## 4. 上传、预检和写入

### 4.1 API

- `POST /api/v1/me/evidence/imports/`：创建私有预检任务。
- `GET /api/v1/me/evidence/imports/{id}/`：查看新增/重复/冲突/错误。
- `POST /api/v1/me/evidence/imports/{id}/apply/`：带预检 checksum 和 resolutions。
- `GET /api/v1/me/evidence/?day_id=&level=&cursor=`
- `GET/DELETE /api/v1/me/evidence/{id}/`

bundle 有数量、字节和展开大小限制；服务端设置 JSON 解析与任务超时。所有权在任务和每条证据两层校验。

### 4.2 事务

预检不修改业务表。apply 在事务内重新校验任务所有者、文件 SHA、过期时间和重复记录，批量写入并返回逐条结果。超过事务预算时使用 staging 表，全部校验后在短事务切换可见状态。

失败 abort 不产生部分可见证据。删除证据只删本人记录和私有暂存对象，不改 DayProgress 任务；最新证据由查询或事务内重算派生。

## 5. 级别与 attestation 边界

用户可以选择声明 L1 或 L1+；即便上传 `level:L2/L3`，也只能记录声明并显示“未核验”，有效级别保持本地证据等级。服务端忽略导入文件中的 signature、verified、effective_level 等未知/保留字段，或按 Schema 拒绝。

L2/L3 只能由 WP-11/WP-16 的内部验证接口以 evidence_hash 关联。Attestation 表只读展示给普通用户，不能通过通用导入、Django admin 默认表单或项目档案接口写入。

文案：

- L1：学习者自报。
- L1+：本地脚本生成，本站未复验。
- L2：指定 commit、受信工作流和公开测试复验。
- L3：平台强隔离执行与私有测试复验。

退出码 0、绿色 CI 链接或完整 JSON 都不能单独提升有效级别。

## 6. 本地执行器

CLI 示例：

```bash
python tools/learning_evidence.py run \
  --day day-029 --tutorial-commit 53b62f1c84223bb6ca466bb8177921ccd5d8ef72 \
  -- bash run_all.sh
```

实现要求：

```python
completed = subprocess.run(
    argv,
    shell=False,
    cwd=project_root,
    env=filtered_env,
    text=True,
    capture_output=True,
    timeout=timeout_seconds,
    check=False,
)
```

- 分隔符后的参数是用户明确选择的本地命令，不来自上传 JSON。
- 环境变量使用 allowlist，不继承云密钥、token 或无关配置。
- 输出限长并本地保存，网站默认只上传结构化摘要。
- 超时/非零退出如实记录；不因生成 evidence.json 而把结果写成 passed。
- 机器测试报告解析失败时标为 unknown/错误，不猜全通过。
- 脚本输出文件原子写入，避免中断留下半文件。

## 7. 证据界面

日课证据卡显示级别、执行时间、commit、环境、测试通过/失败/跳过、性能口径和关联验证状态。列表支持日课/级别筛选和稳定分页。

详情中的 command、测试名、URL 和性能文本全部转义。外部链接显示目标域并需主动点击；不提供“在网站运行此命令”。删除需确认且不影响任务状态。

导入结果展示新增、重复、冲突和失败；冲突由用户选择保留服务端或创建新 attempt，不能静默覆盖不可变证据。

## 8. 导出、删除与隐私

导出包含 EvidenceRecord 的结构化字段、evidence_hash、declared_level、effective_level 和有效 attestation 引用，不包含签名私钥、内部下载凭证、完整私有日志或其他用户信息。

私有暂存对象到期清理；删除证据和账号时处理对应对象。审计记录数量、哈希和结果，不记录命令中的敏感参数。
