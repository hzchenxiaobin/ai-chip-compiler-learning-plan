## 2. 单条证据 Schema

字段以设计文档为准，以下可选环境扩展不改变必填语义：

```json
{
  "schema_version": 1,
  "evidence_id": "local-day029-20261124T092000Z",
  "level": "L1+",
  "day_id": "day-029",
  "tutorial_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "learner_commit": null,
  "executed_at": "2026-11-24T09:20:00Z",
  "environment": {
    "os": "Linux x86_64",
    "llvm": "18.x",
    "compiler": "clang 18.x",
    "mlir_opt": "18.x",
    "arch": "x86_64",
    "cpu": "可选且由用户明确提供",
    "memory_gb": 32,
    "runtime": "本地 WSL2"
  },
  "command": "bash run_all.sh",
  "exit_code": 0,
  "summary": {"passed": 1, "failed": 0, "skipped": 0},
  "tests": [{"name": "minimal-mlir-jit", "status": "passed"}],
  "performance": null,
  "ci_url": null,
  "notes": "可选、脱敏后的短说明"
}
```

### 2.1 校验规则

- `evidence_id` 为 1—128 个安全 ASCII 字符；同 ID 不同哈希为冲突，不能覆盖。
- `day_id` 属于当前 168 天；`tutorial_commit` 为 40 位哈希；`learner_commit` 为 40 位哈希或 null。
- `environment.os/llvm/compiler/mlir_opt` 必填；arch/cpu/memory/runtime 可选。无代码文档日可放宽工具链字段，但必须有明确 `kind=document_declaration` 的后续 Schema，不在 v1 暗中缺字段。
- `command` 最多 2,000 字符，仅展示；`notes` 最多 10,000 字符；tests 名称最多 500 字符。
- `summary` 三项为非负整数，必须等于 tests 的对应状态数量；tests 最多 200 项。
- `exit_code=0`、failed=0 只表示声明的测试通过，不表示站点复验；skipped>0 时显示“含跳过项”。
- `ci_url` 为 null 或允许的 HTTPS GitHub Actions URL；不自动请求、不根据域名授予 L2。

## 3. 批量 envelope 与大小限制

本地脚本默认输出单条对象。批量导入使用：

```json
{
  "schema_version": 1,
  "kind": "ai-chip-compiler-evidence-bundle",
  "generated_at": "2026-11-24T09:30:00Z",
  "evidence": []
}
```

实际 Schema 中 `evidence` 是对象数组，空数组仅用于展示 envelope 结构；真实导入至少包含一条完整单条证据对象。单文件上限 1 MiB、单批最多 200 条、每条 tests 最多 200 项；完整控制台日志留在本机或 CI。重复 JSON 键、截断文件、非法 UTF-8、未来主版本、非正值性能数据均整批拒绝。

预检报告逐条列出：可导入、重复、ID 冲突、未知日课、声明级别、测试结果、性能完整/不完整。所有记录合法或用户明确选择跳过未知日课后，才允许进入一个写入事务。

## 4. 哈希、去重与内部记录

对剔除所有内部字段后的证据执行 RFC 8785 JCS 规范化，再计算 SHA-256：

```text
evidence_hash = SHA256(JCS({
  schema_version, evidence_id, level, day_id,
  tutorial_commit, learner_commit, executed_at,
  environment, command, exit_code, summary,
  tests, performance, ci_url, notes
}))
```

浮点数必须是有限 JSON 数字，拒绝 NaN/Infinity；键排序和数字序列化由同一共享实现完成，Python 与 JavaScript 用固定 fixture 交叉验证。内部记录增加：

```json
{
  "evidence_hash": "64位哈希",
  "declared_level": "L2",
  "effective_level": "L1+",
  "verification_status": "unverified",
  "attestation_id": null,
  "imported_at": "2026-11-24T09:35:00Z",
  "source": "json_import",
  "revision": 0
}
```

`declared_level` 保留原始声明；`effective_level` 决定页面可信级别。L1 自声明保持 L1；本地脚本生成的 L1+ 保持 L1+；导入的 L2/L3 声明没有匹配证明时显示“L2/L3 声明，本站未核验”，其有效级别最高只按 L1+ 处理，不能称“本地脚本生成”或“平台认证”。

## 5. 性能证据

```json
{
  "hardware": "CPU 型号与关键内存信息",
  "input": {"shape": [512, 512, 512], "dtype": "f32"},
  "config": {"tile": [32, 32, 32], "flags": ["--fuse"]},
  "baseline": "未融合、同编译器与同输入",
  "warmup_runs": 5,
  "measured_runs": 20,
  "statistic": "median",
  "baseline_ms": 12.5,
  "optimized_ms": 8.2,
  "environment_commit": "环境/脚本版本"
}
```

`baseline_ms/optimized_ms` 必须为有限正数；`warmup_runs` 为非负整数，`measured_runs` 为正整数；shape/tile 为正整数数组，dtype、flags 和 environment_commit 有长度限制。缺硬件、工具链、输入、配置、基线、次数或统计口径时可保存“不完整实验记录”，但不能进入比较视图。

`getComparisonKey()` 至少包含硬件、OS、LLVM、编译器、MLIR、input、config、baseline、warmup、measured_runs、statistic、environment_commit。只有 key 相同的记录才能并列计算变化；百分比仅在同条证据内由 `(baseline_ms-optimized_ms)/baseline_ms` 派生，显示原始毫秒值和样本口径。不提供跨硬件排名或全体平均加速比。

## 6. 本地脚本实现

### 6.1 CLI

```bash
python3 tools/learning_evidence.py \
  --day day-029 \
  --tutorial-commit "$(git rev-parse HEAD)" \
  --learner-commit "$(git -C /path/to/learner rev-parse HEAD)" \
  --output evidence.json \
  --timeout-seconds 300 \
  -- bash run_all.sh
```

参数解析以 `--` 分隔命令，`subprocess.run(argv, shell=False)`；不支持网站传入命令。脚本默认在当前工作目录运行，Git 仓库路径仅用于解析 commit，不写入证据。`--performance-json` 可显式提供性能文件，脚本只做 Schema 校验，不生成虚假基准。

### 6.2 环境与日志最小化

- 环境只收集 OS/arch 和用户要求的编译器、LLVM、MLIR 版本；不遍历环境变量。
- stdout/stderr 仅用于解析已有测试摘要；原始输出不写 evidence，捕获上限各 256 KiB。
- 默认脱敏 home 目录、用户名、URL userinfo 和常见 token 模式；脱敏不能替代用户公开前检查。
- 测试摘要优先读取受支持的机器报告；无法可靠解析时让调用方显式传入测试 JSON，不猜测“终端没报错=8 项通过”。
- 命令超时或非零退出仍生成失败证据，脚本自身返回非零；只有成功写出并通过自校验才提示可导入。

### 6.3 函数划分

```python
parse_args(argv) -> Args
collect_environment(allowlist) -> Environment
resolve_commit(repo, explicit) -> str | None
run_command(argv, cwd, timeout, output_limit) -> RunResult
load_test_summary(path) -> TestSummary
redact_metadata(value) -> value
build_evidence(...) -> Evidence
validate_and_write(evidence, output) -> EvidenceHash
```

## 7. 导入、列表与详情

导入流程与 P0 一致：完整预检→用户确认→单事务写入→结果报告。evidence_hash 相同且内容相同记为重复，不产生第二条；evidence_id 相同但 hash 不同必须等待用户处理，不能自动覆盖。

日课证据卡显示级别、执行时间、教程/学习者 commit、环境、退出码、测试汇总和性能完整性。详情页只以文本节点展示命令、报错和 notes；链接有安全 rel，且必须用户主动点击。

`DayProgress.latest_evidence_id` 仅在证据事务成功后更新为最新 executed_at 的证据 ID，不回写更高级别，不自动把 experiment/acceptance 标 done。删除证据不级联删除日课进度；若 latest 被删，重新派生剩余最新 ID 或 null。

## 8. 安全、迁移与性能

- 文件和文本按不可信输入处理，拒绝 HTML 注入、危险 URL、原型污染、超长数组和深层嵌套。
- 证据列表按 day_id/executed_at 索引分页，首屏 50 条；tests 默认折叠，不一次渲染 40,000 行。
- v2 迁移不修改 P0 记录；备份 v2 包含内部声明/验证状态，但不包含签名密钥或完整日志。
- 证明 attach 只能由 WP-11 的可信 attestation 流程完成，设置页没有“手动标记 L2”按钮。
