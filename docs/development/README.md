## 1. 文档包用途

本套文档把设计文档中的 `FR-001`—`FR-015` 和 28 个原始验收用例拆解为可实施的工程任务：P0 对应 `WP-01`—`WP-07`，P1/P2 继续拆为 `WP-08`—`WP-16` 及专项验收用例。它面向内容构建、前端、后端、CI、安全、测试和发布人员，要求开发完成后仍保持以下约束：

- Markdown 与 Git 是唯一内容权威源，不建立第二份课程正文数据库。
- 保留现有 Python 静态构建器、`vp-solution.js` 与 GitHub Pages，不更换站点框架。
- P0 无登录、无服务端数据库、无公开社区、无远程代码执行。
- 学习记录默认保存在浏览器 IndexedDB，存储失败时不得假装保存成功。
- 日课 URL 保持 `/tutorials/week-NNN/day-NNN/`，GitHub Pages 项目子路径必须可用。
- 首版只做学习闭环所需能力；证据复验、复习、项目档案和同步 API 分阶段实施。

## 3. 范围基线

### 3.1 P0 必须交付

1. 构建生成完整 `days.json`，168 天记录与目录一一对应，元数据可覆盖且构建可校验。
2. 每日源码 ZIP、GitHub 源码深链、冻结输出入口分别提供；ZIP 保留脚本权限并做路径与密钥检查。
3. 首页、日课页、周页、阶段页、搜索页、设置页接入统一学习数据。
4. 日课四项子任务状态、派生整体状态、计划当前日、继续学习和 `needs_review` 可用。
5. 本地轻量索引与六阶段正文分片搜索可用，失败时明确降级。
6. 本地进度导入、导出、清空可用，导入校验、冲突合并和结果报告明确。
7. 键盘、移动端、明暗主题、无 JavaScript、存储不可用和发布回滚通过验收。

### 3.2 P0 明确不交付

- 注册登录、服务端数据库、跨设备同步和公开排行榜。
- 浏览器远程编译、自动执行导入证据中的命令、教师后台。
- 结构化自测、复习队列、卡点管理、项目档案和可信 L2/L3 标识。
- 原生 App、支付、强制每日锁课、公开社区。
- 为“未来可能使用”而提前创建空后端、空数据表或无调用方的抽象层。

### 3.3 P1/P2 入口

P1 可从证据与本地复习开始，但不得把学习者上传的 JSON 直接视为已复验事实。L2 需要可信工作流和验证方；L3 需要平台控制的隔离执行。账号同步是独立可选项，不是证据、复习或本地进度的前置条件。

- **P1 核心：**WP-08 先统一题包、备份和 Store v2；WP-09/WP-10 可并行；随后分别验收 WP-11 L2 试点和 WP-12 项目档案。
- **可选同步：**WP-13 只在真实跨设备需求成立后启动，并单独升级 Store v4；未启用时不得影响 P0/P1 本地功能。
- **P2 独立项目：**WP-14 按 GitHub 讨论、hosted 社区、教师反馈和 cohort 四个开关分别验收；WP-15 先通过引用质量、隐私和成本评审；WP-16 先通过强隔离、私有测试、安全和成本评审。
- **发布边界：**P2 不捆绑上线，AI 助教与远程实验不进入默认 90 天承诺。详细任务、迁移顺序和准出证据统一见 `14_P1P2工作包与验收追踪.md`。

## 5. 全局接口与命名约定

### 5.1 标识和时间

- 日课 ID：`day-NNN`，三位零填充，范围 `day-001`—`day-168`。
- 周 ID：`week-NNN`，阶段 ID：`phase-N`，阶段范围 1—6。
- 页面日号、目录日号、README 标题日号必须一致；周号与 `ceil(day / 7)` 一致。
- 时间戳统一 RFC 3339 UTC，例如 `2026-11-24T09:20:00Z`；浏览器使用 `new Date().toISOString()`。
- `content_sha` 使用 64 位小写十六进制 SHA-256，不加算法前缀。

### 5.2 URL 与资源路径

`days.json` 内的 `url`、`code_url`、`outputs_url` 均保存**不带站点 base path 的根相对路径**，例如 `tutorials/week-005/day-029/`。前端通过同一个 `joinBasePath()` 生成最终链接；HTML 静态链接继续使用现有 `root_prefix` 相对路径。

本地构建默认 base path 为空；仓库 Pages 部署为 `/ai-chip-compiler-learning-plan`。禁止把 `localhost`、 GitHub 域名或生产域名硬编码进学习模块。

### 5.3 错误分类

| 错误码 | 含义 | 用户行为 |
|---|---|---|
| `STORAGE_UNAVAILABLE` | IndexedDB 被禁用、打开失败或浏览器异常 | 阅读与搜索继续；进度进入显式临时状态并提示及时导出 |
| `STORAGE_QUOTA` | 写入超过配额 | 保留原数据，提示导出后清理，不重试死循环 |
| `DATA_SCHEMA_INVALID` | 导入结构或字段不合法 | 整批拒绝，显示首个错误及路径 |
| `DATA_VERSION_UNSUPPORTED` | Schema 主版本不支持 | 整批拒绝，不猜测迁移 |
| `INDEX_UNAVAILABLE` | 索引下载、解析或版本校验失败 | 保留教程导航，允许重试，不显示伪造结果 |
| `CONTENT_VERSION_MISMATCH` | 索引与 `days.json` 提交不一致 | 停止正文搜索，提示刷新或重新构建 |

错误可以记录不含搜索词、笔记和个人代码的本地诊断信息；P0 不上传遥测。

## 6. 变更控制

### 6.1 可以直接修改的内容

- 文档中明确的函数内部实现、CSS 类命名、测试 fixture 文案。
- 不改变外部契约的性能优化、可访问性修复和测试补充。
- 针对真实 168 天内容补充 `day-overrides.json`，但需在 PR 中说明推断依据。

### 6.2 必须先评审的变更

- `days.json`、进度导入文件、IndexedDB object store、证据文件的字段或语义。
- 日课 URL、任务状态、整体状态派生规则、内容哈希输入范围。
- 引入账号、后端、远程执行、第三方分析脚本或新的生产依赖。
- 将 P1 功能提前塞入 P0，或为了演示放宽导入、ZIP、CI 安全限制。

### 6.3 提交建议

按可审查的小步提交：`content-contract`、`source-assets`、`page-skeleton`、`local-progress`、`local-search`、`data-transfer`、`accessibility-release`。每个提交必须能独立构建；不要把生成后的整个 `public/` 提交到 `main`。

## 7. 分阶段完成定义

### 7.1 P0 完成

只有同时满足以下条件，才能宣告 P0 完成：

- `01`—`06` 中的 P0 任务均关闭，跨文档接口无未决冲突。
- `FR-001`—`FR-009` 有实现和测试证据，P0 的 26 个设计验收用例全部执行；失败项有修复提交，不能仅标注“人工看过”。
- 从干净检出可重复构建，168 个日课、源码包、索引、周/阶段页齐全。
- 在根路径和 `/ai-chip-compiler-learning-plan/` 两种 base path 下均无资源 404。
- 存储、索引、导入失败均有可理解的降级；无 JavaScript 时正文与导航仍可读。
- 构建或测试失败不会上传新 artifact，更不会覆盖现有线上版本。

### 7.2 P1 核心完成

- WP-08—WP-12 按实际开放范围准出，`FR-010`—`FR-013` 有实现与专项测试映射；原 `TC-F13/F14` 与 `EVIDENCE-01/02` 同项关联验收。
- v1→v2→v3 迁移使用真实旧版 fixture，升级失败不丢数据；v1/v2 备份可恢复，替换前保留完整备份。
- 自测先答后看，复习遵循 `[1,7,28]` 及版本化策略，卡点和复习不自动伪造日课验收。
- L1/L1+ 的声明边界清晰；L2 必须有匹配证据、受信工作流、公开测试与有效签名 attestation，导入声明不能直接升级。
- 项目档案默认本机私有，五份文档、性能、干净复现和表达材料分别展示完整度与可信级别。
- P0 的 26 个用例不回归；证据或 L2 服务故障不影响教程、搜索、复习和本地保存。

### 7.3 可选同步与 P2 完成

- WP-13 仅在开启同步时验收：Store v4、双设备 `If-Match` 冲突、tombstone、导出删除和 API 降级全部通过；未开启不阻塞 P1 核心完成。
- WP-14 的四个 feature flag 分别准出，公开讨论、私密教师反馈和 cohort 字段级共享不得混用权限。
- WP-15 必须提交六阶段 golden 评测、真实引用、无源拒答、提示注入、防代做、隐私和成本熔断证据。
- WP-16 必须提交独立安全评审、强隔离、私有测试、资源限制、销毁、独立 L3 签名和邀请灰度证据；任一门槛缺失即保持关闭。
- P2 只能按实际完成的子能力宣告交付，不能以 GitHub 讨论模板、一条 AI 成功回答或普通容器运行成功代替整个工作包验收。

各阶段均须重跑受影响的原始用例和专项用例，并在 `14` 的里程碑报告中记录版本、功能开关、迁移、已知限制、灰度范围与回滚证据。
