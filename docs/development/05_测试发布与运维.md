# 05：测试、部署与运维

> 工作包：WP-07  
> 范围：真实 MySQL/Redis 测试、动态应用部署、数据库迁移、对象存储、备份恢复和回滚  
> 原则：内容发布、应用部署、数据库迁移分开控制；生产写入故障不能降级为浏览器“假成功”。

## 1. 测试矩阵

| 层 | 工具 | 重点 |
|---|---|---|
| 内容单元 | Python/pytest | 解析、哈希、ZIP、HTML 消毒、chunk/token |
| ORM/事务 | Django TestCase＋MySQL | 约束、revision、行级权限、发布切换、迁移 |
| API | Django 测试客户端 | 认证、CSRF、Schema、ETag、错误码、缓存 |
| 前端纯函数 | Node 测试 | 状态机、周/阶段、继续学习、冲突选择 |
| 浏览器 E2E | Playwright | 无 JS/JS、移动端、跨标签、导入导出 |
| 安全 | 依赖/密钥扫描、安全测试 | 越权、XSS、上传、会话、CSP、私桶 |
| 性能 | 查询计数、负载测试 | N+1、搜索、并发写入、静态资源、队列 |
| 运维 | 冒烟、备份恢复、故障演练 | 深链、PITR、Redis 丢失、回滚 |

SQLite 仅可做极少量纯 ORM 原型，不作为准出数据库。MySQL 唯一约束、排序规则、ngram、事务和 DDL 必须在 MySQL 8.4+ 验证。

## 2. 本地与 CI 环境

使用 Compose 或等价工具启动 `mysql`、`redis`、对象存储模拟服务和应用。凭据只用于本地一次性开发，不提交真实秘密。CI 使用服务容器和临时数据库：

```yaml
# 示例片段，不是完整工作流
services:
  mysql:
    image: mysql:8.4
    env:
      MYSQL_ROOT_PASSWORD: ci-only-password
      MYSQL_DATABASE: learning_test
    options: >-
      --health-cmd="mysqladmin ping -h localhost"
      --health-interval=5s --health-retries=20
  redis:
    image: redis:7
```

CI 任务顺序：

1. 内容解析与 ZIP 测试。
2. Python/JS 单元和静态检查。
3. MySQL migrations、API、事务与并发测试。
4. 168 天导入到临时 MySQL，执行全量校验但不激活生产。
5. 构建应用镜像，启动 Nginx/Django/Celery/依赖。
6. Playwright、深链、安全、性能和迁移回退测试。
7. 生成 SBOM/依赖报告与构建校验，扫描秘密。
8. 受保护环境手工批准后部署。

教程内容提交触发导入测试；应用代码提交触发完整测试。生产发布需明确 content release ID 和镜像 digest。

## 3. 基础验收用例

### 3.1 内容与构建：TC-B01—B08

- B01：指定 commit 全量导入并激活，168 天、版本、chunk 和资源完整。
- B02：测试副本缺少“前置准备”等必填元数据时失败，且不切换 active_release。
- B03：测试目录或标题中的日号/周号异常时失败并定位不一致。
- B04：通过 Nginx 检查图片、章节锚点、动态深链和 commit 固定 GitHub 链接。
- B05：绝对路径、逃逸、符号/硬链接等恶意 ZIP 输入被拒绝并报告。
- B06：代表源码包含源码/脚本和必要输入，不含默认排除项，权限/CRC 正确。
- B07：只修改一篇教程时对应 content_sha 变化，激活后学习历史保留并可回滚。
- B08：Day 161—168 等无代码日课可导入，无空源码按钮，有对应验收动作。

### 3.2 功能：TC-F01—F12、F15

- F01：匿名进入 Day 001 后注册，公开阅读不中断，登录后可保存。
- F02：修改任务、退出并换浏览器登录，当前计划和状态恢复。
- F03：浏览早期日课后回首页，最近访问变化但主计划不回退。
- F04：四任务独立持久化，整体状态派生；首次创建、If-Match 和 412 冲突正确。
- F05：blocked 后解除，历史和其他任务不变，冲突解决不静默覆盖。
- F06：激活新 SHA 后原记录保留并提示 needs_review，确认版本留 SHA。
- F07：常量折叠、mlir-opt、E104 和文件名搜索返回相关结果、上下文和真实锚点。
- F08：搜索 DB/服务异常时显示失败可重试，不伪装无结果。
- F09：正常导出、删除学习数据后合并导入，预览正确且确认后恢复。
- F10：截断、类型错误或恶意 JSON 整批拒绝，原数据不变。
- F11：同 day_id、同 revision、不同内容等待用户选择，不静默覆盖。
- F12：MySQL 不可用或写入回滚时明示未保存，缓存公开内容可读。
- F15：仅完成七篇阅读时不显示“本周已掌握”，周/阶段门禁正确。

TC-F13 是 P1 合法 L1+ 证据导入，TC-F14 是无 attestation 的 L2/L3 声明不得提升有效级别；二者不计入 P0 26 项，与上述合计 28 个基础用例。恶意 HTML、危险 URL 和超长数组同时由安全测试覆盖。

### 3.3 设备、无障碍与发布：TC-A01—A05

- A01：键盘操作导航、任务、弹层和导入，所有目标可达可退出且焦点恢复。
- A02：320 px、横屏和 200% 字体下无整页溢出、内容丢失或遮挡。
- A03：明暗主题的文本、代码和状态对比度达标，状态不只依赖颜色。
- A04：禁用 JS 或第三方静态依赖失败时，公开正文、搜索表单和下载可用。
- A05：迁移、测试或冒烟失败不切换流量，应用/内容兼容回滚成功。

另设不占用基础编号的横切测试：行级越权、CSRF、XSS、上传/压缩炸弹、密钥扫描、N+1、搜索分页、响应时延、并发写入和缓存隐私。具体性能目标由部署容量确定，验收前写入测试配置，不以开发机一次测量代替负载测试。

## 4. 生产拓扑

```text
Internet → HTTPS/Nginx
                ├── /static/、受控公开媒体 → 静态文件/对象存储
                └── 其他请求 → Gunicorn/Django
                                  ├── MySQL（权威数据）
                                  ├── Redis（缓存/限流/队列）
                                  ├── Celery workers
                                  └── S3 兼容公开/私有 bucket

独立后续服务：Verification、AI Gateway、Lab Controller/Executor/Signer
```

Nginx 只把合法动态路由代理到应用，不将 404 全部重写首页。限制请求体、超时和上传大小，设置 `X-Forwarded-*` 仅信任真实代理。Django 配置 `SECURE_PROXY_SSL_HEADER`、允许域名、安全 Cookie 和 CSRF trusted origins。

Gunicorn 使用非 root 用户、只读根文件系统（可行时）、受限资源和独立密钥挂载。Celery 与 Web 分队列/资源；导入、导出、证据处理不阻塞 Web worker。

## 5. 配置与秘密

生产通过环境或密钥管理注入：MySQL、Redis、对象存储、Django SECRET_KEY、邮箱/OAuth、签名公钥和后续服务凭据。禁止打包进镜像、JS、模板、GitHub Pages 或普通 CI 日志。

配置启动校验：DEBUG=false、数据库严格模式、时区 UTC、HTTPS、主机、bucket 公私分离、Celery 队列和备份参数。缺关键秘密启动失败，不生成弱默认值。

## 6. 数据库发布流程

1. 确认最近备份与恢复可用，记录当前镜像、Schema 和 active release。
2. 在预生产克隆数据上演练 expand、回填、校验和应用启动。
3. 部署兼容新旧 Schema 的迁移，监控锁、复制延迟和慢查询。
4. 启动新应用执行冒烟，逐步切换流量。
5. 观察后停止旧版本；contract 留到回滚窗口之后。
6. 失败时回滚到兼容当前 Schema 的旧镜像；必要时暂停写入，不直接恢复旧整库覆盖新学习记录。

内容 publish 是独立步骤：镜像与 Schema 健康后再激活 ready release。内容错误可切回旧 release，不必回滚应用或数据库。

## 7. 备份与恢复

MySQL 定期全量、binlog/PITR、加密和跨故障域保存；私有 bucket 使用版本/保留策略。每次备份记录时间、范围、校验和、密钥版本和保留期，不记录秘密。

每季度至少一次隔离恢复演练：

1. 恢复到指定时间点。
2. 校验账号、168 天 release 引用、进度、任务和审计数量/抽样。
3. 验证私有对象可下载且权限仍私有。
4. 清空 Redis 后重建缓存和可重放队列状态。
5. 测量 RTO/RPO 并更新 runbook。

未做恢复演练的备份不能算验收完成。

## 8. 可观测性与告警

结构化日志包含 request_id、release_id、actor 的安全伪匿名 ID、路由、状态、耗时和队列任务 ID；不记录密码、CSRF、Session、完整导入文件、原始笔记、证据附件或搜索原文。

指标：请求率/错误率/时延、MySQL 连接/锁/慢查询、Redis 命中/内存、Celery 深度/失败、导入发布失败、对象存储错误、备份年龄和磁盘容量。

告警至少覆盖：5xx 激增、MySQL 不可用、队列积压、发布失败、备份超期、私桶异常公开、证书到期和磁盘不足。Runbook 明确负责人、止血、沟通和恢复步骤。

## 9. 故障与回滚演练

- MySQL 只读/不可用：公开缓存可读，个人写入明确未保存。
- Redis 不可用：缓存可旁路，限流和敏感任务按策略 fail closed。
- Celery 停止：任务保持 queued，不显示已完成。
- 对象存储不可用：正文可读，ZIP/导出/证据下载显示失败。
- 新内容错误：切回旧 active release，进度不变。
- 新应用错误：回滚兼容镜像，保留当前 MySQL 数据。
- 私桶配置错误：立即撤销公开访问、轮换受影响签名、审计访问并通知。

## 10. 发布准出

- CI 全绿，P0 26 用例和 WP-07 专项测试有证据。
- 真实 MySQL/Redis 环境完成全新安装、升级和恢复演练。
- 生产 Nginx 深链、HTTPS、安全头、Cookie、CSRF 和缓存正确。
- 迁移与内容发布可独立回滚，不覆盖新学习数据。
- 备份、监控、告警、日志脱敏和故障 runbook 可用。
- GitHub 仅承担代码与 CI，不依赖 Pages 运行生产网站。
