# 05：测试、发布与运维

> 工作包：WP-07，并覆盖 WP-01—WP-06 的验收  
> 目标：内容、前端、无障碍、项目子路径和部署失败语义都有可重复证据。

## 1. 测试分层

| 层级 | 工具建议 | 运行时机 | 必过范围 |
|---|---|---|---|
| 纯函数单元测试 | Python `unittest`、浏览器 JS 测试运行器 | 每次提交 | 解析、哈希、状态机、合并、tokenizer、评分 |
| 构建与产物测试 | Python `unittest`、JSON Schema | 每次构建 | 168 天、ZIP、索引、链接、Schema、base path |
| 浏览器 E2E | Playwright + Chromium | PR、main、发布前 | 真实静态站上的进度、搜索、导入导出、降级 |
| 无障碍 | `@axe-core/playwright`＋人工键盘/读屏检查 | PR 与发布前 | 模板全量规则、代表性内容人工审查 |
| 部署冒烟 | CI HTTP 检查＋Playwright | 部署后 | 首页、日课、ZIP、索引、设置页和旧版本回滚 |

Node.js 只用于测试，不改变 Python 静态站生产架构。建议 Python 3.11、Node.js 20 LTS；锁定 npm 依赖并使用 `npm ci`。

## 3. 内容构建测试

### 3.1 元数据

- 正常解析“今日目标、预计时间、前置准备、今日产出”，保留命令与中文标点。
- 缺失、重复、空标签给出文件和行号；非法时间、未知覆盖字段、重复 JSON 键失败。
- Day 6、Day 7、Day 168 类型正确；Day 029 环境类型覆盖生效；Day 161—168 无代码围栏仍可构建。
- 168 天完整，日号/周号/阶段一致；重复 day_id、断号、错误路径失败。
- `run_all` 与实际普通文件一致，当前仓库应识别 111 天，但测试不把未来新增脚本视为错误。

### 3.2 内容哈希

- 相同文件树和覆盖配置得到相同 SHA，不受构建时间、文件遍历顺序影响。
- README、图片、代码、冻结输出、有效覆盖任一变化都会改变 SHA。
- 其他日课、CSS、JS、base path 变化不影响本日 SHA。
- 符号链接、读取中文件变化、路径编码异常按失败处理。

### 3.3 ZIP

- 条目排序和时间戳固定，两次构建哈希一致。
- `run_all.sh` 的可执行权限保留，ZIP CRC 正确。
- ZIP 以当日 `code/` 为根；冻结 `outputs/`、build、缓存、二进制和对象文件默认不在 ZIP 中，显式 `source_include` 例外逐项通过。
- 绝对路径、`..`、反斜杠、符号链接、设备文件、超限文件、疑似密钥均失败。
- 无 `run_all.sh` 的日课不会生成虚假一键运行说明。

### 3.4 索引与页面

- lite 不含正文 chunk；六分片各 28 天，合计 168 天，commit 一致。
- 固定关键词命中预期日课，代码 token 不被错误拆分。
- chunk 锚点在 HTML 存在；重复/空 chunk 失败。
- 首页、日课、周、阶段、搜索、设置和静态 JS/CSS 全部存在。
- 根路径与项目子路径构建中无错误绝对资源 URL。

## 4. 状态机与导入合并测试

### 4.1 参数化状态测试

为七种日课类型生成所有关键组合，至少验证：

- 全未开始、单项进行中、部分完成、全部完成。
- 任一适用任务 blocked 时整体 blocked；不适用任务 blocked 被规范化。
- 其他任务完成而验收未开始/进行中为 ready_for_review。
- 验收先完成、练习未完成为 in_progress。
- review 不强制 experiment，但阅读、回忆/错题和复盘清单全部完成才 completed；final_assessment 必须完成所有适用项。

### 4.2 内容更新与计划

- SHA 变化保留任务、planned、证据 ID、访问时间并设置 needs_review。
- 复核只更新 SHA 和 needs_review，不自动完成任务。
- 浏览旧课仅更新访问时间；显式设置 planned 才改变首页主目标。
- 多条 planned 异常可检测、可修复，不随机切换。

### 4.3 导入安全

| 用例 | 预期 |
|---|---|
| 非 JSON、超过 5 MiB、重复日课、未来 Schema | 整批拒绝，数据库零变化 |
| `__proto__`、HTML、命令字符串、未知字段 | 拒绝或按白名单剔除策略中的明确规则处理，绝不执行/注入 |
| 合法记录＋未知日课 | 预检说明跳过，确认后仅导入交集 |
| 导入 revision 较新/较旧 | 较新整记录更新，较旧跳过并计数 |
| 同 revision 不同内容 | 等待用户选择本机/导入/稍后处理，不静默覆盖 |
| SHA 不同 | 保留历史并 needs_review |
| 替换导入 | 同事务先保存完整本机备份，abort 时备份与替换都回滚 |
| 写入中途失败 | 合并事务回滚并报告失败，不显示全部成功 |

## 5. Playwright E2E

### 5.1 浏览器上下文

每个用例使用新 context，确保 IndexedDB/localStorage 隔离；跨标签和跨持久化测试显式复用 context。测试不依赖线上生产站，也不把测试进度上传到第三方。

Chromium 为每次 PR 必过；Firefox/WebKit 为发布前必过，用于覆盖当前主流浏览器及其前两个稳定版本的兼容目标，旧浏览器只保证静态阅读。移动测试至少 320×800 和常见 390×844，桌面至少 1280×800。

### 5.2 核心 E2E 脚本

**进度闭环**

1. 打开 Day 029，勾选阅读 done、练习 in_progress、实验 blocked。
2. 验证整体 blocked，刷新后状态仍在。
3. 设为当前计划，回首页显示继续 Day 029。
4. 打开 Day 001，确认 planned 未回退。
5. 解除实验 blocked，完成适用任务，验证 ready_for_review→completed。
6. 周页、阶段页、总计划和首页计数同步。

**内容更新**

1. 注入同一 day_id 但不同 content_sha 的测试构建。
2. 验证原任务、证据引用和计划保留，出现待复核。
3. 点击已复核，提示消失且任务未改变。

**搜索**

1. 轻量搜索 MLIR，断言未请求 phase 分片。
2. 全文搜索 `run_all.sh`，按需请求分片并命中正确日课/锚点。
3. 设置阶段和类型筛选，结果全部满足条件，清除筛选后恢复；阶段筛选不请求无关分片。
4. 快速连续输入，旧请求后返回也不覆盖新结果。
5. 拦截一个分片为 500，显示不完整范围与重试，不显示“全站无结果”。

**导入导出**

1. 导出文件可重新解析，字段和记录数正确。
2. 坏文件预检后数据库不变；冲突文件显示摘要并按规则合并。
3. 清空需二次确认，完成后记录计数为 0，主题偏好不变；另测清除全部本地偏好只删除明确列出的主题/UI 键，不删除进度或同源其他应用数据。

**降级**

1. 禁用 JavaScript，正文、上下日、源码链接和总计划可用。
2. 模拟 IndexedDB 打开失败，任务操作进入有显著提示的内存临时状态，可导出，搜索和下载可用。
3. 模拟 quota/transaction abort，显示未保存且 UI 回滚。
4. 索引 404 时课程导航仍可用。

## 6. 无障碍验收

### 6.1 自动检查

对首页、计划、普通日课、集成日、复盘日、周、阶段、搜索、设置运行 axe；明暗主题各一次。阻断 critical/serious 违规，moderate 需逐项评审并修复或记录有期限的例外，不能简单忽略规则。

### 6.2 人工键盘路径

- 从页面顶部仅用 Tab/Shift+Tab 完成导航、任务设置、源码下载、搜索、导入和导出。
- 所有交互有可见 focus-visible；DOM 顺序与视觉顺序一致。
- 移动抽屉打开后焦点进入、Tab 循环、Escape 关闭、焦点恢复。
- SVG 缩放弹层可键盘打开/关闭，焦点不丢失。
- 状态提示通过适度 live region 播报，不重复、不抢焦点。

### 6.3 视觉与内容

- 普通文字、按钮、焦点指示和状态图形满足 WCAG 2.2 AA 对比度。
- completed/blocked 等同时有文字或图标，不仅靠颜色。
- 200% 缩放与 320 px 宽度无内容丢失；触控目标满足 24×24 CSS px 最低要求或有足够间距。
- 554 个 SVG 的引用通过构建检查 alt 属性；装饰图允许空 alt，信息图必须有等价文本。自动规则之外，每阶段至少抽样一张复杂图做人工替代说明评审。

## 8. 性能、兼容与依赖预算

以下是发布预算，不是当前网站实测值。测试报告必须记录设备、浏览器、网络、构建 commit 和测量方法：

- 首屏自有新增 CSS＋JS gzip 后建议不超过 150 KiB，不含既有渲染依赖、正文与图片；超限需评审并拆包。
- 首页和日课首屏不得请求六个正文索引或源码 ZIP；只有用户主动搜索/下载才触发对应请求。
- 索引加载后的常规查询以低于 100 ms 为目标，在约定参考设备测量；大分片解析不能造成持续长任务。
- 长文图片 lazy-load，任务卡和图片预留空间，新增组件不能造成明显正文跳动。
- 构建报告列出轻量索引、六分片、ZIP 的数量和大小，异常膨胀阻断评审。
- 字符量较大的代表日课上测试代码复制、SVG 弹层和进度操作，不得持续卡顿。
- 第三方脚本和样式尽量自托管；阻断现有 CDN 后，正文、目录、源码链接和上下篇仍可用。
- 任何页面不得隐式批量下载源码或冻结输出。

## 9. CI 工作流

### 9.1 推荐阶段

```yaml
jobs:
  content-test:
    steps:
      - checkout
      - setup-python: 3.11
      - run: python3 -m unittest discover -s tests/content -p 'test_*.py'
  build:
    needs: content-test
    steps:
      - checkout with full metadata
      - setup-python: 3.11
      - run: python3 tools/build.py
        env:
          LEARNING_BASE_PATH: /ai-chip-compiler-learning-plan
          TUTORIAL_COMMIT: ${{ github.sha }}
      - run: python3 tools/learning_validate.py --public public --base-path /ai-chip-compiler-learning-plan
      - upload-pages-artifact only after all checks
  browser-test:
    needs: build
    steps:
      - download the same tested artifact
      - setup-node: 20
      - run: npm ci
      - run: npx playwright install --with-deps chromium
      - run: npm run test:e2e && npm run test:a11y
  deploy:
    needs: [build, browser-test]
    environment: github-pages
    steps:
      - deploy exactly the artifact tested above
  smoke:
    needs: deploy
    steps:
      - verify deployed commit and critical URLs
```

实际 GitHub Pages 的 artifact 在 job 间传递需要Actions artifact，而不能假设 runner 文件系统共享。部署 job 必须引用同一 commit、同一 artifact digest。

### 9.2 权限与并发

- 顶层 `permissions` 最小化；只有部署 job 获得 `pages: write` 和 `id-token: write`。
- 测试 job 使用 `contents: read`，不需要 Pages 写权限。
- `concurrency.group: pages`，`cancel-in-progress: false`，避免旧构建晚于新构建覆盖。
- PR 只运行测试和构建，不部署；fork PR 不获得额外秘密。
- 不将 learner evidence、搜索词或本地进度加入 CI 日志。

## 10. 发布失败与回滚

### 10.1 失败语义

- 内容测试、构建、E2E、无障碍任一失败：不上传新 Pages artifact、不进入 deploy，现有线上版本不变。
- artifact 上传失败：不部署。
- 部署失败：标记发布失败，核实 Pages 当前版本；不得自动重复部署一个未测试构建。
- 部署后冒烟失败：立即停止后续宣传/发布步骤，按回滚流程恢复上一已知良好 artifact。

这对应 TC-B02 的准确含义：“不发布新产物，现有线上版本不被覆盖”。

### 10.2 回滚

1. 从 release 记录选择上一已知良好 commit 和 artifact digest。
2. 优先重新部署该**已测试 artifact**，而不是临时修改 HTML。
3. 若 artifact 已过期，从对应 commit 干净重建，重跑内容、E2E、无障碍和子路径检查。
4. 回滚后执行相同冒烟，记录故障版本、回滚版本、时间和原因。
5. 内容修复走新的 forward-fix PR，不在生产分支直接改生成文件。

浏览器 IndexedDB 数据与站点代码版本解耦。回滚不得清空学习者记录；若未来涉及 DB 降版本，应用应保留数据并提示，而不是删除高版本数据库。

## 12. 运维与故障诊断

P0 无服务端日志。问题报告建议收集：页面 URL、浏览器版本、是否隐私模式、控制台错误码、构建 commit 和可复现步骤；主动要求用户移除搜索词、笔记、个人代码、完整导出文件和 token。

常见定位：

| 现象 | 优先检查 |
|---|---|
| 全部进度“消失” | 是否换浏览器/域名/base path 源、清站点数据、IDB 是否不可用 |
| 任务点击后恢复 | 事务 abort/quota、UI 是否误报成功 |
| 搜索无正文 | 分片 404、commit 不一致、旧请求覆盖、网络失败 |
| 图片或 JS 404 | root_prefix、base path 双重拼接、绝对路径 |
| 内容更新反复提示 | 旧 content_sha 是否按复核语义更新 |
| 新构建未上线 | 测试 job、artifact、deploy needs、Pages concurrency |
