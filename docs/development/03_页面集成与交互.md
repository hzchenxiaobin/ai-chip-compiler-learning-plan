# 03：页面集成与交互

> 工作包：WP-03、WP-04、WP-05、WP-06  
> 输入：168 天 `days.json`、本地学习记录、轻量/正文搜索索引  
> 原则：服务端静态 HTML 先可读，JavaScript 只增强学习功能。

## 1. 全站集成顺序

### 1.1 静态层与增强层

每个页面分为两层：

- **静态层**：构建器直接生成标题、课程链接、目标、任务说明、源码链接和 noscript 提示。无 JavaScript 时可阅读、跳转和下载。
- **增强层**：`app.js` 读取本地数据后启用任务操作、完成率、继续学习、搜索和导入导出。增强失败只影响对应组件，不清空静态层。

不要在静态 HTML 中写“已完成 0%”让无 JS 用户误以为这是自己的真实进度。未初始化时显示“学习进度仅在启用 JavaScript 后读取”，初始化后替换为真实数据。

### 1.2 脚本与样式加载

```html
<link rel="stylesheet" href="<root_prefix>static/css/learning.css">
<script src="<root_prefix>static/js/vp-solution.js" defer></script>
<script type="module" src="<root_prefix>static/js/learning/app.js"></script>
```

保留现有主题初始化，避免闪烁；`learning.css` 使用现有 CSS 变量，不复制一套颜色。若现有脚本不是 `defer`，以实际页面为准保持其执行顺序，学习模块不得依赖它的私有变量。

### 1.3 DOM 命名

统一使用 `data-learning-*` 作为增强挂载点：

```text
data-learning="continue"
data-learning="day-progress"
data-learning="week-progress"
data-learning="phase-progress"
data-learning="search-form"
data-learning="search-results"
data-learning="data-management"
data-learning="storage-status"
data-learning="live-status"
```

CSS 类只负责样式，行为选择器使用 `data-learning-*` 和 `data-task-id`，避免修改主题样式时破坏功能。

## 2. 首页 `/`

### 2.1 静态内容

保留现有首页课程介绍、六阶段入口和总计划入口，新增三个区域：

1. **继续学习**：静态显示 Day 001 和总计划链接；JS 初始化后替换为真实继续目标。
2. **学习概览**：静态说明“进度保存在本浏览器”；JS 后显示完成、进行中、卡点和待复核数量。
3. **快速检索**：搜索框可静态链向 `/search/`，真正即时轻量搜索由 JS 增强。

### 2.2 初始化

```text
加载 days.json
  → 打开 Store
  → 读取全部 DayProgress（168 天规模可接受）
  → summarizeDays() + getContinueTarget()
  → 渲染继续卡、概览和最近访问
```

存储不可用时，继续卡读取显式内存临时状态，并持续显示“仅本次会话有效，请导出备份”；没有临时记录时退化为“从 Day 001 开始”或静态总计划。不得把临时状态显示为已持久保存。

### 2.3 继续学习卡

内容：日号、标题、阶段/周、整体状态、上次访问时间、待复核提示和主按钮。按钮文案按状态变化：

- 从未学习：“开始第 N 天”。
- 进行中：“继续第 N 天”。
- 待验收：“完成第 N 天验收”。
- 卡点：“查看第 N 天卡点”；P0 仅定位到任务卡，不展开 P1 卡点详情。
- 全部完成：“查看完整学习计划”。

只有用户显式点击“设为当前计划”才改变 `planned`；点击继续学习本身只更新访问时间。

## 3. 日课页 `/tutorials/week-NNN/day-NNN/`

### 3.1 页面区域顺序

```text
面包屑与周/阶段链接
日课标题、类型、技能、预计时间
内容版本待复核提示（如需要）
今日目标 / 前置准备 / 今日产出
学习任务卡
源码与实验资源卡
Markdown 正文
上一日 / 下一日
```

资源卡应在正文前可发现，但不遮挡正文。移动端不固定一个过高任务面板；可使用原生 `<details>` 折叠，默认展开当前未完成任务。

### 3.2 学习任务卡

四项任务使用 `<fieldset>` 和 `<legend>`，每项状态使用 radio group，而不是只有颜色的小圆点：

```html
<fieldset data-task-id="exercise">
  <legend>练习</legend>
  <label><input type="radio" name="exercise" value="not_started"> 未开始</label>
  <label><input type="radio" name="exercise" value="in_progress"> 进行中</label>
  <label><input type="radio" name="exercise" value="done"> 已完成</label>
  <label><input type="radio" name="exercise" value="blocked"> 有卡点</label>
</fieldset>
```

不适用项以文本显示“本日类型不要求”，对应 radio 不渲染或禁用并解释。状态变化后：

1. 禁用该任务组，防止重复点击。
2. `store.updateDay()` 中读取最新值、执行 `setTaskStatus()`、提交事务。
3. 成功后更新整体状态、周/阶段汇总和“已保存”时间。
4. 失败时恢复原选中值，显示“本次更改未保存”。

整体状态使用文字＋图标＋颜色三重编码：`not_started/in_progress/ready_for_review/completed/blocked`。`aria-live="polite"` 只播报一次操作结果，不把四个 radio 的所有变化重复读出。

### 3.3 计划当前日

任务卡提供独立 toggle：“设为当前学习计划”。设置成功后才更新首页继续学习主目标。取消计划不清空任务，也不修改 `last_visited_at`。

浏览旧课时绝不自动设置 planned。若当前记录 planned 且内容更新需要复核，计划仍保留。

### 3.4 内容版本提示

当前 `body.dataset.contentSha` 与记录 `content_sha` 不同时显示：

> 本日教程或代码已更新。你的任务状态和证据历史已保留，请复核变化后再继续。

按钮“已复核新版内容”调用 `acknowledgeContent()`。P0 不做全文 diff 查看器，可提供“查看当前源码”链接；不能自动勾选复核，也不能清除 `blocked/done`。

### 3.5 源码与实验资源卡

根据 `days.json` 渲染：

- “下载源码 ZIP”：指向 `source_zip`，使用普通 `<a download>`；同时显示 ZIP 不包含冻结输出。
- “在 GitHub 查看代码”：新窗口打开，使用 `rel="noopener noreferrer"`。
- “查看冻结输出”：仅 `outputs_url` 非空时显示。
- “运行方式”：`run_all=true` 时显示 `unzip day-NNN-source.zip -d day-NNN-source`，进入解压目录后执行 `bash run_all.sh`；否则提示查看 README。

本站 P0 不执行命令、不收集代码、不根据 ZIP 是否下载自动勾选实验完成。复制命令可复用现有代码复制机制，但不得复制 base path 或本地用户名。

## 4. 周页 `/weeks/week-NNN/`

### 4.1 静态结构

- 周号、所属阶段、本周关键产出、7 天列表、周总预计时间。
- 每日显示标题、类型、目标摘要、产出、学习/练习分钟和正文链接；关键产出日有显式标记。
- Day 6 标记“集成”，展示其组合/对照产出；Day 7 标记“复盘”，展示卡点、待补产出和下周准备；最终周按实际类型覆盖。
- 提供上一周、下一周和阶段页链接。

### 4.2 增强内容

读取 7 天记录，显示已完成、进行中、待验收、卡点、待复核数量及辅助阅读/日课进度。周主状态按关键产出、Day 6 集成和 Day 7 复盘派生，不能把 `7/7` 阅读或普通日课百分比直接写成“本周已掌握”。辅助进度条必须有文本等价值，例如 `<progress value="3" max="7">3/7</progress>` 旁显示“已完成 3/7 天（辅助指标）”。

每日卡片显示整体状态和四项子状态摘要，但不提供四个任务的完整编辑，避免与日课页产生多入口复杂冲突。Day 6/7 另显示关键产出和复盘状态。提供“继续本周”链接：优先本周 planned/最近未完成日，否则本周第一个未完成日。

## 5. 阶段页 `/phases/phase-N/`

静态输出阶段能力目标、4 周递进导航、28 天清单和 `key_output` 综合证据清单；增强后显示 28 天辅助完成数、各周关键产出状态、阶段主状态和本阶段继续入口。阶段主状态由四周关键产出和第 28 天综合复盘共同派生。

六个阶段使用一致布局，不为每阶段写独立 JavaScript。阶段页只加载当前阶段记录即可，若 Store 已提供全量缓存也可复用；不得为显示进度请求六个正文搜索分片。

## 6. 搜索页 `/search/`

### 6.1 页面结构

```text
标题与隐私说明（搜索仅在本地进行）
搜索表单：输入框、范围选择、提交按钮
轻量结果状态
正文分片加载/失败状态
结果列表
无结果与重试提示
```

范围选项：“课程信息”（轻量）和“全文”（六阶段）。另提供阶段（全部/1—6）、周（全部/1—24）和日课类型筛选，筛选条件写入 URL；无结果时显示当前筛选和一键清除。从首页携带 `?q=MLIR` 时，页面加载后自动执行轻量搜索；只有用户选择全文或点击“搜索正文”才加载大分片。

### 6.2 URL 与请求生命周期

- 输入防抖 150 ms，仅用于轻量查询；全文查询由显式提交触发。
- 使用 `history.replaceState()` 更新 `q` 和 `scope`，避免每次按键产生历史记录。
- 新查询调用 `controller.cancel()`，旧响应即使返回也不能覆盖新结果。
- 查询词写入 URL 属于用户可见行为；默认不上传服务器分析，也不写入 IndexedDB。
- 页面卸载时 abort 全部请求并释放分片引用；可在会话内缓存已验证分片，但不持久化到 localStorage。

### 6.3 结果项

显示日号、标题、章节、匹配片段、技能、阶段和链接。chunk 链接为 `joinBasePath(day.url) + "#" + encodeURIComponent(anchor)`；锚点必须在构建校验中存在。

高亮通过拆分文本节点并创建 `<mark>` 完成，不使用 `innerHTML`。无结果时提供“缩短关键词”“尝试命令/错误码完整文本”“切换到全文”建议，不推荐无关课程。

### 6.4 降级

- lite 失败：保留搜索页和课程导航，显示重试。
- 某一正文分片失败：可显示已成功阶段的少量结果，但必须显著标注“正文结果不完整，缺少阶段 N”，不能伪装成全站无结果。
- JavaScript 禁用：显示 noscript，提供总计划和 GitHub 仓库搜索链接。

## 7. 设置页 `/settings/`

### 7.1 存储状态

显示“进度保存在此浏览器，不会自动上传”。状态分为：

- 可保存：IndexedDB 可用，显示已有记录天数和最近本地更新时间。
- 临时状态：说明浏览器限制，进度只保存在当前页面会话的内存中，持续提示及时导出；课程阅读和下载仍可用。
- 配额异常：显示未保存提示和导出入口；不承诺导出一定成功，按实际事务结果显示。

不显示精确浏览器指纹、设备型号或持久化唯一用户 ID。

### 7.2 导入

流程：

```text
选择 JSON 文件
  → 完整预检（尚无数据库写入）
  → 显示可导入/跳过/冲突摘要
  → 选择合并或替换；同 revision 冲突逐项选择本机/导入/稍后处理
  → 用户确认；替换模式先建立可恢复本机备份
  → 在一个事务中执行导入
  → 显示新增/更新/冲突/失败结果
  → 触发全站数据失效通知
```

合并是默认模式；替换模式必须单独确认并先建立可恢复备份。相同 revision 但内容不同的记录展示双方摘要，等待用户逐项选择“保留本机”“使用导入”或“稍后手动处理”，未选择前不能开始导入。

使用文件选择按钮和拖放区时，两者都必须键盘可操作；拖放不是唯一入口。只接受 `.json` 和 `application/json` 作为初步提示，最终仍按内容校验，不能信任 MIME。

### 7.3 导出和清空

导出成功后显示文件名和记录数，不显示完整个人数据。清空采用二次确认，第一次点击展示风险与“先导出”按钮，第二次需明确确认；清空完成重新读取验证。

“清除全部本地偏好”是独立操作，明确列出将重置的主题、侧栏等设置，不影响学习记录，也不使用 `localStorage.clear()`。

设置页同时解释数据边界：换浏览器、清站点数据或使用隐私窗口可能导致记录不可用，导出备份是用户责任，P0 不做云同步承诺。

## 8. 总计划页 `/plan.html`

保留现有 168 天计划结构，按现有日课 pill/表格增加整体状态标记。增强策略优先复用 `data-day-id`；若现有 DOM 没有该属性，构建器补上，不在运行时靠标题猜日号。

计划页应支持“只看待复核/只看卡点”作为 P1 增强，不纳入 P0 验收。P0 只显示真实状态、继续学习和完成数。

## 9. 导航与移动抽屉

主导航增加：学习计划、阶段、搜索、我的数据。桌面和移动端使用同一链接集合。

移动抽屉要求：

- 打开按钮有 `aria-expanded` 和 `aria-controls`。
- 打开后焦点进入抽屉，Tab/Shift+Tab 不落到背景；背景不可交互。
- Escape 关闭，关闭后焦点回到打开按钮。
- 抽屉打开时锁定背景滚动，但不导致页面横向跳动。
-  breakpoint 变化、链接跳转和页面卸载时清理监听器。

若采用 `<dialog>`，使用原生焦点与 Escape 行为并补测试；若保留现有 div，则显式实现焦点圈和 `inert`，不要只加 `aria-modal`。

## 10. 主题、SVG 与正文交互边界

- 新组件颜色引用现有主题变量；完成/卡点不能只用绿/红区分。
- SVG 图片仍由 `vp-solution.js` 缩放。缩放弹层需要可访问名称、键盘关闭、焦点恢复；正文 `alt` 作为替代说明来源。
- 学习 JS 不重排代码块、不重写 KaTeX/MathJax、不对 SVG 内部脚本给予权限。
- 外链统一 `rel="noopener noreferrer"`；证据中的链接在 P1 仍不自动打开。
- 页面已存在的代码复制、页内目录、返回顶部不得因学习模块加载而重复绑定事件。

## 11. 响应式与视觉状态

断点沿用现有站点，不另建移动页面。最低验收宽度为 320 CSS px；任务 radio 在窄屏纵向排列，源码按钮可换行，表格允许合理横向滚动但页面整体不能横向溢出。

状态必须覆盖：默认、hover、focus-visible、active、disabled、loading、error、empty、storage-unavailable、needs-review。焦点环对比度清晰，不能全局 `outline: none`。

## 12. 页面集成完成定义

- 六类页面均使用同一份 `days.json` 和 Store，不出现各页自算一套状态。
- 日课页四项任务、计划当前日、内容复核、资源卡完成真实事务闭环。
- 首页继续学习和周/阶段汇总能随跨标签更新而刷新。
- 搜索仅在用户请求全文时加载正文分片，结果链接在根路径和项目子路径都正确。
- 设置页导入预检、合并报告、导出和清空均不误导用户。
- 无 JS、存储失败、索引失败、320 px、键盘和明暗主题下均保留可用路径。
