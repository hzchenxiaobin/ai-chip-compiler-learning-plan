# 03：动态页面集成与交互

> 工作包：WP-03、WP-04、WP-05、WP-06  
> 目录：`config/urls.py`、`apps/*/views.py`、`templates/`、`static/`  
> 目标：服务端输出完整可导航页面，JavaScript 负责增强；登录态、权限和错误状态一致。

## 1. 路由与页面

| 页面 | URL | Django 路由名 | 模板 |
|---|---|---|---|
| 首页 | `/` | `home` | `home.html` |
| 路线总览 | `/plan/` | `plan` | `plan.html` |
| 日课 | `/tutorials/week-005/day-029/` | `tutorial-day` | `tutorials/day.html` |
| 周详情 | `/weeks/week-005/` | `week-detail` | `weeks/detail.html` |
| 阶段详情 | `/phases/phase-2/` | `phase-detail` | `phases/detail.html` |
| 搜索 | `/search/` | `search` | `search.html` |
| 我的学习 | `/dashboard/` | `dashboard` | `me/dashboard.html` |
| 设置与数据 | `/settings/` | `settings` | `me/settings.html` |
| 登录/注册 | `/login/`、`/register/` | Django auth 路由 | `registration/*` |

`/plan.html` 可 301 到 `/plan/` 以兼容旧链接；其余无效 URL 返回动态 404，不由 Nginx 全部回退首页。日课参数非法或不属于 active release 返回 404，避免枚举未发布版本。

所有内部链接使用 `{% url 'tutorial-day' week=day.week day=day.day %}`。静态资源用 `{% static %}`，公开资源下载使用 ContentAsset 的授权 URL。没有 base path 配置。

## 2. Base 模板与全站组件

```django
{% load static %}
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{% block title %}AI 芯片编译器学习{% endblock %}</title>
  <link rel="stylesheet" href="{% static 'css/site.css' %}">
  {% block head %}{% endblock %}
</head>
<body>
  <a class="skip-link" href="#main-content">跳到正文</a>
  {% include "components/header.html" %}
  <main id="main-content">{% block content %}{% endblock %}</main>
  {% include "components/footer.html" %}
  <script type="module" src="{% static 'js/learning/bootstrap.js' %}"></script>
</body>
</html>
```

全站组件：当前路线 header、移动端导航、面包屑、学习状态 badge、卡片、进度环、任务 checkbox、筛选 tabs、代码块/复制、提示条、对话框、toast、页脚。

`vp-solution.js` 仅作用于 `.vp-doc` 的折叠解析、代码复制、图片查看和锚点；DOM 无目标即退出，不隐藏正文，不接管进度保存。重复初始化用 data attribute 防重。

## 3. 匿名与登录上下文

公开首页、路线、日课、周/阶段和搜索对匿名开放。匿名用户看到“登录后保存进度”，checkbox 不伪装已保存，可以禁用或点击后打开登录说明。

登录用户的私有 context 只进入私有页面或受保护 API，不注入公开 HTML 共享缓存。`Vary: Cookie` 不能单独替代私有 no-store；对 dashboard 和 API 明确设置缓存策略。

标准 Django 登录/注册表单在 JS 不可用时仍能提交。启用增强后保留表单字段名称、CSRF 和验证错误。密码管理器可识别字段，错误信息不泄露账号是否存在；注册后按配置进入验证或 onboarding。

## 4. 首页

### 4.1 服务端渲染

- Hero、真实教程统计、六阶段、Day 029 等代表样例和 FAQ。
- 匿名主按钮“从 Day 1 开始”。
- 登录用户通过 dashboard fragment/API 获取今日任务卡；主按钮为“继续 Day N / 复习 Day N / 开始 Day N”。
- 私有卡片加载失败不阻塞公开内容，显示局部重试。

### 4.2 今日任务卡

展示日号、标题、阶段、预计时间、四任务状态、整体派生状态和继续链接。内容 `needs_review` 时显示“教程已更新，查看变更”，不自动清空任务。

任务切换遵循 ProgressController 的 pending/成功/失败/412 流程。连续点击只保留一个串行写队列；离开页面时未完成请求提示未保存，不用 beforeunload 做不可靠保存。

## 5. 日课页

### 5.1 内容与安全

- 服务端输出面包屑、标题、目标、时间、前置准备、产出、技能、内容版本和消毒后的正文。
- 上一日/下一日、源码、run_all、原始 README 和 GitHub 链接根据实际资源显示。
- 代码路径、测试命令来自教程，不由 UI 猜测；不存在 run_all 时不显示该按钮。
- `needs_review` banner 展示旧复核 SHA 和当前版本入口，确认后才更新 ack_content_sha。

### 5.2 学习面板

四任务保留稳定 DOM ID，如 `task-day029-reading`。状态包括：未加载、未登录、保存中、已保存、未保存、冲突。颜色之外配文本和图标。

标准表单降级可以采用“保存本日进度”一次提交完整任务映射；服务端成功 PRG（Post/Redirect/Get），冲突回到页面显示当前版本。JS 增强后才启用单 checkbox 即时保存。

上一日/下一日只更新 URL 和服务器访问记录；不因浏览旧课改变 planned。planned 通过“设为当前学习日”单独操作。

## 6. 路线、周与阶段

路线总览使用 active release 的 24 周和六阶段。登录时服务端批量查询用户进度，避免模板 N+1。显示每个日的派生状态、关键产出和待复核标记，但不把阅读完成当周完成。

周详情包含 Day 1—7、关键任务、集成、复盘和完成门禁；阶段详情包含 28 天、周卡、阶段综合项目和能力解释。P0 未启用自测/证据/复习/卡点组件不渲染，也不提前出现假按钮。

筛选通过 GET 参数和标准链接实现；JS 增强可以局部更新，但复制 URL 可复现筛选结果。

## 7. 搜索页

桌面 Ctrl/⌘＋K 打开搜索入口，移动端 header 提供按钮。标准 GET 表单支持无 JS 查询和分页。

增强交互：

- 输入、阶段筛选、加载更多、取消旧请求。
- 结果显示日号、标题、章节、技能、 snippet 和真实锚点。
- 代码/错误 token 使用 `<code>` 样式，但 snippet 一律纯文本转义。
- 错误、空结果、查询过短、服务不可用分别提示。
- 加载更多失败保留已加载列表和 cursor，可重试。

## 8. 我的学习与设置

### 8.1 Dashboard

包含当前计划、最近访问、连续学习的谨慎事实指标、周/阶段进度和待复核列表。P0 只显示可由 LearningPlan/DayProgress 证明的数据，不显示虚构 streak 或学习时长。

### 8.2 数据管理

- 导出：任务创建、排队、生成、下载、过期状态。
- 导入：文件选择、预检摘要、逐日冲突、合并/替换选择、替换文字确认、最终任务结果。
- 删除学习数据与删除账号是不同对话框，明确范围、认证要求和恢复可能。
- 删除进行中禁用高风险操作，但不阻止用户查看状态。
- 私有下载链接短时有效，页面不长期暴露签名 URL。

替换或删除成功使用 PRG/完整刷新清理内存状态；失败保留用户选择，不让 UI 显示“已删除/已导入”。

## 9. 账号生命周期页面

提供注册、登录、退出、密码重置、会话管理和必要的邮箱验证。退出必须 POST＋CSRF，不用 GET。会话撤销显示设备/时间的安全摘要，不暴露完整 IP 或 token。

删除账号按隐私策略采用立即匿名化或短时延迟任务；待删除期间限制新证据、导出和社区操作。备份保留期在设置中说明。

## 10. 无障碍与响应式

断点建议：`<768` 单列和底部/抽屉导航，`768—1199` 双列，`>=1200` 最大内容宽度加侧栏。日课正文优先可读性，数据表横向滚动而非压扁。

所有交互有键盘路径、可见焦点、语义按钮、label、aria-live 状态和焦点恢复。触控目标至少 44×44 CSS px。尊重 reduced-motion，不自动播放动画。

代码、表格、SVG 和长路径在 320px 宽度不破坏页面；中文和英文技术词合理换行。对比度至少 WCAG 2.2 AA。

## 11. 安全、缓存与降级

- 启用 Django clickjacking、XSS、安全 Cookie、HSTS（HTTPS 验收后）、Referrer-Policy 和合理 CSP。
- 教程 sanitizer、snippet 转义、个人文本转义三层不能互相替代。
- 公开内容可短缓存；登录页面和私有 API no-store。
- MySQL 故障：公开缓存页面可继续读；个人读取/写入明确失败，不进入本地“成功”模式。
- Redis 故障：依赖限流/队列的敏感操作 fail closed；非关键缓存可穿透限流访问数据库。
- Celery 故障：导出/导入保持排队或失败状态，绝不生成假下载。

## 12. 页面验收

1. 无 JS 可阅读、导航、搜索、登录和完整保存进度。
2. 匿名阅读、登录保存、退出和会话撤销一致。
3. 六阶段/24 周/168 天深链和导航正确。
4. 勾选、失败、412 冲突、planned 与 needs_review 可见且正确。
5. 源码按钮和资源存在性一致。
6. 导入导出、替换确认和删除状态完整。
7. 320px、键盘、读屏、减弱动画和代码复制可用。
8. 公开缓存不含私有数据；错误降级不伪造成功。
