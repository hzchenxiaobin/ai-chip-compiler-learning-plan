# 13：P2 隔离远程实验与 L3 复验开发

> 工作包：WP-16（独立执行与验证项目）  
> 对应范围：FR-015 的远程执行；证据级别 L3  
> 前置：WP-11 证明链经验、独立安全预算、威胁建模和运维责任人  
> 原则：学习者代码始终不可信；未通过隔离与私有测试验收，就不开放“平台复验”。

## 1. 范围与上线门槛

L3 用于少量需要教师评估或可信证明的日课，不替代本地/WSL 和 L2 CI。首批建议只做 Day 029、097、160 的固定测试管道，由受信执行清单控制构建和测试命令；不开放任意长时间终端、任意 apt 安装或持久 root 环境。

上线必须同时具备：微虚拟机或等价强隔离、无秘密执行环境、资源配额、默认无外网、平台控制的私有测试、产物限制、签名 attestation、审计、成本熔断和销毁验证。普通 Docker 容器＋FastAPI 子进程不满足门槛。

## 2. 服务架构

```text
浏览器实验页
  ↔ Lab API（认证、配额、幂等、任务状态）
  ├── Source Intake：ZIP/commit 校验、内容哈希、恶意路径检查
  ├── Queue：持久任务、租约、超时、取消、死信
  ├── Lab Controller：按清单创建一次性执行环境
  │     └── 独立 worker pool → Firecracker microVM / 经评审的 gVisor 环境
  ├── Private Test Broker：位于独立验证域，以最小用例通道连接受信测试适配器
  ├── Artifact Store：隔离上传区 → 扫描 → 受限下载
  └── L3 Attestation Signer：独立密钥，只接收结构化验证结果

Lab API / Controller / Signer 不共用数据库超级权限；
任何组件都不能通过 Pages 静态前端直接调用管理接口。
```

同步账号可用于配额和身份，但 L3 与 Learning API 分库分权。教师反馈、AI 助教都不能直接创建 job，必须经用户显式提交和 Lab API 校验。

## 3. 执行清单

```json
{
  "manifest_version": 1,
  "day_id": "day-160",
  "tutorial_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "image_digest": "sha256:固定基础镜像",
  "test_suite_sha": "64位私有测试套件哈希",
  "build_command": ["/opt/verifier/bin/build", "/work/source"],
  "test_command": ["/opt/verifier/bin/test", "/work/source"],
  "limits": {
    "cpu": 2,
    "memory_mb": 4096,
    "pids": 256,
    "disk_mb": 2048,
    "wall_seconds": 300,
    "output_bytes": 1048576,
    "artifact_bytes": 10485760
  },
  "network": "none",
  "artifact_retention_days": 7
}
```

命令由平台清单固定，不接受学习者 JSON 中的 command。Day 097 的性能数据只在该声明环境中有效，页面显示 image/test suite/limits，不与其他硬件直接排名。清单按 day_id＋tutorial_commit 显式兼容，不能使用“最新版”镜像或测试。

## 4. 输入与任务创建

### 4.1 来源

支持两种输入，初版二选一实现完整后再扩展：

- HTTPS 公开 Git 仓库＋完整 commit：Source Intake 用短期只读凭证解析并快照，凭证绝不进入执行环境。
- ZIP：最大 20 MiB、2,000 条目、解压后 100 MiB；拒绝绝对路径、`..`、反斜杠逃逸、符号链接、硬链接、设备文件、二进制超大文件和疑似密钥。

输入保存为不可变 `source_sha`，包含路径、大小和文件哈希。私有仓库不是默认试点；未来支持时使用短期 broker token，克隆后立即吊销，不写入日志/artifact。

### 4.2 API 与状态机

| 接口 | 用途 | 约束 |
|---|---|---|
| `POST /v1/lab-jobs` | 创建任务 | 登录、Idempotency-Key、day_id、source、清单校验 |
| `GET /v1/lab-jobs/{id}` | 状态和资源用量 | 仅所有者/授权教师，不泄露私有测试 |
| `POST /v1/lab-jobs/{id}/cancel` | 请求取消 | 本人，幂等 |
| `GET /v1/lab-jobs/{id}/events` | SSE 状态/脱敏日志 | 有上限，不能伪装实时终端 |
| `GET /v1/lab-jobs/{id}/artifacts` | 列出扫描后产物 | 短时签名 URL，禁止 HTML 内联 |
| `GET /v1/lab-jobs/{id}/attestation` | 获取 L3 证明 | 仅成功且签名有效时返回 |

```text
queued → preparing → running → collecting → verifying → succeeded
   │         │          │            │            └→ failed_verification
   │         │          │            └→ failed
   │         │          └→ timed_out | cancelled | resource_exceeded
   └→ expired_cancelled
```

终态不可回写运行中；worker 结果必须带 job_id、lease_generation 和 attempt，过期 lease 不得覆盖新 attempt。重试产生新 attempt 和新日志，不篡改上次结果。

## 5. 隔离执行合同

每次任务使用全新 microVM 或经独立评审的等价隔离环境：

- 非 root 用户、只读根文件系统、独立临时工作盘，任务结束销毁整实例和密钥材料。
- 无 privileged、host PID/IPC、Docker socket、宿主机目录写挂载、云 metadata 地址或管理网络路由。
- seccomp、capabilities 全部drop、cgroup CPU/内存/PID/磁盘和 RLIMIT 同时生效；不能只设置应用层 timeout。
- 默认网络完全关闭，依赖已在固定镜像中；构建和测试都不允许 DNS/出站连接。
- 私有测试包驻留在 learner 执行域之外的独立验证域，或由独立 verifier 用户以 learner 不可读、不可写的权限保护；只读挂载只能防篡改，不能当作保密控制。结果采集只输出通过/失败和允许公开的错误摘要。
- stdout/stderr 分通道限长、控制字符清理、UTF-8 安全处理；达到上限截断并标记，不继续读满内存。
- 一台 worker 同一时间只运行声明数量的隔离实例；高风险评估使用独立节点池，避免共享宿主机侧信道假设。
- 销毁后由 controller 验证实例、临时盘、网络命名空间和本地秘密均已清理。

gVisor 可降低系统调用风险但不自动等价微虚拟机；选择时必须记录威胁模型和独立安全评估，不得只在文档写“沙箱”就验收。

## 6. 私有测试与结果采集

Private Test Broker 按 manifest.test_suite_sha 向独立 verifier 安全域提供不可变测试包，controller 验证哈希和调用方身份。受信适配器只按固定协议逐用例请求必要输入并返回机器结果；完整测试包、未下发用例和期望输出不得进入 learner 工作区、Source Intake、artifact、模型索引或普通日志。若采用同 microVM 内的独立 verifier 用户，测试目录必须对 learner 不可读且执行通道最小化，并通过独立安全评审；不能仅以 chmod 只读作为验收依据。

测试保密边界必须如实表述：某个输入一旦按协议交给被测程序，就应视为本次已对被测代码暴露；平台保护的是完整测试集、未下发用例、期望输出和后续评测材料，不承诺被测程序无法记录它已经收到的输入。错误反馈只返回 rubric 项和允许公开的反例，不批量回显隐藏用例。

结果分为：

- `passed`：构建和全部必需私有测试通过，退出码与机器报告一致。
- `failed`：测试失败，只返回允许公开的测试名/摘要。
- `error`：基础设施错误，不显示为学习者代码失败，也不能签发通过证明。
- `resource_exceeded/timed_out/cancelled`：明确区分，不自动重试到成功为止。

性能结果必须记录执行环境、输入、基线、预热、重复次数、统计方法和 limits；异步执行需明确同步口径。私有测试失败详情如可能泄露隐藏输入，只返回 rubric 项和可公开反例。

## 7. L3 Attestation

```json
{
  "schema_version": 1,
  "attestation_id": "01J...ULID",
  "level": "L3",
  "evidence_hash": "64位证据哈希",
  "job_id": "01J...ULID",
  "job_attempt": 1,
  "day_id": "day-160",
  "tutorial_commit": "40位教程提交",
  "learner_commit": "40位学习者提交或null",
  "source_sha": "64位输入快照哈希",
  "manifest_sha": "64位执行清单哈希",
  "image_digest": "sha256:固定镜像",
  "test_suite_sha": "64位私有测试哈希",
  "result": "passed",
  "started_at": "2026-11-24T10:00:00Z",
  "finished_at": "2026-11-24T10:02:00Z",
  "resource_usage": {"wall_ms": 120000, "max_memory_mb": 1024},
  "verifier_version": "l3-lab-v1",
  "key_id": "l3-2026-01",
  "signature": "独立L3私钥对JCS payload的签名"
}
```

签名服务只接受 controller 经服务间认证的规范结果，并重新校验 job/source/manifest/test suite/result 一致性。L3 与 L2 使用不同 key 和策略；attestation 过期、撤销或字段不匹配时前端不显示有效 L3。

教师人工反馈和 AI 文本都不能成为 signer 输入。学习者提供的 `level:L3` 字符串、控制台截图或 job URL 不能替代签名证明。

## 8. 威胁模型与必测攻击

| 威胁 | 主要控制 | 必测证据 |
|---|---|---|
| ZIP 路径逃逸/链接 | 路径规范化、普通文件白名单、解压后复查 | 恶意 ZIP fixture，无宿主机写入 |
| fork bomb/内存/磁盘/死循环 | cgroup＋RLIMIT＋墙钟＋输出限制 | 各类资源超限终态准确，worker 不失联 |
| 宿主机逃逸 | microVM/评审隔离、最小 syscall/capability、无 socket | 独立渗透测试，无共享宿主资源 |
| 网络数据外泄 | network none、无 metadata/管理路由、无凭证 | 出站与 DNS 全阻断测试 |
| 私有测试窃取 | 独立验证域、最小用例通道、结果脱敏、产物白名单 | 日志/artifact 不含完整测试包、未下发用例或期望输出 |
| artifact XSS/日志注入 | 纯文本、控制字符清理、下载强制附件 | HTML/SVG/ANSI 恶意 fixture |
| 队列/成本 DoS | 用户/全站配额、并发1、幂等、熔断 | 重复请求和洪峰不超预算 |
| 重放旧 worker 结果 | lease_generation、attempt、不可变终态 | 过期 lease 无法覆盖新结果 |
| 供应链替换 | 固定 digest、test suite hash、构建清单签名 | 标签变化不被接受，digest 改变可审计 |

## 9. 配额、成本与运维

初始每用户同时运行 1 个 job，每日成功创建 5 个，单 job 最长 300 秒；全站设置并发、每日费用和队列长度硬上限。超过配额返回可理解错误，不排队到不可控未来。管理员有全局 kill switch，只停止新任务，可取消运行任务，不影响静态教程。

审计记录 job 所有者、source/manifest/test suite hash、状态、资源用量、worker、attempt 和时间，不记录私有测试正文或秘密。artifact 默认 7 天后删除，日志和证明保留策略分别说明。

监控只使用必要指标：排队时长、成功率、超时/资源超限、销毁失败、单 job 成本和配额拒绝。告警不包含用户代码/完整日志。灾难恢复优先销毁 worker 并停止签名，不能为了恢复队列而跳过验证。

## 10. 灰度、测试与回滚

1. **离线攻击测试**：无公网用户，验证资源限制、路径安全、销毁和结果签名。
2. **内部试点**：仅开发者提交固定样例，Day 029/097/160 各跑成功、失败和超时。
3. **独立安全评审**：渗透与架构复核，高危问题关闭后才能邀请用户。
4. **邀请灰度**：少量账号、固定配额、无教师证书承诺，观察成本和结果质量。
5. **受控发布**：按日课 feature flag 开放，保留一键关闭和撤销证明能力。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| P2-TC-LAB-01 | 正常通过 | 固定 source/manifest/test 私有测试通过，签名 L3 可验 |
| P2-TC-LAB-02 | 路径与产物攻击 | 逃逸/链接/XSS/日志注入均不能影响宿主或页面 |
| P2-TC-LAB-03 | 资源与网络 | fork/内存/磁盘/超时/出站均受限，实例完全销毁 |
| P2-TC-LAB-04 | 私有测试保密 | 日志、错误、artifact、API 均不泄露完整测试包、未下发用例或期望输出 |
| P2-TC-LAB-05 | 重试与重放 | 过期 lease、重复 webhook、重复创建不篡改终态或证明 |
| P2-TC-LAB-06 | 证明边界 | 人工反馈、AI、学习者声明不能签发 L3，撤销/过期生效 |
| P2-TC-LAB-07 | 配额与熔断 | 并发/日配额/全站 kill switch 生效，Pages 和本地学习不受影响 |
| P2-TC-LAB-08 | 安全评审与灰度 | 独立高危问题清零，代表日三类结果和成本报告齐全 |

任何隔离、私有测试、销毁或签名门槛不满足，WP-16 都只能保持关闭；不能用“内部测试版”名义向普通学习者开放任意代码执行。
