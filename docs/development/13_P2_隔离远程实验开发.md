# 13：P2 隔离远程实验与 L3 复验开发

> 工作包：WP-16（独立执行与验证项目）  
> 对应范围：FR-015 的远程执行；证据级别 L3  
> 前置：WP-11 证明链经验、独立安全预算、威胁建模和运维责任人  
> 原则：学习者代码始终不可信；未通过隔离与私有测试验收，就不开放“平台复验”。

## 1. 范围与上线门槛

L3 用于少量需要可信证明的日课，不替代本地/WSL 和 L2 CI。首批只做 Day 029、097、160 的固定测试管道，由受信清单控制构建和测试命令；不开放任意长终端、任意 apt 安装或持久 root 环境。

上线必须同时具备：microVM 或经独立评审的等价强隔离、无秘密执行环境、资源配额、默认无外网、平台控制的私有测试、产物限制、L3 attestation、审计、成本熔断和销毁验证。普通 Docker 容器＋Web 子进程不满足门槛。

## 2. 服务架构

```text
Django 动态主站实验页
  ↔ Lab API（用户认证、配额、幂等、任务状态）
      ├── Source Intake：ZIP/commit 校验、source_sha、路径检查
      ├── Queue：持久任务、租约、超时、取消、死信
      ├── Lab Controller：按受信清单创建一次性执行环境
      │     └── 独立 worker pool → Firecracker microVM / 经评审的等价隔离
      ├── Private Test Broker：独立验证域，最小用例通道
      ├── Artifact Store：隔离上传区 → 扫描 → 受限下载
      └── L3 Attestation Signer：独立密钥，只接收结构化结果
```

Lab API、Controller、Executor、Signer 不共用数据库超级权限。任何浏览器前端都不能直接调用 Controller、worker、Broker 或 Signer 管理接口；主站 Django/Gunicorn 也不执行学习者代码。

主站账号只用于身份和配额。Lab 使用独立 Schema/DB 和最小服务 API；教师反馈、AI 助教不能直接创建 job，必须经用户显式提交和 Lab API 校验。

## 3. 执行清单

```json
{
  "manifest_version": 1,
  "day_id": "day-160",
  "tutorial_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
  "image_digest": "sha256:固定基础镜像",
  "test_suite_sha": "64位私有测试套件哈希",
  "build_command": ["/opt/verifier/bin/build", "/work/source"],
  "test_command": ["/opt/verifier/bin/test", "/work/source"],
  "limits": {
    "cpu": 2,
    "memory_mb": 4096,
    "pids": 256,
    "disk_mb": 2048,
    "wall_seconds": 300,
    "output_bytes": 1048576
  },
  "network": "none"
}
```

manifest、基础镜像、私有测试和 signer 版本不可由学习者修改。命令是固定 argv，不拼接 shell 字符串。允许教程 commit 明确列出。

## 4. Source Intake 与任务状态

支持受控 ZIP 或公开 Git commit 快照。ZIP 检查路径穿越、链接、重复条目、炸弹、大小、文件数和疑似秘密；Git 源码固定完整 SHA，拒绝运行过程中的分支漂移。计算 source_sha 并保存来源清单。

状态：

```text
queued → preparing → building → testing → collecting → verified
   │         │          │         │          │
   └─────────┴──── failed / timeout / cancelled / resource_exceeded
```

`POST /api/v1/lab/jobs/` 带 Idempotency-Key、day_id、source reference 和 manifest_version。重复提交返回同一 job；源码或清单不同则创建新 attempt，不复用旧结果。

Queue 有租约、心跳、重试上限和死信。worker 崩溃后 lease 过期才可重试，重试产生 run_attempt 并绑定最终证明，避免多个执行同时写成功。

## 5. 强隔离执行环境

最低控制：

- 每次 job 一次性 microVM 或独立评审认可的等价隔离，内核/硬件边界按威胁模型选择。
- 非 root、只读 rootfs、独立临时 workdir、最小 capabilities、seccomp/sysctl 基线。
- CPU、内存、PID、磁盘、wall time、输出和进程数硬限制。
- 默认无外网；构建依赖预置固定镜像，禁止下载未锁定依赖。
- 执行环境无云 metadata、宿主 Docker socket、主站/MySQL/Redis/签名密钥和其他任务数据。
- Controller 与 Executor 分权，worker 只能领取被授权 job。
- 完成/失败/超时后销毁环境并验证卷、网络、进程和临时密钥清理。

gVisor 等方案不能仅因名称被视为等价，必须由独立威胁模型、逃逸攻击面和测试证明其适用性。

## 6. 私有测试 Broker 与保密边界

私有测试位于独立验证域，不打包进学习者镜像，不以下载 URL 发给执行环境。Executor 只通过最小用例通道接收当前 day/attempt 所需输入，Broker 返回结构化通过/失败和允许公开的诊断。

限制：用例内容、隐藏边界、预期完整输出和内部堆栈不进入学习者日志。错误消息经过策略过滤，避免逐字节 oracle 泄露私有测试。私有测试适配器不接收主站数据库凭据。

私有测试的读取权限不等于保密：Broker 必须只暴露最小必要输入，并对频率、结果长度和错误粒度进行控制。

## 7. 结果、日志与 Artifact

机器报告包含 summary/tests、环境、source_sha、manifest_sha、test_suite_sha、run_attempt、开始/结束时间和资源使用。summary 与 tests 一致；timeout/resource_exceeded 不能写成 passed。

日志按字节/行数截断，控制序列和疑似秘密清理，明确标记 truncated。artifact 先隔离扫描，再生成短时授权下载；私有测试、完整系统镜像和其他任务产物不提供下载。

只有验证管道可写最终结果。用户取消或页面关闭不能伪造失败/成功；状态来自 Controller 事件。

## 8. L3 Attestation

payload 至少包含：

```text
schema_version, level=L3, evidence_hash, day_id,
source_sha, learner_commit, tutorial_commit,
manifest_sha, image_digest, test_suite_sha,
job_id, run_attempt, verification_result_digest,
issuer, kid, issued_at, expires_at
```

对 JCS(payload) 使用独立 Ed25519 密钥签名。Signer 只接受授权 verifier 的结构化结果，拒绝外部任意 payload。主站验签并核对 EvidenceRecord、job、source、manifest、test suite 和 attempt 后提升 effective_level=L3。

L2 与 L3 使用不同 key/issuer/scope。撤销、过期和密钥轮换有明确策略；导入 JSON、教师反馈、AI 输出和项目同步均不能创建 L3。

## 9. Lab API 与前端

- `POST /api/v1/lab/jobs/`
- `GET /api/v1/lab/jobs/{id}/`
- `POST /api/v1/lab/jobs/{id}/cancel/`
- `GET /api/v1/lab/jobs/{id}/events/`（SSE 或轮询）
- `GET /api/v1/lab/jobs/{id}/artifacts/`

只显示本人 job 和授权公共示例。环境、资源限制、私有测试边界和证据范围在提交前可见。取消、重试和刷新状态一致；断线不重复创建 job。

主站显示“平台强隔离＋私有测试复验”，不称绝对安全或防作弊考试。Lab 关闭时主站学习、L1/L1+/L2 和项目档案继续工作。

## 10. 配额、成本与 kill switch

按用户/日课/全站设置并发、每日次数、CPU 秒、存储和队列上限。超额返回明确 429/配额状态，不绕过限制。全站成本和异常失败率达到阈值自动停止新 job。

kill switch 分入口、队列、worker、签名四层；紧急停止只阻止新任务，正在销毁环境仍需完成清理。审计包含操作者、理由、job、资源、销毁和签名，不含秘密或私有测试正文。

供应链评审覆盖基础镜像、驱动、Broker、依赖和签名组件。worker 镜像不可由学习者指定。

## 11. 攻击测试、独立评审与灰度

测试路径穿越、压缩炸弹、fork bomb、磁盘/内存/超时、网络外联、metadata 访问、宿主挂载、逃逸、跨任务读取、私有测试推断、日志注入、artifact 替换、重放和签名伪造。

独立安全评审必须验证隔离、Broker、销毁和密钥边界，高危问题清零。灰度顺序：内部→独立评审→邀请用户→按日开放；每步保留 kill switch 和成本报告。

## 12. 验收

- `P2-TC-LAB-01`：合法 job、结果和 L3 签名绑定。
- `P2-TC-LAB-02`：资源/路径/日志/artifact 攻击与销毁验证。
- `P2-TC-LAB-03`：强隔离、无网络、非 root、无宿主秘密。
- `P2-TC-LAB-04`：私有测试独立域、最小通道和防泄漏。
- `P2-TC-LAB-05`：状态机、attempt、取消、SSE、本人权限。
- `P2-TC-LAB-06`：独立 key、撤销、过期、重放和伪造拒绝。
- `P2-TC-LAB-07`：配额、成本、全站熔断、kill switch 和审计。
- `P2-TC-LAB-08`：内部→独立评审→邀请灰度及主站降级。

任何强隔离、私有测试、销毁、签名或独立评审缺失，WP-16 保持关闭。
