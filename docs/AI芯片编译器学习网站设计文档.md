# AI 芯片编译器学习网站设计文档

**项目名称：**`ai-chip-compiler-learning-plan`  
**文档版本：**V2.0（动态网站架构）  
**修订日期：**2026-11-25  
**设计基线：**最新版《AI 芯片编译器 168 天学习网站建设指南》及仓库提交 `53b62f1c84223bb6ca466bb8177921ccd5d8ef72`  
**文档用途：**产品、交互、视觉、前后端、测试与运维联合评审  
**实施边界：**本文是设计交付，不代表功能已经开发

## 1. 产品概述

### 1.1 产品定位

网站定位为“**AI 芯片编译器项目制学习工作台**”。它以现有 24 周、168 天教程为内容基础，帮助学习者完成从 Modern C++、图 IR、MLIR、图优化、Lowering、Tiling、LLVM 与 Runtime 到 `minic` 端到端编译器的连续实践。网站围绕“今天学什么、需要交付什么、实验如何验证、卡住后如何继续、最终如何形成项目证据”组织体验。

本站采用**动态 Web 应用**：Django 提供服务端页面与 JSON API，MySQL 保存账号、内容读模型和学习数据，Redis 承担缓存、限流和任务队列，对象存储保存源码包、公开图片和私有文件。GitHub 只用于代码协作、教程版本管理和可选 CI，**不使用 GitHub Pages 托管生产网站**。

### 1.2 建设目标与成功标准

| 目标 | 可验证结果 | 不采用的替代指标 |
|---|---|---|
| 降低开始成本 | 新用户无需作者解释即可理解 Day 001 前置并获取源码 | 只统计首页访问量 |
| 降低续学成本 | 登录后从任意设备回到当前计划、任务或卡点 | 只统计页面停留时间 |
| 提升资源可达性 | 有代码日课提供版本化源码包与 GitHub 深链 | 要求用户理解整个仓库目录 |
| 区分学习状态 | 阅读、练习、实验和验收分别持久化 | 用滚动到文末代表学会 |
| 支持工程复现 | 证据关联教程版本、代码版本与环境 | 用单一百分比替代证据 |
| 支持可靠运营 | 内容可原子发布，数据可备份恢复，权限和故障可测试 | 以“页面能打开”代替系统验收 |

### 1.3 设计原则

**内容优先于平台。**168 篇正文继续以 Markdown/Git 为唯一权威源，不建立第二套可编辑 CMS。  
**任务优先于目录。**首页优先呈现下一步、当前产出与卡点，完整路线退居第二层。  
**证据优先于打勾。**“读过”“练过”“运行过”“复验过”分开表达。  
**本地执行优先于在线执行。**C++、MLIR、LLVM 实验在学习者本机或 WSL 中运行，动态网站负责指导、记录与复核。  
**模块化单体优先于微服务。**P0/P1 在一个 Django 应用中划分模块，高风险验证和执行服务再独立部署。  
**公开阅读与私密学习分离。**教程免登录可读，个人数据必须认证和行级授权。

## 2. 用户、场景与范围

### 2.1 用户角色

| 角色 | 主要诉求 | 首版支持方式 |
|---|---|---|
| 首次来访者 | 判断路线、时间、环境和最终项目 | 免登录阅读路线与 Day 001 |
| 持续学习者 | 跨设备继续当前日和本周闭环 | 注册登录、MySQL 进度、继续学习 |
| 实践学习者 | 获取代码、运行实验、记录问题 | 版本化源码包、自声明状态、P1 证据 |
| 复习者 | 按概念、命令、报错或文件名回查 | 服务端全文搜索；P1 复习与卡点 |
| 项目完成者 | 汇总架构、Pass、Lowering、测试、性能和复现 | P1 私密项目档案 |
| 内容维护者 | 从 Git 发布教程并保证资源完整 | 导入命令、发布后台、内容版本与回滚 |
| 平台管理员 | 账号、功能开关、审计和故障处理 | Django Admin/受控后台，最小权限 |

### 2.2 核心用户旅程

**首次学习：**打开首页→查看六阶段和最终项目→进入 Day 001→理解目标与前置→下载源码→注册/登录以保存进度→本地完成构建与测试→提交四项任务状态→在个人中心导出备份。

**持续学习：**再次打开首页→服务端返回当前计划、周关键产出和未解决卡点→继续当前日→完成 Day 6 集成与 Day 7 复盘→进入下一周。浏览旧课只更新最近访问，不回退主计划。

**跨设备学习：**设备 A 修改任务并提交 revision→设备 B 刷新读取最新记录→若 B 以旧 revision 写入，服务端返回 412 和当前记录→用户查看差异后重试，不做字段级时间戳拼接。

**回查与排错：**输入 `mlir-opt`、错误码、文件名或中文概念→服务端按阶段、周和类型筛选→返回命中上下文和真实锚点→P1 可加入复习或创建私密卡点。

### 2.3 版本范围

| 版本 | 纳入范围 | 明确排除 |
|---|---|---|
| P0：动态学习闭环 | Django/MySQL/Redis、内容导入、账号会话、源码包、服务端搜索、任务面板、在线进度、导入导出、周/阶段页、后台与部署 | 公开社区、排行榜、远程运行、离线编辑 |
| P1：练习与证据 | 自测、复习、卡点、证据上传、L2 CI、项目档案 | 将上传文件宣称为平台认证、断签惩罚 |
| P1 可选：离线恢复 | IndexedDB outbox、多设备冲突界面、删除防复活 | 把浏览器作为在线数据权威源 |
| P2：规模化能力 | 教师反馈、学习小组、讨论、AI 助教、隔离远程实验 | 未评审前上线高风险执行或社区 |

导航当前项使用 `aria-current="page"`；全站提供“跳到正文”。GitHub、源码下载和示例输出分别标注，避免误解。

## 4. 页面与交互设计

### 4.1 首页

匿名首页展示 Day 001、完整计划和公开搜索；登录首页由服务端注入当前计划、最近更新、周关键产出和卡点摘要。首屏不堆放复习卡、证书、积分或公开排名。缓存公开骨架时不得缓存任何用户字段；个人区域通过独立模板上下文或认证 API 获取。

```text
┌ 品牌 ─ 计划 ─ 路线 ─ 教程 ─ 搜索 ─ 我的学习 ─ 主题 ┐
│ AI 芯片编译器 168 天学习计划                       │
│ [继续 Day 029]  第 5 周 · MLIR 工作台               │
│ 云端已保存：今天 09:30  [查看本周] [回到卡点]        │
├──────────────────────────────────────────────────┤
│ 本周任务：D029—D035       关键产出：MLIR 最小闭环   │
└──────────────────────────────────────────────────┘
```

### 4.2 日课页

日课页由 Django 输出面包屑、标题、任务卡、白名单正文 HTML、资源卡与上下日导航。登录用户同时获得四项任务状态和 revision；匿名用户看到“登录后保存进度”，不显示虚假的 0%。

任务卡根据日课类型显示操作：有代码时展示源码 ZIP、GitHub 代码和示例输出；有 `run_all.sh` 时提供复制命令；无代码日展示产出或复盘动作。P0 实验完成是 L1 自声明，P1 才增加证据上传。状态提交使用 `fetch`＋CSRF＋`If-Match`，成功后重新读取或采用响应中的新 revision；失败时恢复原控件并明确“未保存”。

### 4.3 周页与阶段页

周页按“Day 1—5 能力零件→Day 6 集成→Day 7 复盘”组织。周完成由关键产出、Day 6 和 Day 7 派生，七篇已读不能显示“本周已掌握”。阶段页展示四周递进和综合证据，日课完成率只作辅助。

### 4.4 搜索页

搜索表单由服务端处理 GET，结果支持无 JavaScript 翻页。ES Modules 可增加防抖建议和取消旧请求，但全文搜索不依赖浏览器下载六份大索引。结果项包含日课、阶段/周、命中字段、纯文本上下文和真实锚点；加载失败显示可重试状态，不能把异常当作无结果。

### 4.5 我的学习与设置

“我的学习”展示当前计划、最近访问、待复核、卡点和账号数据摘要。设置页提供导出、导入预检、合并/替换、替换前备份、删除学习数据和删除账号。所有破坏性操作要求二次确认，账号删除还需近期重认证。

导入先上传到私有临时区并完成完整校验，不直接写业务表；用户确认预览后在单用户事务中应用。替换前生成可恢复快照，导入期间锁定该用户的学习写入或使冲突写入返回 412，防止半批替换与并发写入交叉。

### 4.6 P1 复习与项目档案

复习页按今日到期、错题、卡点和历史实验分组，先答后看。初始间隔 `[1,7,28]` 天，离线不惩罚。项目档案按项目入口、五份文档、性能、复现、表达和最终验收组织，默认仅本人可见；公开预览必须逐字段确认。

### 5.2 日课类型与完成规则

| 类型 | 典型内容 | 必做状态 | 实验处理 |
|---|---|---|---|
| `concept_lab` | 概念、最小代码、运行与修改参数 | 阅读、练习、实验、验收 | P0 自声明；P1 可传证据 |
| `environment_lab` | Day 001、Day 029 等环境闭环 | 阅读、检查、最小运行、验收 | 记录工具版本 |
| `integration` | 每周第 6 天集成 | 阅读、集成清单、关键产出、验收 | 强调整体管道 |
| `review` | 每周第 7 天复盘 | 阅读、回忆/错题、复盘、下周准备 | 不强制新运行 |

类型由显式覆盖优先、稳定规则其次、默认类型兜底。Day 161—168 没有代码围栏不代表数据无效。

### 5.3 学习状态机

每个日课分别保存 `reading/exercise/experiment/acceptance`，单项取 `not_started/in_progress/done/blocked/not_applicable`。不适用项由日课类型派生，学习者不能绕过必做要求。整体状态只在服务层或视图模型派生：

```text
not_started → in_progress → ready_for_review → completed
                   │                │
                   └→ blocked ──────┘
内容版本变化：保留历史 + needs_review
```

优先级为：任一适用项 blocked→blocked；全部适用项 done→completed；除验收外均 done 且验收未完→ready_for_review；已有活动→in_progress；否则 not_started。P0 的实验 done 只是 L1，不因后续证据导入自动改变验收状态。

### 5.4 继续学习与周完成

`LearningPlan.current_day_id` 是主计划，`DayProgress.last_visited_at` 是浏览位置。用户显式“设为当前学习计划”才修改前者；周复盘时可优先返回本周 Day 7。周状态由关键产出、Day 6 和 Day 7 派生，阶段状态由四周与第 28 天综合复盘派生，不强制锁课。

## 6. 视觉与组件设计规范

### 6.1 视觉方向

延续技术文档的克制风格，以编译流水线、IR 节点、终端和工程证据为品牌语义。现有色值 Token 可继续作为候选，但实际前景/背景组合必须通过 WCAG 2.2 AA 检查。状态使用图标、文本和颜色三重编码。

### 6.2 布局与响应式

中文正文使用系统无衬线字体，代码使用等宽字体。正文桌面字号 16—18 px、行高 1.75—1.9，正文列宽约 720—820 px。初始断点为 `<768 px` 移动、`768—1199 px` 单主栏＋折叠侧栏、`≥1200 px` 双栏。代码块自身横向滚动，页面不得整体横向溢出。

### 6.3 核心组件状态

| 组件 | 必要状态 | 交互要求 |
|---|---|---|
| `ContinueCard` | 匿名、新用户、进行中、卡点、完成、服务不可用 | 主行动真实；匿名引导登录但不阻断阅读 |
| `DayTaskCard` | 匿名、默认、保存中、已保存、冲突、内容更新 | 显示 revision 冲突和未保存原因 |
| `ProgressChecklist` | 五种任务状态 | 原生表单、键盘可用、服务端校验 |
| `CodeActions` | 有/无源码、无 run_all、下载失败 | 不展示无效按钮 |
| `SearchBox` | 初始、加载、结果、无结果、失败 | GET 可翻页，增强请求可取消 |
| `EvidenceBadge` | L1、L1+、L2、L3、无效/过期 | 明示来源与可信边界 |
| `ImportDialog` | 上传、预检、冲突、确认、成功、失败 | 通过预检后才可确认 |
| `SessionState` | 匿名、已登录、过期、需重认证 | 过期不丢表单，不静默登出后丢数据 |

所有按钮必须有实际行为或明确禁用原因。P1/P2 功能关闭时不展示死入口。

## 7. 内容模型与导入设计

### 7.1 权威源与发布关系

```text
tutorials/**/README.md ─┐
tutorials/**/images/* ──┤
tutorials/**/code/* ────┼→ import_tutorial → ContentRelease(validating)
day-overrides.json ─────┘        ├─ Day / DayVersion / ContentChunk
                                 ├─ Asset / 源码 ZIP / 搜索 posting
                                 └─ 全量校验 → ready → active

Django 读取 active_release；学习数据按 day_id 关联，不随内容切换重写。
```

`DayVersion.rendered_html` 是可重建读模型，不是正文权威源。渲染只允许白名单标签、属性与协议；SVG 以图片资源加载，不直接内联不可信脚本。每次导入使用固定 commit，禁止导入过程中跟随移动分支。

### 7.2 内容表与发布状态

| 表 | 关键字段 | 约束 |
|---|---|---|
| `content_release` | id、commit、status、checksum、created_at、activated_at | commit＋配置版本唯一 |
| `content_day` | day_id、day、week、phase、current_version_id | day_id/day 唯一 |
| `content_day_version` | release、day、metadata_json、rendered_html、content_sha | `(release,day)` 唯一 |
| `content_chunk` | version、chunk_id、heading、anchor、text、token_data | `(version,chunk_id)` 唯一 |
| `content_asset` | version、kind、storage_key、sha256、size、visibility | 存储键不可猜测私有资源 |
| `site_state` | active_release_id、updated_at | 单行事务切换 |

发布状态为 `validating→ready→active`，失败进入 `failed`，停用进入 `retired`。只有 ready 可激活；激活后事务内重算公开缓存版本并失效旧缓存。历史 release 不随新内容删除。

### 7.3 日课元数据

```json
{
  "day_id": "day-029",
  "day": 29,
  "week": 5,
  "phase": 2,
  "type": "environment_lab",
  "key_output": false,
  "title": "搭好 MLIR 工作台——让 mlir-opt、FileCheck 和 JIT 都听你指挥",
  "objective": "从今日目标引用块提取",
  "time": {"learning_min": 25, "practice_min": 45},
  "prerequisites": "从前置准备引用块提取",
  "deliverable": "从今日产出引用块提取",
  "source_path": "tutorials/week-005/day-029/README.md",
  "code_path": "tutorials/week-005/day-029/code",
  "content_commit": "53b62f1c84223bb6ca466bb8177921ccd5d8ef72",
```

日号连续且唯一，`week=((day-1)//7)+1`，`phase=((day-1)//28)+1`。内容 SHA 输入包含当日 README、images、code、outputs 和有效覆盖，不包含构建时间、部署域名、ZIP 本身或全局前端资源。

### 7.4 源码包与对象存储

ZIP 以当日 `code/` 为根，包含源码、构建文件、测试、IR 和必要配置，默认排除 outputs、build、缓存、VCS、二进制、对象文件和疑似密钥。确需小型冻结输入时通过 `source_include` 逐项声明。条目排序、固定时间戳、保留 POSIX 权限，重读校验 CRC、路径和大小。

公开对象键包含 commit 和内容 SHA，例如 `public/releases/<commit>/day-029-source.zip`。私有证据与导出文件放独立私有 bucket，通过授权和短时签名 URL 下载。页面下载计数不含个人路径或秘密。

### 7.5 服务端搜索模型

`content_chunk` 保存正文与锚点；`search_token` 保存规范化 token，`search_posting` 关联 chunk、字段、权重和位置。中文以二元词召回，英文命令、错误码、路径和 IR token 保留完整形式。可在 MySQL ngram 与应用 posting 间组合召回，但必须用固定样例验证“常量折叠”、`mlir-opt`、`run_all.sh`、FileCheck、Roofline。

排序字段权重为标题 12、技能 8、目标/产出 5、章节 4、代码路径 3、正文 1，精确技术 token 额外加权。同日最多取 3 个 chunk，分页顺序稳定。搜索词默认不写业务日志。

## 8. MySQL 数据与证据设计

### 8.1 存储决策

P0 使用 **MySQL** 作为账号和学习记录的唯一权威存储。Redis 只保存可失效缓存、限流计数、Celery 状态和短期任务锁，清空 Redis 不得造成数据丢失。localStorage 仅保存主题、侧栏折叠等 UI 偏好。P0 不使用 IndexedDB 保存业务记录；可选离线 outbox 由 WP-13 单独实现。

MySQL 使用 InnoDB、utf8mb4、严格 SQL 模式和 UTC。所有学习时间由服务端生成 RFC 3339 UTC 输出；客户端时间只作展示或不可信证据字段。ORM 迁移按 expand→migrate→contract 执行。

### 8.2 P0 核心表

| 表 | 关键字段与约束 |
|---|---|
| `auth_user` / `accounts_profile` | Django 用户；profile 保存必要偏好和删除状态 |
| `learning_plan` | user_id 唯一、current_day_id、revision、updated_at |
| `learning_day_progress` | `(user_id,day_id)` 唯一、ack_content_sha、last_visited_at、needs_review、revision |
| `learning_task_progress` | `(user_id,day_id,task_id)` 唯一、status、updated_at |
| `learning_data_job` | user、kind、status、private_file、report_json、expires_at |
| `learning_import_conflict` | job、day_id、local_payload、incoming_payload、resolution |
| `audit_event` | actor、action、object_type、object_id、created_at、safe_metadata |

P1 API 可从不可变证据中派生 `latest_evidence_id`，但不把它作为任务完成依据。删除学习记录不删除公开内容；账号删除通过任务执行并撤销全部会话。

### 8.4 导出与导入

导出包含 `schema_version/kind/exported_at/content_commit/plan/days`，P1 扩展新实体，不包含 Django/MySQL 内部主键、会话或密钥。初始文件上限 5 MiB、最多 500 条日课记录；严格 UTF-8、重复键检测、字段白名单、数组和字符串长度限制。

合并按 day_id＋revision＋完整内容比较：目标不存在可新增，同版同内容不变；两侧都存在但内容不同，无论 revision 是否相同都列为冲突，由用户选择后基于最新 revision 应用。禁止仅凭 revision 或 updated_at 自动判断独立副本的新旧。替换先生成私有快照，再在单用户事务内应用。任何失败不改变原数据；导入结果分列新增、更新、跳过、未变化、冲突和失败。

## 9. 技术架构与接口边界

### 9.1 技术选型

| 组件 | 推荐 | 职责 | 边界 |
|---|---|---|---|
| Web 框架 | Django 5.2 LTS 或部署时仍受支持的兼容版本 | SSR、Auth、ORM、Admin、表单与 API | 不执行学习者代码 |
| 数据库 | MySQL 8.4+，以受支持版本为准 | 内容读模型与业务权威数据 | 不直接暴露公网 |
| 缓存/队列 | Redis＋Celery | 缓存、限流、导入和后台任务 | 非权威存储 |
| 应用服务 | Gunicorn | Django WSGI/ASGI 运行 | 仅监听内网 |
| 入口 | Nginx＋HTTPS | 反向代理、静态文件、安全头和请求限制 | 深层路由转发 Django |
| 资源 | S3 兼容对象存储或受控文件服务 | 公开源码/图片、私有证据/导出 | 公私 bucket 分离 |
| 前端 | Django Templates＋原生 ES Modules | 渐进增强、复用 `vp-solution.js` | 不保存秘密或权威进度 |
| CI | GitHub Actions 或等价 CI | 测试、镜像、迁移预检、部署 | 不使用 Pages |

版本号是实现基线而非永久锁定，进入开发时统一升级到仍受安全支持的兼容版本并锁定依赖。

### 9.3 核心 API

统一前缀 `/api/v1/`，浏览器使用同源 Session＋CSRF。响应错误包含稳定 `code/message/details`，不返回堆栈或 SQL。

| 方法与路径 | 语义 | 并发/权限 |
|---|---|---|
| `GET /api/v1/days/` | 当前 active release 日课清单 | 公开、缓存 |
| `GET /api/v1/search/?q=&phase=&cursor=` | 搜索与筛选 | 公开、限流、分页 |
| `GET /api/v1/me/dashboard/` | 当前计划与学习摘要 | 登录 |
| `GET /api/v1/me/progress/{day_id}/` | 读取单日进度 | 仅本人 |
| `PATCH /api/v1/me/progress/{day_id}/` | 修改任务/版本复核 | If-Match、CSRF |
| `PUT /api/v1/me/plan/` | 设置当前计划日 | If-Match、CSRF |
| `POST /api/v1/me/exports/` | 创建私有导出 | 登录、限流 |
| `POST /api/v1/me/imports/` | 上传并完整预检 | 私有临时文件 |
| `POST /api/v1/me/imports/{id}/apply/` | 确认合并或替换 | 预检有效、单用户事务 |
| `DELETE /api/v1/me/data/` | 删除学习数据 | 二次确认 |
| `DELETE /api/v1/me/account/` | 删除账号 | 近期重认证 |

新记录统一使用 `If-None-Match: *`；已有记录使用当前 revision 对应的 `If-Match`。版本不匹配返回 **412**，body 带当前服务端记录和新 ETag；业务冲突可用 409。不得静默最后写入覆盖，也不做字段级时间戳合并。

### 9.4 缓存与故障隔离

公开日课和搜索可缓存，缓存键包含 active_release、locale、查询和筛选，不包含个人 Cookie。个人页面 `Cache-Control: private, no-store`。MySQL 不可用时，已缓存公开页面可继续可读，所有学习写入明确失败；Redis 不可用时降级为数据库限流/直接查询或关闭非核心任务，不把任务入队成功冒充完成。

L2 Verification、AI 和 L3 Lab 与主应用分权。其故障不能破坏教程阅读、已保存进度或本地脚本使用。

## 10. 非功能设计

### 10.1 性能预算

以下是验收目标，不是当前实测值：

| 指标 | 初始预算 |
|---|---|
| 首屏自有新增 CSS＋JS | gzip 后建议不超过 150 KiB |
| 公开日课服务端响应 | 约定负载下缓存命中 p95 目标 300 ms，未命中目标 800 ms |
| 常规搜索 | 约定数据集与负载下 p95 目标 800 ms |
| 进度写入 | 不含网络的服务端 p95 目标 300 ms |
| 首页数据 | 不加载完整正文或全部个人证据 |
| 长文交互 | 代码复制、SVG 弹层和任务提交无持续卡顿 |
| 下载 | 仅用户主动触发，私有文件 URL 短时有效 |

测试报告记录应用版本、数据量、实例规格、缓存状态、并发和测量方法。公开页缓存不得泄露用户信息。

### 10.2 无障碍与响应式

以 WCAG 2.2 AA 为基线。键盘可到达和退出全部组件，焦点不被 sticky 头部遮挡；状态更新通过适度 live region 通知；复杂 SVG 有正文等价解释。移动抽屉管理焦点和背景滚动，320 px、200% 字体下无内容丢失。

### 10.3 隐私与安全

首版即明确服务端数据处理。只收集账号、会话和学习闭环所需字段，提供导出、更正和删除。学习日志、报错、环境、证据和档案默认私密；公开分享再次确认。原始搜索词、完整控制台日志和个人代码默认不进入分析系统。

所有导入 JSON、笔记、证据和附件均为不可信输入。Django 模板默认转义，Markdown 白名单 sanitizer，ORM 防 SQL 注入，写操作 CSRF，登录与上传限流，密码哈希，管理操作审计。数据库、Redis、对象存储和 OAuth 秘密只在服务端密钥系统，不进入 Git、镜像、前端或日志。

### 10.4 SEO、兼容与降级

公开页由服务端输出完整 HTML，保留 sitemap、canonical、Open Graph、面包屑和课程结构化数据。无 JavaScript 时可阅读、搜索、翻页和下载；登录与进度可使用标准表单 POST 作为基础路径。旧浏览器至少保证公开阅读。动态深链、刷新、404、HTTPS 跳转和静态资源缓存纳入发布测试。

### 10.5 可用性与备份

MySQL 每日全量备份并保留 binlog 或等价时间点恢复能力；备份加密、访问受控，定期执行恢复演练。公开内容可从 Git 重建，个人学习数据只能依赖受控备份。应用镜像、数据库迁移、active_release 和静态资源 manifest 共同记录发布版本。

## 11. 埋点与内容运营设计

指标优先衡量 Day 001 有效开始、第一周闭环、Day 029 环境通过、阶段证据、Day 139 冻结、Day 160 复现和项目档案。只采集明确需要的事件，默认不记录原始搜索词、完整日志或精细设备指纹。匿名公开阅读不需注册。

| TC-A05 | 发布与回滚 | 模拟迁移/测试/冒烟失败并回滚 | 失败不切换流量，兼容回滚成功 |

P0 必过 26 项：B01—B08、F01—F12、F15、A01—A05；F13/F14 属 P1，总计 28 项。

## 14. 设计决策记录与待评审项

### 14.1 已确定决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 站点形态 | Django 动态应用，服务端模板＋JSON API | 满足账号、进度、搜索、后台和后续服务需求 |
| 生产托管 | 云主机/托管容器＋Nginx，不使用 GitHub Pages | 支持服务端和数据库，统一权限与运维 |
| 内容权威源 | Markdown/Git 唯一权威源，MySQL 为可重建读模型 | 避免 CMS 与仓库漂移 |
| 首版用户系统 | 公开阅读免登录；保存进度需登录 | 兼顾公开内容与跨设备学习 |
| 学习数据 | MySQL 权威；Redis 非权威；localStorage 仅 UI 偏好 | 可靠持久化、事务和权限 |
| 前端 | Django Templates＋原生 ES Modules | 复用现有资产，避免不必要 SPA 迁移 |
| 搜索 | MySQL ngram＋技术 token posting | 首版减少外部服务，保留技术检索能力 |
| 并发 | 整记录 revision＋If-Match，412 返回当前版本 | 不静默覆盖，不拼接不存在的状态 |
| 日课完成模型 | 四项子状态＋按类型派生 | 避免“看过等于学会” |
| 实验执行 | 本地/WSL 优先，后续 L2/L3 | 符合真实工具链和安全边界 |
| 离线能力 | P1 可选 outbox，不是 P0 依赖 | 在线优先，避免双权威源 |
| P2 边界 | 社区、AI、远程执行分别立项 | 治理、安全与成本独立评审 |

### 14.2 开发前需确认的实现事项

这些事项不改变动态架构方向：生产域名和部署地区、邮件服务商、对象存储实现、MySQL 自建或托管、首版是否启用 GitHub OAuth 作为密码登录之外的补充、复杂 SVG 的具体 sanitizer、代表日课 CI 的 Linux 与 LLVM/MLIR 固定环境。

所有决策通过样本、压测和安全测试决定。若变化影响外部契约，必须同步更新设计、ORM Schema、API Schema、fixtures 和追踪矩阵。

## 15. 首版交付定义

首版完成时，网站应具备：可原子发布和回滚的 168 天内容版本；可公开阅读并支持动态深链的日课与周/阶段页面；安全账号与会话；MySQL 持久化的四项学习状态、当前计划和跨设备恢复；版本化源码包；服务端技术搜索；可恢复的数据导出导入与账号删除；以及覆盖权限、并发、迁移、备份、故障和无障碍的发布证据。

首版不承诺离线编辑、服务端远程执行、防作弊考试、公开社区、AI 自动答疑和浏览器内完整 MLIR 实验。它要证明的是：**动态架构能够可靠承载 168 天学习路径，教程与个人数据各自具有清晰权威源，学习记录可跨设备恢复，内容更新和系统故障不会静默破坏历史。**
